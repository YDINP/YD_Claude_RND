## 0. 원작 시스템 매핑표 템플릿

**사용법**: 원작(무명전) 시스템 각각을 새 컨셉에서 어떻게 구현할지 정리.

| # | 원작 시스템 | 새 컨셉 대응 | 엔진 변경 | 콘텐츠만 변경 | 비고 |
|----|-----------|-----------|---------|------------|-----|
| 1 | 출생 추첨(지역→종족→신분) | ? | □ | ■ | 새 지역·종족·신분 정의 후 확률 유지 |
| 2 | 4스탯(생명력·평온·학식·인연) | ? | □ | ■ | 스탯명만 바뀌고 곡선은 유지 가능 |
| 3 | 정규화 틱(1틱=k년) | ? | □ | ■ | 새 종족 k값만 정하면 됨 |
| 4 | 이중 시간축 해저드 | ? | □ | ■ | 원인변수만 다시 정의 |
| 5 | 사인 가중표(생활권×단계) | ? | □ | ■ | 새 생활권·사인 카탈로그 |
| 6 | 신분 기울기`exp(-g(q-3))` | ? | □ | ■ | 신분 5단계 유지 시 g값만 조정 |
| 7 | 정규화 단계(영아~황혼) | ? | □ | ■ | 척도 나이 경계 유지 |
| 8 | 마나 각성(고유시스템) | ? | □ | □ | 제거 또는 다른 시스템으로 대체 |
| 9 | 탄생 징조 | ? | □ | ■ | 컨셉별 징조 도메인 + DSL |
| 10 | 세계 사건·날짜시드 | ? | □ | ■ | 세계 사건 재정의 |

## 1. 컨셉 슬롯 목록

새 컨셉에서 «반드시 정해야 할 것»:

### 1.1 기본 설정

```
[ ] 세계명 또는 세계관 한 줄 피치
[ ] 시간대 (역사적 배경, 현재 시대 이름, 시간 단위)
[ ] 플레이어 관점 (일인칭·3인칭, 성장 여부)
[ ] 톤 (밝음·어두움·중립, 판타지·현실·혼합)
```

### 1.2 세계 구조

```
[ ] 지역 수: 최소 6곳 (MVP), 최대 10곳 (2차)
    - 각 지역: 이름, 생활권, 주요 종족, 설명
    
[ ] 종족 수: 기본 6종
    - 각 종족: 이름, 출생비중(%), k값, 성년 나이, 특수성
    - ※ 신체·지능·성격 수치는 금지(원칙 3)
    
[ ] 신분 계층: 5단계 유지
    - q1~q5 이름, 각 비중(%), 기울기 g(권장 1.0)
    
[ ] 직업 분포: 15~20개
    - 각 직업: ID, 비중(%), 첫 소득, 위험도, 경로
```

### 1.3 세계 통계 기관

```
[ ] 통계를 관리하는 «세계 안 기관» 3~4개
    (무명전: 왕립 서기국, 상인조합, 석판 대장 등)
    
[ ] 각 기관의 데이터 품질 등급(S/A/B/C/D)
    
[ ] 신뢰구간 표기 로직
    (기록있음 ±10~15%, 기록없음 ±30%)
```

### 1.4 원인 변수 & 생성 모델

```
[ ] 생활권 분류 (필수 7가지 카테고리)
    예: 곡창·초원·습지·변경·해안·광산·학술
    → 각 생활권별 사인 카탈로그 적용
    
[ ] 원인 변수 6개 정의
    (무명전: climate/security/wealth/monsters/medicine/plague)
    → 새 컨셉 맞춤 6개 선택 또는 신규 정의
    
[ ] 해저드 성분 식 (각 1년 단위)
    disease = f(medicine, plague)
    violence = f(security)
    occupational = f(?)
    ... 모두 지역 원인변수에서 도출
    
[ ] 지역별 calibration 값 (1.0 기준)
    → 시뮬과 연감 오차 ±2% 안으로
```

### 1.5 고유 시스템 (선택)

```
[ ] 마나 같은 «고유 기계류» 필요한가?
    필요 시:
    - [ ] 고유시스템 ID, 상태 구조
    - [ ] resolve() 함수 (순수, state + rng → void)
    - [ ] 사인 연결 (2~3개 사인)
    - [ ] 카드 5~10장
    - [ ] 사건 10~20종
    - [ ] 실험실 검증 기준값
```

### 1.6 카드 & 사건 콘텐츠

```
[ ] MVP 결정 카드: 60장 (확정안)
    + 지역별 변주
    + 1회/생 ≤ 2회 CI
    
[ ] MVP 사건: 140종
    + 각 사건 3~5개 문구 변종(variants)
    
[ ] 회고 질문 (5회, 단계 경계)
    각 단계별 현실을 향한 질문 2종
    
[ ] 공유 카드 템플릿
    (사망/출생/전승) × 로컬라이제이션
```

### 1.7 번역 & 로컬라이제이션

```
[ ] 기본 언어 (ko/ja/en?)
[ ] i18n 구조 (L`…` 태그 + 사전)
[ ] 조사 헬퍼 (한국어 은/는·이/가 등)
[ ] 고유명사 받침 사전
```

## 2. 컨셉 3안 심사 루브릭

새 컨셉 3개 후보안이 있을 때 사용.

| 기준 | 배점 | 심사항목 | 가중치 |
|------|------|--------|--------|
| **감정 핵심** | 10 | 원작의 «한 번뿐인 삶» 무게를 유지하는가? | 1.5x |
| **판타지 신성** | 10 | 설정이 «손을 닿을 수 있는» 세계인가? | 1.0x |
| **구현 용이** | 10 | 1인 + AI로 데이터 저작 가능한 분량인가? (콘텐츠 <6주) | 1.2x |
| **재플레이성** | 10 | 같은 콘텐츠 반복을 새롭게 읽게 하는가? | 1.0x |
| **바이럴** | 10 | 한 줄 피치 자체가 밈이 되는가? | 1.0x |
| **합계** | 50 | — | — |

**심사 과정**:
1. 각 안별로 5개 기준 모두 점수 (1~10)
2. 기준별로 가중치 곱함
3. 준우승안과의 「약점을 메우는 부품」 체크

## 3. 열린 질문 유형 체크리스트

새 컨셉에서 사용자(또는 기획팀)의 결정이 필요한 항목들:

```
[ ] Q1. 콘텐츠 분량을 늘릴까? (MVP 40vs60 카드)
    예상 비용: 저작 3~8일
    
[ ] Q2. 무엇을 2차로 미룰까? (연대기·전승·사운드 등)
    예상 범위 축소: 2주
    
[ ] Q3. 종족 성년을 어떻게 정할까?
    (문화적 나이 vs 척도 나이)
    
[ ] Q4. 희귀 이벤트 확률을 피치와 맞춰야 하는가?
    예: «미션 1%» 피치 vs 실제 시스템
    
[ ] Q5. 장수 종족의 높은 아동사망률을 받아들일까?
    (척도 기준 장수 = 아동기 길어짐)
    
⚠️ 위 5개 모두 «추천안»으로 자동 확정 권장
   (오케스트레이션으로 끝까지 진행하는 경우)
```

## 4. 분량 산정식

### 4.1 한 삶의 결정 & 사건 소비량

```
MODE(분)     | tickSec | E[ticks] | 결정 회수 | 사건 슬롯 |
─────────────┼─────────┼──────────┼────────┼──────────
10 (견습)    | 6.7초   | ~90      | 10회   | ~270
20 (기본)    | 14.6초  | ~82      | 18회   | ~246
40 (긴)      | 33초    | ~75      | 24회   | ~225
```

### 4.2 콘텐츠 풀 계산

```
한 삶이 쓸 카드: 약 18개 (20분 모드)
반복 회피 cooldown: 14틱
평균 반복 = 한 삶 안에서 같은 카드 ≤ 2회

따라서:
MVP = 60 카드 × 0.20 poolRate = 12개 기대값
      + 지역별 변주 추가로 다양성 확보
```

### 4.3 사건 계산

```
한 삶 틱당 사건 슬롯: 3개 (영아 제외 2개)
한 삶 틱 수: ~80틱
= 약 240개 슬롯

140종 사건 × 각 3~5개 변종
= 최대 700개 문구 변종 필요
```

## 5. 연감 작성 절차

### 5.1 Phase별 의존성

```
Phase 0-1: 컨셉 확정 + 원인변수 정의
    ├─ 지역 6개 + 원인변수
    ├─ 종족 6개 + k값, 성년
    └─ 신분 5단계 + 기울기

Phase 2: 생성 모델 조정
    └─ tools/almanac/ 수정
    └─ 자기일관성 CI 통과
    └─ 연감 v1 산출

Phase 3-4: 콘텐츠 & 엔진
    ├─ (병렬) 카드 60장 저작
    ├─ (병렬) 사건 140종 저작
    └─ (병렬) 엔진 구현

Phase 5-7: 통합 & 밸런스
    ├─ 카드·사건 DSL 검증
    ├─ 통계 테스트(N=10,000)
    └─ 실험실 밸런싱
```

### 5.2 성과물 체크리스트

```
□ 생성된 almanac.json (자기일관성 CI 통과)
□ 연감 시각화 (지역×종족 e0 표)
□ 신뢰구간 표기 샘플(기록있음/없음)
□ 환경 분해 패널 샘플(신고서용)
□ 공유 카드 샘플 5개 (사망·출생·전승)
```

## 6. 적대적 검토 체크리스트

새 컨셉 기획이 완성되면, 다음을 확인하세요:

```
설정 검토:
  [ ] 세계관이 «나도 저 세계였다면» 감정을 일으키는가?
  [ ] 판타지가 «양념»인가 아니라 «주인공»인가? → 양념으로
  [ ] 톤이 일관적인가? (담담한 공문서체)
  
데이터 검토:
  [ ] 신분 격차가 «부당하지만 현실적»인가?
  [ ] 종족 간 기대수명 격차가 환경으로만 설명되는가?
  [ ] 기록 없는 지역 신뢰구간이 서사와 맞는가?
  
콘텐츠 검토:
  [ ] 카드·사건이 «피해자 우월감»을 주는가? → 아니어야 함
  [ ] 회고 질문이 현실을 향하는가? (판타지 탈출 아님)
  [ ] 민감 콘텐츠 린트(자해·아동폭력 등)를 통과했는가?
  
운영 검토:
  [ ] 1인 + AI로 범위 내 완료 가능한가?
  [ ] 2차·3차 로드맵이 그려지는가?
  [ ] 배포 후 밸런스 피드백 루프가 있는가?
```

## 7. 성공 사례: 무명전 회고

### 7.1 잘한 점

✓ 원작의 감정 («한 번뿐»)을 판타지로 옮김  
✓ 수치 기반 저작 (생성 모델 → 데이터 QA 자동)  
✓ 환경 분해로 인종주의 오독 예방  
✓ 신뢰구간으로 «가짜 통계» 신뢰 해결  

### 7.2 배운 점

⚠️ Q1~Q5 열린 질문이 중요 (기획팀 합의 필수)  
⚠️ 연감 CI가 통과할 때까지 개발 진행 금지  
⚠️ 공유 카드 수치 정합(스크립트 자동화)이 필수  
⚠️ 애매한 문구(«빠르다» «강하다») 린트 규칙화
