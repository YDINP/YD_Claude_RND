  3. **털렸을 때 빨리 바꾼다** — 무엇을 어디서 폐기·재발급할지 미리 적어 둔 목록

## 1. 목표 / 비목표

**목표**
- 비밀값이 어디에 있는지 보여 주는 지도 + 안전한 보관소로 옮기기
- 미끼(카나리아) 파일을 읽는 프로세스가 생기면 즉시 알림
- 시작 프로그램·예약 작업·서비스·런처 파일이 바뀌면 알림 (공급망 변조 탐지)
- "털린 것 같다" 버튼 → 바꿔야 할 키 체크리스트와 해당 대시보드 링크

**비목표 (안 만드는 것)**
- 백신 엔진, 시그니처 검사 → Defender에 맡긴다
- 커널 드라이버, 네트워크 패킷 가로채기 → 개인용으로는 위험 대비 이득이 적다
- 자동 차단/자동 삭제 → 오탐으로 작업 중인 프로그램이 죽을 수 있어 **알림만** 준다

## 2. 기능 설계

### F1. 비밀값 지도 (`pcg scan`) — 가장 먼저
- `D:\park`, `C:\dev`, 사용자 홈 아래에서 `.env*`, `*.pem`, `*credentials*.json`, `id_*`, `shared-login.json`, `*.kdbx` 등을 찾는다.
- 내용 패턴(gitleaks 규칙 일부: `sk-`, `ghp_`, `xoxb-`, 텔레그램 봇 토큰, JWT, AWS 키 등)으로 **종류만** 분류한다. 값은 출력하지도 저장하지도 않고, 해시 앞 8자만 남긴다.
- 각 항목: 경로 / 종류 / git 추적 여부 / .gitignore 여부 / 마지막 수정일 / 위험 등급
- 출력: `docs/pc-guard/inventory.md` 대신 **로컬 전용** `%LOCALAPPDATA%\pc-guard\inventory.json` (저장소에 커밋하지 않음)

### F2. 보관소로 옮기기 (`pcg vault`)
- Windows **DPAPI**(사용자 계정에 묶인 암호화)를 쓴다. 외부 서비스가 필요 없다.
- `.env` → `.env.vault`(암호화)로 바꾸고, 실행할 때만 `pcg run -- npm run dev` 처럼 환경변수로 주입한다.
- 한계를 분명히 적어 둔다: 같은 계정으로 실행 중인 악성코드는 DPAPI도 풀 수 있다. 다만 **"폴더를 통째로 긁어 가는" 대량 탈취형은 막아 준다.** 이번 니케 건이 바로 이 유형이다.
- 단계적으로: 위험 등급이 높은 것(결제·배포 키)부터 옮긴다.

### F3. 미끼 파일 (`pcg canary`) — 효과 대비 비용이 가장 좋음
- 인포스틸러가 노리는 위치에 가짜 파일을 둔다.
  - `%APPDATA%\Exodus\exodus.wallet\`, `%APPDATA%\Electrum\wallets\` 같은 지갑 경로
  - `Desktop\passwords.txt`, `D:\park\.env.backup`
  - 가짜 AWS/OpenAI 형식 키 (Canarytokens.org 무료 토큰 → **누가 쓰면 메일이 옴**)
- 파일에 SACL(읽기 감사)을 걸고 감사 정책을 켜면 → 이벤트 4663이 남는다 → 감시기가 **읽은 프로세스 경로**와 함께 알린다.
- 사용자 본인도 Explorer 미리보기 등으로 건드릴 수 있으므로 화이트리스트를 둔다 (explorer.exe 썸네일, Defender 검사).

### F4. 변경 감시 (`pcg watch`)
- 스냅샷을 찍고 비교한다: 시작 프로그램(Run 키, Startup 폴더), 예약 작업, 서비스, 브라우저 확장 목록, hosts 파일, 프록시 설정, 루트 인증서.
- **런처·업데이터 무결성**: Steam·Epic·게임 런처, Node/Python 전역 패키지 폴더에서 서명되지 않았거나 서명자가 바뀐 exe·dll·js가 새로 생기면 알린다.
- 새로 외부와 통신하는 프로세스(처음 보는 exe + 외부 IP)를 하루 단위 요약으로 알린다. 실시간은 소음이 많아 하지 않는다.

### F5. 털렸을 때 (`pcg panic`)
- F1 지도에서 "이 PC에 있던 키" 목록을 뽑고, 각 키마다 **폐기·재발급 URL**(GitHub, Vercel, Supabase, OpenRouter, Telegram BotFather, Google 세션 등)과 순서를 적은 체크리스트 MD를 만든다.
- 순서: ① 이메일·Google 세션 전부 로그아웃 + 비밀번호 변경 → ② 돈과 연결된 것(결제·지갑·OpenRouter) → ③ 배포 권한(GitHub·Vercel) → ④ 나머지 봇 토큰
- 이 기능은 **위험한 작업을 대신 실행하지 않는다**. 목록과 링크만 주고 사람이 직접 처리한다.

### F6. 하드닝 점검 (`pcg check`)
- 한 번 돌리면 점수를 보여 준다: CFA, 스마트 앱 컨트롤, 브라우저 비밀번호 저장 여부, 2FA 체크리스트(수동 입력), 관리자 계정으로 일하는지, BitLocker, Windows 업데이트 상태.
- 고치는 건 사용자 확인 후 명령 한 줄씩만 제안한다.

## 3. 구조

```
pc-guard/            (C:/dev/pc-guard, 비공개 저장소)
  crates/
    core/            스캐너·규칙·스냅샷 diff (순수 함수, 테스트 중심)
    vault/           DPAPI 래퍼
    agent/           상주 감시기 (이벤트 로그 구독 + 주기 스냅샷), 트레이 알림
    cli/             pcg scan | vault | run | canary | watch | panic | check
  rules/             비밀값 패턴, 미끼 경로, 화이트리스트 (TOML)
```

- **언어: Rust**. 실행 파일 하나로 끝나고 메모리가 적게 들며, KeyClack에서 이미 Windows API를 다뤄 봤다.
- 설계 패턴: 감시 대상마다 `Probe` 트레이트(snapshot → diff) — 전략 패턴. 알림은 `Sink` 트레이트(토스트·로그 파일·텔레그램 선택). 이벤트 처리는 링버퍼 + 중복 억제(같은 경보는 10분에 한 번).
- 상주 메모리 목표 < 20MB, CPU 평균 < 0.5%.
- 데이터는 모두 로컬에만 둔다. 외부로 보내는 건 사용자가 켠 텔레그램 알림과 Canarytokens뿐이다.

## 5. 위험과 주의
- 미끼·감사 정책은 이벤트 로그를 늘린다 → 감사는 미끼 파일에만 걸고 폴더 전체에는 걸지 않는다.
- 스캐너가 비밀값을 읽는 프로그램 자체가 되므로, **값을 메모리에서 바로 해시하고 버린다.** 로그와 패닉 메시지에도 남기지 않는다.
- 사용자 세션에서 마우스·키 자동조작이나 다른 프로세스 강제 종료는 하지 않는다 (기존 원칙).
- 자동 대응은 넣지 않는다. 오탐 비용이 탐지 이득보다 크다.
