2. 원인 — 왜 이런 무게가 남아 있나

누가 정하나현재저탄소 기본값 이후
개발 시작 때 템플릿압축·캐시·이미지 변환은 개발자가 따로 켜야 함 → 일정에 쫓기면 그대로 납품켜진 상태로 시작. 끄려면 일부러 바꿔야 함
검수기능·보안·접근성은 검수하지만 전송량·전력 항목 없음「무게 점검표」 한 쪽을 검수표 옆에 첨부
운영개발사는 떠나고 운영 중 무게는 아무도 보지 않음OpenTelemetry 지표로 요청당 전송량·전력 추정 상시 확인

3. 제안 구조 — 한 번 바꾸면 전국으로

구성내용NIA만 할 수 있는 이유
① 저탄소 기본값응답 압축·정적 파일 1년 캐시를 켠 설정 템플릿 / 공통컴포넌트 게시판·첨부 이미지의 WebP 표시용 사본과 가로 폭 상한(원본 보관) / Spring AI·RAG 예제에 같은 질문 응답 캐시·바뀐 문서만 다시 임베딩표준프레임워크 실행환경·공통컴포넌트·AI 예제를 NIA가 직접 개발·배포
② 무게 점검표개발환경 플러그인(이클립스·VS Code 확장)이 빌드·테스트 때 첫 화면 전송량, 압축, 이미지 형식·크기, 캐시 4항목을 측정해 한 쪽 결과표 출력 → 검수 때 첨부(권고)5.0에서 VS Code 확장을 새로 제공 — 같은 배포 경로 활용
③ 운영 계측OpenTelemetry 기본 지표에 요청당 전송량·처리 시간 추가, 쿠버네티스 예제에 전력 추정 도구(Kepler, CNCF 오픈소스) 대시보드 예시5.0에 Kubernetes·OpenTelemetry가 이미 포함

4. 감축량 계산 (추정)

항목값과 근거
첫 화면 1회당 줄일 수 있는 전송량중앙값 2.32MB (약 26%) = 압축 안 된 텍스트 × 70%(통상 압축률, 가정) + 이미지 × 25%(WebP, Google 연구 25~34%의 하한)
첫 화면 방문 1억 회당 전송 감소232TB
데이터센터·통신망 전력232,110GB × 0.114kWh/GB(SWD v4 운영 에너지, 이용자 기기 제외) ≈ 26.5MWh
온실가스26.5MWh × 0.4173tCO₂eq/MWh(2023 전력배출계수) ≈ 11.0tCO₂eq — 이용자 기기 전력(0.080kWh/GB)까지 넣으면 약 18.8tCO₂eq
캐시·AI 응답 캐시 효과재방문 전송과 생성형 AI 호출 감소분은 계산에서 뺌(보수적 추정) — 시범에서 실측

※ 방문 수 1억 회는 계산 단위이며 실제 공공 누리집 전체 방문 수 추정치가 아님. 1개월 시범에서 NIA 운영 누리집의 실제 방문 수·전후 전송량으로 다시 계산
