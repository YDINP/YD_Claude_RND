## 0. 설계 전제 — 내러티브 / game-narrative-designer

### 4대 필러의 내러티브 번역

| 필러 | 내러티브 구현 방식 |
|------|------------------|
| **선택이 정체성이다** | 5챕터 전체가 "고르는 행위"에 대한 논쟁이다. 고블린 왕·이자나미·오딘이 각각 다른 각도에서 "너는 왜 줍고, 왜 문 앞에 세우는가"를 묻는다. 답은 5-5 마지막 한 줄에서만 나온다. |
| **읽히는 세계, 막지 않는 진행** | 모든 씬 `skipable: true`. 스토리를 읽지 않아도 전투 흐름은 완결된다. 대신 컷씬을 본 사람만 5-5 오딘 대사의 무게를 안다. 정보가 아니라 **의미**를 보상으로 준다. |
| **유닛이 아니라 동행자** | 아이리스가 챕터 1부터 5까지 상시 동행 화자로 고정된다. 전투 편성과 무관하게 서사 파티원. 나머지 9명은 첫 만남·각성·전직에서만 목소리를 낸다. |
| **첫 세션 안에 첫 각성** | 1-2 클리어 직후 `first_hero` 컷씬 배치. **1-4 진입 직전** `evolve_gate` 컷씬(기관 선택 관문) 배치 — 골렘의 "등록되지 않은 자, 통과 불가"가 게이트의 서사적 원인이 된다. 챕터 1 = 온보딩 = 첫 각성 + 첫 전직 결정. |

### 이 문서가 다루지 않는 것

- 스테이지 배치·적 웨이브 구성 → game-level-designer
- 컷씬 재생 UI, 스킵 버튼, 텍스트 속도 → game-ux-designer
- 보상 수치, 재화 밸런싱 → game-system-designer
- 구현 코드 → 본 문서는 기획 문서와 JSON 데이터 스펙만 제공

## 1. 메인 서사 아웃라인 — 내러티브 / game-narrative-designer

### 1-1. 드라마틱 퀘스천

> **"신이 사라진 자리에, 누가 무엇을 세울 것인가?"**

이 질문은 3단계로 심화된다.

| 단계 | 표면 질문 | 실제 질문 | 제기자 |
|------|---------|---------|--------|
| 1 | 균열은 무엇인가? | 왜 나는 이 빛을 줍는가? | 숲의 지배자 (1-5) |
| 2 | 균열은 누가 만들었나? | 이름을 주는 것이 친절인가, 구속인가? | 이자나미 (3-5) |
| 3 | 균열을 어떻게 멈추나? | 살아남는 방식으로 통합과 분화 중 무엇이 옳은가? | 오딘 (5-5) |

**답**:
> 답은 수집가가 말하는 것이 아니다. 수집가가 **문 앞에 세운 자들**이 답이다.
> 오딘의 답은 "열둘을 하나로 합친다"였고, 수집가의 답은 "하나를 열둘로 나누어 세운다"였다.
> 왕좌를 받으면 수집가는 열세 번째 신이 되고, 게임은 처음으로 되돌아간다.
> 그래서 수집가는 왕좌를 비워두고 문을 다시 연다. — **결말은 승리가 아니라 재개(再開)다.**

### 1-2. 챕터별 기·승·전·결

#### 챕터 1 — 균열의 시작 (Rift Awakening)

| 구분 | 내용 |
|------|------|
| **기** | 숲의 이상 신고. 수집가가 처음으로 미정령의 빛에 손을 댄다. 등록관이 장부에 이름을 적는다. |
| **승** | 조각이 모이고(1-1~1-2), 첫 기본영웅 아이리스가 각성한다. 1-3에서 "방향을 얻지 못한 미정령"의 잔해(움직이는 버섯)를 본다 — 기관의 존재 이유가 감정적으로 각인된다. |
| **전** | 1-4 앞에서 폐허의 문지기 골렘이 "등록되지 않은 자는 통과 불가"라며 길을 막는다. 그래서 아이리스를 열두 문 앞에 데려간다 — **첫 기관 선택**. 통과 후 폐허가 **수집가 길드의 옛 시설**이었음이 드러나고, 벽의 열두 줄 각인이 방금 고른 문들과 같은 이름임을 알게 된다. 등록관의 정체에 첫 균열이 간다. |
| **결** | 1-5 숲의 지배자가 "우리는 굶주려서 줍는다. 너는 왜 줍지?"라고 묻고 답을 듣지 않고 흩어진다. 첫 기관 선택을 막 끝낸 직후이므로 이 질문이 가장 아프게 꽂힌다. |
| **챕터 목표** | 미정령 → 기본영웅 → 전직의 3단계 루프를 서사로 체험시킨다 |
| **플레이어가 알게 되는 것** | 균열은 시작일 뿐이다. 그리고 수집가라는 직업은 예전에 훨씬 흔했다. |
| **감정 곡선** | 호기심(중) → 애착(중) → 불안(중고) → 결정의 무게(고) |
| **다음 챕터 후크** | "더 강한 자들이 온다" + 숲 안쪽에 두 번째 균열 발견 |

#### 챕터 2 — 신들의 전장 (Battlefield of Gods)

| 구분 | 내용 |
|------|------|
| **기** | 숲을 나오자 하늘이 둘이다. 발할라의 전운과 타카마가하라의 금빛이 경계선에서 서로를 갈아낸다. |
| **승** | 아인헤리아르와 텐구가 서로 왜 싸우는지도 모른 채 죽인다(2-1~2-2). 균열은 땅이 아니라 **세계의 지도**를 찢고 있었다. |
| **전** | 2-3 뒤틀린 비프로스트 — 되돌릴 수 없다는 사실 확정. 2-4 차원 경계에서 공허가 새어 나온다. |
| **결** | 2-5 균열의 수호자를 쓰러뜨리자 갑주 안이 **비어 있다**. 룬만 형태를 붙들고 있었다. "균열의 배후에는 신들이 있다. 아스가르드는 알고도 나를 여기 세웠다." |
| **챕터 목표** | 사고(事故)였던 균열을 **의도**로 재정의한다 |
| **플레이어가 알게 되는 것** | 균열은 자연재해가 아니다. 아는 자들이 침묵하고 있었다. |
| **감정 곡선** | 압도(중고) → 무력감(중) → 배신감(고) |
| **다음 챕터 후크** | "그 답은 더 아래에 있다. 죽은 자들이 먼저 알고 있을 것이다." |

#### 챕터 3 — 요미의 심연 (Yomi's Abyss)

| 구분 | 내용 |
|------|------|
| **기** | 땅이 아래로 열린다. 등록관이 "여기서는 미정령을 줍지 마 — 주인이 있다"고 경고한다. |
| **승** | 망각의 강, 저주받은 전장. 영원히 싸우는 전사들은 **자기가 왜 싸우는지 잊은 자들**이다. 챕터 2의 아인헤리아르/텐구와 같은 그림. |
| **전** | 3-4 궁전 앞. 등록관의 경고에도 불구하고 수집가는 계속 줍고 있다. 아이리스가 처음으로 그것을 지적한다. |
| **결** | 3-5 이자나미가 수집가의 행위 자체를 심판한다. "이름이 없으면 죽지 않는다. 문이 없으면 잃을 것도 없다. 너는 자유로운 것들을 데려다가 죽을 수 있는 것으로 만들었다." 패배 후 "균열은 내 것이 아니다. 나도 하류에서 주웠을 뿐이다 — 너처럼." |
| **챕터 목표** | 게임 시스템(수집·각성·전직)에 **도덕적 반론**을 제기해 플레이어의 행위를 자각시킨다 |
| **플레이어가 알게 되는 것** | 균열은 더 큰 계획의 하류다. 그리고 자신도 이자나미와 같은 층위에서 행동하고 있었다. |
| **감정 곡선** | 정적(중) → 죄책감(고) → **가장 어두운 순간**(최고) |
| **다음 챕터 후크** | "계획을 세운 쪽은 아래가 아니라 위에 있다" — 상승 전환 |

> **감정 피로 방지**: 3-5 직후 챕터 4 진입 컷씬은 의도적으로 가벼운 톤(등록관의 농담)으로 시작한다. 고강도 3연속 금지 원칙 적용.

| 구분 | 내용 |
|------|------|
| **기** | 산은 위로 갈수록 좁아지고 공기는 무거워진다. 등록관이 "여긴 신들이 아직 자기가 신인 줄 아는 유일한 곳"이라고 비꼰다. |
| **승** | 전령들이 **이름을 묻는다**. "등록되지 않은 자는 존재하지 않는 것으로 친다." — 길드의 등록 제도가 올림푸스에서 유래했음이 드러난다. |

| **플레이어가 알게 되는 것** | 통합 제안은 실재했고, 거절한 세력이 있으며, 제안자는 오딘이다. |
| **감정 곡선** | 긴장 완화(중) → 존경(중고) → 목표 확정 / 결의(중고) |
| **다음 챕터 후크** | 오딘의 이름. 그리고 "네가 위에서 볼 것은 아래에서 본 것보다 나쁘다"는 경고. |

### 1-3. 수집가(플레이어)의 역할 변화

```
챕터 1  구경꾼 (Witness)
        — 신고를 받고 간다. 줍는다. 왜 줍는지 아직 질문받지 않았다.
        — 첫 질문을 받지만 대답하지 않고 자리를 뜬다.

챕터 2  개입자 (Intervener)
        — 신의 일에 발을 들인다. 등록관이 "수집가는 원래 신의 일에 끼지 않아"라고 경고한다.
        — 그럼에도 균열 앞의 파수꾼을 쓰러뜨린다. 처음으로 세계의 구조를 바꾼다.

챕터 3  피고 (Accused)
        — 이자나미가 수집가의 직업 윤리 자체를 심판한다.
        — 처음으로 자기 행위를 의심한다. 그러나 멈추지 않는다. 멈출 수 없다는 것이 밝혀진다.

챕터 4  도전자 (Challenger)
        — 신에게 직접 답을 요구한다. 제우스가 "들을 자격"을 시험한다.
        — 이 시점부터 수집가는 관찰 대상이 아니라 협상 상대다.

챕터 5  결정자 (Decider)
        — 오딘이 왕좌를 내민다. 받으면 신이 되고, 거절하면 수집가로 남는다.
        — 거절이 곧 답이다. 수집가는 자기 직업을 선택함으로써 세계의 형식을 선택한다.
```

**설계 의도**: 역할 변화가 **권능의 상승**이 아니라 **책임의 상승**으로 그려진다. 수집가는 챕터 5에서도 챕터 1과 같은 일을 한다 — 줍고, 이름을 주고, 문 앞에 세운다. 달라진 것은 그것이 무슨 의미인지 안다는 점뿐이다.

### 1-4. 시스템 ↔ 서사 접합점 — "문 앞에 세우는 행위"와 5-5

이것이 본 설계의 핵심 구조다.

| 게임 시스템 | 서사적 의미 | 5-5에서의 회수 |
|------------|-----------|--------------|
| 미정령 조각 30개 수집 | 이름 없는 것을 계속 줍는 노동 | 오딘: "나는 계산을 했다. 너는 노동을 했다." |
| 기본영웅 각성 (이름 부여) | 자유를 잃게 만드는 대신 존재를 얻게 하는 거래 | 이자나미의 반론이 여기 대응 → 오딘 앞에서 정당화됨 |
| 기관 선택 (전직) | **열두 방향 중 하나를 고르는 분화(分化)** | 오딘의 통합안과 정면 대립하는 대안 |
| 멀티 루트 개방 | 같은 존재가 다른 문을 통과하면 다른 것이 된다 | "정체성은 본질이 아니라 통과한 문이다"의 증명 |

**5-5 오딘의 최종 논거는 플레이어의 세이브 데이터다.**

```
오딘: "너는 {{ascendedCount}}명을 문 앞에 세웠고,
       그중 {{institutionCount}}개의 서로 다른 문을 골랐다."
오딘: "나는 열둘을 하나로 만들려 했다. 너는 하나를 열둘로 나누어 세웠다."
```

- `{{ascendedCount}}` = 플레이어가 보유한 전직 영웅 수
- `{{institutionCount}}` = 그 전직 영웅들이 속한 **서로 다른 기관의 수** (1~12)

즉 **플레이 그 자체가 최종 보스에 대한 반론의 증거물**이 된다. 한 기관만 파고든 플레이어와 여러 기관에 분산한 플레이어가 같은 대사에서 다른 숫자를 읽는다. 대사 자체는 분기하지 않으므로 제작 비용은 0에 수렴하고, 체감 개인화는 최대가 된다.

> **가드레일**: `institutionCount`가 1인 극단적 케이스에서도 대사가 성립해야 한다. 이 경우 오딘의 문장은 "너는 하나의 문만 믿었다. 그것도 하나의 답이다"로 읽히도록 조사(助詞) 처리 없이 숫자만 삽입한다. game-system-designer에게 **1 이상 보장**만 요청한다(전직 0회로 5-5 도달은 밸런스상 불가능하나, 방어값 `1` 필요).

### 2-7. 신규 조력자 캐릭터 시트 — 등록관 (The Registrar)

> 창작 제한 범위 내 **비플레이어 조력자 1명**. 포트레이트 자산이 없으므로 실루엣/음성 전용으로 설계했다.

| 항목 | 내용 |
|------|------|
| **화자 ID** | `npc_registrar` |
| **표기명** | 챕터 1 진입 첫 3줄까지 `???` → 이후 `등록관` |
| **portraitId** | `null` (영구) — 실루엣 + 텍스트박스 색상 구분만으로 처리 |
| **역할** | 조력자 / 튜토리얼 안내역 / 세계관 해설자 |
| **동기 (Want)** | 장부를 다시 채우는 것. 길드가 살아있다는 증거를 남기는 것 |
| **욕구 (Need)** | 자기가 실패한 일을 남이 해내는 것을 봐도 괜찮다는 확인 |
| **두려움** | 마지막 등록관으로 죽는 것 |
| **결함 (Flaw)** | 자기 과거를 절대 말하지 않는다. 조언은 하지만 동행은 하지 않는다 |
| **말투** | 반말, 건조한 실무자 톤, 감상을 농담으로 덮는다. 문장이 짧고 지시형이 많다 |
| **자주 쓰는 표현** | "장부에 적어둘게", "…그래도 갈 거잖아", "여기부터는 내 일이 아니야" |
| **금기 주제** | 자신이 과거에 수집가였다는 사실. 열두 해 전에 무슨 일이 있었는지 |

**복선 배치**: 1-4(길드 옛 문장) → 4-00("우리 길드가 저기서 배워온 규칙") → 5-EPI(장부 첫 장을 새로 펴는 행위). 정체는 **명시적으로 밝히지 않는다**. 확정 텍스트 없이 세 번의 암시로 끝낸다 — 확장 콘텐츠 여지를 남기기 위함.

**연출 요구(→ designer)**: 배경보다 어두운 단색 실루엣 + 전용 텍스트박스 테두리색. 포트레이트 슬롯은 비우거나 길드 문장(저울+열쇠) 엠블럼으로 대체.

## 4. 화자 표기 규칙 — 내러티브 / game-narrative-designer

### 4-1. 화자 이름 표기 방식

| 화자 유형 | `speakerType` | 표기 규칙 | 예시 |
|----------|--------------|---------|------|
| 내레이터 | `narrator` | 이름표 **없음**. 화자명 필드는 빈 문자열 | `""` |
| 기본영웅 | `hero` | `base-heroes.json`의 `name` 그대로 | `아이리스` |
| 전직영웅 | `hero` | `ascended-heroes.json`의 `name` 그대로 | `번개의 아이리스` |
| 적/보스 | `enemy` | `enemies.json`의 `name` 그대로 | `고블린 왕`, `이자나미` |
| NPC 조력자 | `npc` | 직함 사용. 고유명 미공개 | `등록관` |
| 플레이어 | `player` | `수집가` 고정 (커스텀 닉네임 미사용) | `수집가` |
| 미공개 화자 | `unknown` | `???` 고정 | `???` |

**정식명 vs 별칭 원칙**
- 캐릭터가 **자기 입으로 이름을 말하기 전에는** 정식명을 쓰지 않는다.
- 아이리스는 첫 만남 컷씬 3번째 줄에서 스스로 이름을 말한다. 그 줄부터 `아이리스`. 이전 2줄은 화자 없는 내레이션이므로 문제 없음.
- 보스는 스테이지명이 이름을 이미 노출하는 경우(3-5 "죽음의 여신" → 이자나미) 예외적으로 첫 줄부터 정식명 허용. 스테이지명이 정체를 숨기는 경우(2-5 "균열의 수호자")는 `???` 유지.

### 4-2. 내레이터 vs 캐릭터 대사 시각 구분 (→ game-ux-designer 제안)

| 요소 | 내레이터 | 캐릭터 |
|------|---------|-------|
| 이름표 | 없음 | 좌상단 이름 태그 |
| 포트레이트 | 없음 (슬롯 비움) | 좌측 슬롯 표시 |
| 따옴표 | 없음 | `"..."` 포함 |
| 정렬 | 중앙 정렬 | 좌측 정렬 |
| 텍스트 색 | 흐린 회백색 | 순백 |
| 배경 처리 | 화면 전체 어둡게 + 박스 없음(레터박스) | 하단 대화박스 |
| 서체 스타일 | 이탤릭 계열 | 기본 |

**핵심 원칙**: 내레이터는 "화면 밖의 목소리"이므로 대화박스에 들어가지 않는다. 이 구분만으로 플레이어는 대사 주체를 무의식적으로 분리한다.

### 4-3. 플레이어(수집가) 대사 처리 정책 — **무언의 주인공 (Silent Protagonist)**

**결정: 수집가는 본작 전체에서 말하지 않는다. 단, 5-5 에필로그에서 정확히 2줄만 말한다.**

근거 3가지:

1. **필러 1(선택이 정체성이다)의 보호.** 기관 선택의 무게는 플레이어 본인이 져야 한다. 수집가가 "나는 발할라가 좋아"라고 말해버리면 플레이어의 선택이 아니라 캐릭터의 선택이 된다. 이 게임의 유일한 진짜 선택지는 대화창이 아니라 기관 선택 화면에 있다.
2. **필러 2(막지 않는 진행)와의 정합.** 선택지 없는 스킵 가능 서사에서 주인공이 말하면, 그것은 "플레이어가 하지 않은 말"이 되어 몰입을 깬다. 침묵은 스킵과 충돌하지 않는 유일한 화법이다.
3. **자산 현실.** 수집가는 포트레이트가 없다. 말하는데 얼굴이 없는 캐릭터는 존재감이 아니라 결핍으로 읽힌다.

**존재감 확보 대체 기법 — 반응 미러링(Reaction Mirroring)**
수집가의 대사 자리를 **다른 화자가 수집가의 반응을 받아 말하는 대사**로 채운다.

```
[등록관] "…그래도 갈 거잖아. 장부는 챙겨갈게."         ← 수집가가 고개를 저은 것
[아이리스] "…물어볼 사람을 잘못 골랐네, 등록관."       ← 수집가가 돌아서지 않은 것
[이자나미] "…그것이 친절이라고 생각하나."              ← 수집가의 침묵 자체가 답이 됨
```

**예외 1회의 설계 의도**: 25스테이지 내내 한 번도 말하지 않은 인물이 마지막에 두 마디를 한다. 침묵 정책의 유일한 목적은 이 두 마디를 게임 전체에서 가장 무거운 대사로 만드는 것이다. 이 예외를 다른 곳에 반복하면 정책 전체가 무효화되므로, **`speakerType: "player"`는 `cs_5_epilogue` 외 어떤 씬에서도 사용 금지**한다.

### 4-4. 정체 공개 연출의 표기 전환 규칙

```
[규칙 R1] 미공개 화자는 speaker="???", speakerType="unknown"
[규칙 R2] 정체 공개는 반드시 씬 경계에서만 일어난다 (씬 중간 전환 금지)
[규칙 R3] 공개 후 씬에서는 정식명으로 고정. 소급 변경 없음
[규칙 R4] revealAs 필드로 "이 화자는 나중에 무엇으로 밝혀지는가"를 데이터에 명시
          → 회상/도감 기능에서 소급 표기에 사용 (구현 시점 자유)
```

| 적용 사례 | 공개 전 | 공개 시점 | 공개 후 |
|----------|--------|---------|--------|
| 등록관 | `???` (chapter_1 진입 첫 5줄) | 같은 씬 6번째 줄, 자기소개 | `등록관` (영구) |
| 균열의 수호자 | `???` (`cs_2_5_boss_before` 전체) | 씬 경계 — `boss_after` 진입 | `균열의 수호자` |

> 2-5 수호자는 **보스 전 씬 내내 `???`를 유지**하는 것이 핵심이다. 등록관이 "아스가르드 양식"을 읽어내지만 이름은 끝내 부르지 않는다. 이름을 얻는 것은 죽은 뒤다 — "갑주 안이 비어 있었다"는 사실과 결합해 "역할만 남고 사람은 없었다"는 챕터 2의 주제를 표기 규칙 자체로 표현한다.

## 5. `src/data/story.json` 스키마 제안 — 내러티브 / game-narrative-designer

### 5-1. 파일 구조

```
{
  "_meta": { ... },
  "scenes": [ SceneObject, ... ]
}
```

### 5-2. SceneObject 필드 정의

| 필드 | 타입 | 필수 | 설명 |
|------|------|:---:|------|
| `id` | string | O | 씬 고유 ID. `cs_` 접두 + snake_case. 예: `cs_1_5_boss_after` |
| `trigger` | enum | O | 재생 시점 (§5-3) |
| `chapterId` | string \| null | 조건부 | `chapter_1` 형식. `chapter_enter`/`epilogue`에 필수 |
| `stageId` | string \| null | 조건부 | `1-1` 형식. `stage_enter`/`stage_clear`/`boss_before`/`boss_after`에 필수 |
| `heroId` | string \| null | 조건부 | `base_iris` 형식. `first_hero`/`hero_ascend`/`hero_evolve`/`evolve_gate`에 필수 |
| `cultId` | string \| null | 조건부 | `olympus` 형식. `hero_evolve`에만 필수 |
| `priority` | number | O | 같은 트리거에 복수 씬이 걸릴 때 재생 순서. 낮을수록 먼저 |
| `skipable` | boolean | O | **전 씬 `true` 고정** (필러 2). `false`는 사용하지 않는다 |
| `oncePerAccount` | boolean | O | `true`면 계정당 1회. 스테이지 반복 클리어 시 재생 안 함 |
| `background` | string \| null | X | 배경 키. 미지정 시 현재 화면 유지 |
| `bgm` | string \| null | X | BGM 키. 미지정 시 현재 BGM 유지 |
| `varsUsed` | string[] | X | 이 씬이 사용하는 치환 변수 목록. 빈 배열 기본 |
| `lines` | LineObject[] | O | 대사 배열. 6~12줄 권장 |

### 5-3. `trigger` enum (실제 필요한 것만)

| 값 | 발화 시점 | 조건 키 |
|----|---------|--------|
| `chapter_enter` | 챕터의 첫 스테이지 진입 직전 | `chapterId` |
| `stage_enter` | 스테이지 전투 시작 직전 | `stageId` |
| `stage_clear` | 스테이지 승리 정산 직전 | `stageId` |
| `boss_before` | 보스 스테이지 전투 시작 직전 (`stage_enter` 대체) | `stageId` |
| `boss_after` | 보스 스테이지 승리 정산 직전 (`stage_clear` 대체) | `stageId` |
| `epilogue` | 챕터 최종 보스 `boss_after` 직후 | `chapterId` |
| `first_hero` | 해당 기본영웅 **최초** 각성 완료 시 | `heroId` |
| `hero_ascend` | 해당 기본영웅 성장 마일스톤(한계돌파 등) 도달 시 | `heroId` |
| `evolve_gate` | 기관 선택 화면 최초 진입 시 | `heroId` |
| `hero_evolve` | 전직 확정 순간 (기관 결정 직후) | `heroId` + `cultId` |

> **`stage_enter`/`boss_before` 배타 규칙**: 보스 스테이지(`isBoss: true`)는 `boss_before`/`boss_after`만 사용하고 `stage_enter`/`stage_clear`는 정의하지 않는다. 컷씬 중복 재생 방지.

### 5-4. LineObject 필드 정의

| 필드 | 타입 | 필수 | 설명 |
|------|------|:---:|------|
| `speaker` | string | O | 화면 표시 이름. 내레이터는 `""`, 미공개는 `"???"` |
| `speakerType` | enum | O | `narrator` \| `hero` \| `enemy` \| `npc` \| `player` \| `unknown` |
| `portraitId` | string \| null | O | **캐릭터 ID**를 넣는다 (`base_iris`). 파일명 매핑은 `HeroAssetLoader`가 처리. 자산 없으면 `null` |
| `text` | string | O | 대사 본문. 캐릭터 대사는 따옴표 포함, 내레이션은 미포함 |
| `emotion` | enum \| null | X | `neutral` \| `calm` \| `tense` \| `angry` \| `sad` \| `joy` \| `awe` \| `resolute`. 연출 힌트 |
| `revealAs` | string \| null | X | 미공개 화자의 정체(캐릭터/적 ID). 도감·회상 소급 표기용 |

### 5-5. 선택지(choices) — 기본 없음

**본작 스토리 모드는 대화 선택지를 사용하지 않는다.**

근거:
1. **기관 선택 화면이 이미 이 게임의 선택지다.** 대화창에서 또 고르게 하면 진짜 선택의 무게가 희석된다.
2. 분기 대사는 5챕터 × 25스테이지 텍스트 물량을 최소 2배로 만든다. MVP 범위 밖.
3. 필러 2(막지 않는 진행)와 충돌한다 — 스킵 가능한 서사에 선택지가 있으면 "스킵하면 뭘 놓치지?" 불안이 생긴다.

**그럼에도 선택지가 있어야 할 자리 (확장 필드 제안, 구현은 보류)**

딱 한 곳이다 — **3-5 이자나미의 질문 직후**.

```
이자나미: "…그것이 친절이라고 생각하나."
   A. [고개를 끄덕인다]   → 이자나미: "…그렇게 믿는 편이 편하겠지."
   B. [고개를 젓는다]     → 이자나미: "정직하군. 그렇다면 왜 멈추지 않지."
   C. [침묵]              → 이자나미: "…대답하지 않는군. 그것도 대답이다."
```

이 자리에만 선택지를 두는 이유: 세 답변 모두 **결과가 같고 보상도 같다**. 스토리 분기가 발생하지 않는다. 순수하게 플레이어에게 자기 행위를 한 번 자각시키는 장치다. 즉 **무보상·무분기 플레이버 선택지**이며, 침묵 정책(§4-3)을 깨지 않는다(선택지 텍스트가 대사가 아니라 행동 묘사 `[...]` 형식이기 때문).

**확장 시 필요한 필드**

```jsonc
{
  "choices": [                       // LineObject 레벨에 선택적으로 부착
    {
      "id": "c_a",
      "text": "[고개를 끄덕인다]",
      "responseLines": [ LineObject, ... ],   // 응답 대사 (합류 후 씬 계속)
      "effects": []                            // MVP에서는 항상 빈 배열
    }
  ],
  "autoAdvanceMs": 8000,             // 미선택 시 자동으로 defaultChoiceIndex 적용
  "defaultChoiceIndex": 2            // 스킵/방치 시 C(침묵)
}
```

`effects`를 항상 빈 배열로 강제하면 "선택지는 있으나 게임 상태는 안 바뀐다"는 계약이 데이터 레벨에서 보장된다. 이 계약이 유지되는 한 선택지 추가는 안전하다.

### 5-6. `stages.json`과의 SSOT 관계 및 마이그레이션

| 대상 | SSOT 범위 | 형식 | 사용처 |
|------|---------|------|--------|
| `story.json` | **컷씬 대본** — 다중 화자, 포트레이트, 감정, 연출 | `lines[]` 배열 | 컷씬 재생기 |
| `stages.json`의 `story_intro` / `story_clear` | **스테이지 요약문** — 1~2문장 | 단일 문자열 | 스테이지 선택 카드, 결과 화면 서브텍스트 |

**두 필드는 역할이 다르므로 병존한다. 삭제하지 않는다.**
- `story.json` = "장면"
- `stages.json` = "캡션"
- **충돌 시 `story.json`이 우선**한다. 캡션은 대본의 요약이어야 하며, 대본에 없는 사실을 캡션이 주장해서는 안 된다.

**마이그레이션 방향 (3단계)**

| 단계 | 작업 | 담당 |
|------|------|------|
| M1 | `stages.json` 챕터 1~2의 `story_intro`/`story_clear` 20건을 §2-2 재작성본으로 교체 (파손 텍스트 제거). 챕터 3~5는 현행 유지 | executor |
| M2 | `src/data/story.json` 신설 + 챕터 1 전체 13씬 + 영웅 대사 씬 투입 (§5-7 샘플 그대로 사용 가능) | executor |
| M3 | 챕터 2~5 핵심 씬(각 3~4개) 확장 투입. 챕터 3~5 캡션 톤 다듬기 | game-narrative-designer → executor |

> **주의**: `story_intro`/`story_clear`는 현재 `src/types/stage.d.ts`에 타입 선언만 있고 코드에서 미사용이다. M1은 표시 기능 구현과 무관하게 **데이터 위생 작업**으로 선행할 수 있다.

**작성 문서**: `docs/story/NARRATIVE_STORY_MODE.md`
**담당 에이전트**: game-narrative-designer

### 작성 범위
- 5챕터 관통 드라마틱 퀘스천 + 챕터별 기승전결/감정곡선/후크
- 수집가 역할 변화 5단계 (구경꾼 → 개입자 → 피고 → 도전자 → 결정자)
- 시스템↔서사 접합점: 기관 선택 누적치의 5-5 회수 구조
- 챕터 1 전 스테이지 완전 대본 + 챕터 2~5 핵심 장면 대본
- 챕터 1~2 `story_intro`/`story_clear` 재작성본 20건
- 기본영웅 10명 × 3종 대사 세트 (전직은 24개 기관 루트 전부)
- 화자 표기 규칙 + 무언 주인공 정책
- `src/data/story.json` 스키마 + 즉시 투입 가능한 샘플 JSON
- 신규 조력자 1명(등록관) 캐릭터 시트

### 다른 분야에 넘기는 의존 항목

**game-level-designer**
1. 컷씬 트리거 지점이 스테이지 진입/승리 정산 사이에 삽입된다 — 1-3(Elite), 1-5(Boss)는 전투 전후 각각 컷씬 슬롯 필요
2. 1-4 고대 폐허는 "수집가 길드 옛 시설"로 확정 — 배치물에 저울+열쇠 문장, 벽면 열두 줄 각인 요소 필요 (환경 스토리텔링). **1-4 직전 15초 "벽 인지 구간"의 골렘 대사가 `evolve_gate`의 서사적 원인이 되므로(R-04), 해당 구간에서 "등록되지 않은 자 / 통과 불가" 대사가 반드시 선행 노출되어야 한다**
3. 1-3 버섯 군락지는 "방향을 얻지 못한 미정령"의 시각적 대조군 — 사망 이펙트가 포자가 아니라 **빛 산란**이어야 함
4. 5-1~5-3은 "모든 신화의 망자가 한 전장에 섞임"이 서사 근거 — 적 구성이 신화별로 분리되면 서사 붕괴

**game-ux-designer**
1. 컷씬 스킵은 **전 씬 상시 노출** (필러 2). 진행 차단 없음. 스킵해도 보상/진행 동일 보장
2. 내레이터/캐릭터 시각 구분 규칙 §4-2 참조 — 내레이터는 대화박스 밖(레터박스 중앙 정렬)
3. 등록관·적·보스는 포트레이트 자산이 없음 → 실루엣 + 전용 테두리색 처리 필요
4. `evolve_gate` 컷씬은 **1-4 진입 직전 · 기관 선택 화면 진입 직전** 재생(R-04 확정). 재생 체인: 1-3 클리어 → 10연 → 15초 벽 인지 구간(골렘 대사) → `evolve_gate` → 기관 선택 화면 → `hero_evolve` → 1-4. 선택 화면 자체가 이 게임의 유일한 진짜 선택지이므로 컷씬이 그 무게를 예열하는 역할
5. 대사 라인당 6~12줄 기준으로 씬이 설계됨 — 자동 진행 속도 튜닝 시 참고
6. 5-5 에필로그의 `speakerType: "player"` 2줄은 연출상 특별 처리 권장(다른 씬과 다른 톤/타이밍)

**game-system-designer**
1. `{{ascendedCount}}`(전직영웅 총 수), `{{institutionCount}}`(서로 다른 기관 수) 두 값을 컷씬 렌더 시점에 제공해야 함. **`institutionCount` 최소값 1 클램프 필요**
2. `stages.json`의 `story_intro`/`story_clear` 챕터 1~2 20건 교체 필요 (§2-2)
3. `enemies.json` 미정의 적 ID 보강 시 표시명을 본 문서와 일치시킬 것 (§7 이슈 4)
4. 컷씬 재생 이력은 `oncePerAccount` 기준으로 계정 저장 필요

**game-design-director (판정 요청)**
- §7 이슈 1(균열 원인 SSOT 충돌), 이슈 2(기관 12 vs 15) — 서사 척추에 직결되므로 상위 판정 필요
