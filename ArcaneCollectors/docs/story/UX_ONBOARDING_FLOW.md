## 1. 경험 목표 3단계 — UX / game-ux-designer

### 1-1. 세 개의 지평선

| 구간 | 플레이어가 **느껴야** 하는 것 | 반드시 **도달**해야 하는 지점 | 실패 신호 |
|------|------------------------------|------------------------------|----------|
| **첫 3분** | "무엇을 해야 하는지 헷갈릴 틈이 없다." 화면에 눌러야 할 것이 **하나뿐**이고, 눌렀더니 이겼다. | T-03 완료 = **1-1 클리어**. 첫 승리 + 첫 보상(젬 30 + achieve_001) 수령 | 3분 지점에 아직 메인 메뉴에서 서성이고 있음 |
| **첫 세션 (12~15분)** | "이 캐릭터는 **내가** 방향을 정해준 애다." 소유가 아니라 결정의 감각. | T-09 완료 = **첫 기관 선택 확정 → 전직영웅 1명 획득**, 이어서 T-11 = 1-5 보스 클리어, T-12 = 유휴전투 안내 | T-09 도달 전 이탈 |
| **첫 3일** | "내일 오면 열리는 게 있다." 결핍이 아니라 **예약된 기대**. | Day3에 두 번째 10연(2,700젬) 실행 + 2-5 돌파. 챕터2 완주로 무한탑·PvP 해금 | Day2 재접속 후 10분 내 이탈 |

### 1-2. 각 목표의 UX 번역

**첫 3분 — "선택지를 뺏어서 만드는 자신감"**
신규 유저의 그리드는 **0개**다. 화면에서 누를 수 있는 것은 상단 "현재 모험" 패널의 전투 시작 버튼 하나뿐. 이것이 Pillar ②(막지 않는 진행)와 모순되지 않는 이유: 막는 것이 아니라 **아직 존재하지 않는 것**이다. 잠긴 자물쇠 아이콘 13개를 보여주면 그것은 벽이지만, 아무것도 없으면 그것은 그냥 다음 방이다. **잠긴 메뉴를 회색 자물쇠로 표시하지 않는다 — 아예 그리지 않는다.**

**첫 세션 — "첫 각성보다 첫 결정이 먼저 기억되게"**
T-07(오마르 각성)은 손으로 하는 조작이고, T-09(기관 선택)는 머리로 하는 결정이다. 두 개가 4분 안에 붙어 있으므로, **연출 강도를 T-09 쪽에 몰아준다**. T-07은 1.5초 성공 연출로 짧게 끊고, T-09는 전용 컷씬(`evolve_gate`) → 3루트 카드 → 확정 다이얼로그의 3단 예열을 준다. 시스템 문서가 T-09를 유일한 F-2(되돌릴 수 없는 선택)로 분류한 것과 정확히 대응한다.

**첫 3일 — "세션 마지막 30초가 D1을 결정한다"**
T-12(유휴전투·오프라인 보상 안내)를 첫 세션의 **마지막**에 두는 것은 시스템 문서 4-3의 결정이고, UX적으로도 옳다. 게임을 끄기 직전이 "끄면 무슨 일이 일어나는가"를 설명할 유일한 타이밍이다. 이 안내는 **보상 예고까지만** 하고 수령은 Day2로 넘긴다.

## 2. 단계별 튜토리얼 플로우 — UX / game-ux-designer

### 2-1. 설계 원칙

1. **도구보다 목적이 먼저다.** "소환 버튼을 누르세요"가 아니라 "혼자서는 1-4를 못 넘는다"를 먼저 보여준 뒤 버튼을 준다. 시스템 문서가 1-4를 의도된 벽(0.86×)으로 배치한 것이 이 원칙의 데이터적 근거다.
2. **강제는 4개뿐이다.** T-03 / T-05 / T-07 / T-09. 나머지 8개는 전부 **안내(코치마크)** 수준이며, 무시해도 게임이 진행된다.
3. **텍스트가 아니라 손으로 가르친다.** 강제 스텝의 설명문은 **1문장·20자 이내**. 나머지 정보는 화면의 하이라이트가 말한다.
4. **모든 안내는 폴백을 갖는다.** 코치마크를 무시했을 때 진행이 멈추면 그것은 안내가 아니라 강제다.
5. **되돌아갈 곳이 항상 있다.** 튜토리얼 중에도 팝업의 ✕와 시스템 뒤로가기는 살아 있다(강제 스텝의 4개 마스킹 구간 제외).

## 3. 컷씬 재생 UX — UX / game-ux-designer

### 3-1. 판단: `PopupBase` 재사용이 아니라 신규 `CutsceneScene`

**결론: 신규 Phaser Scene `CutsceneScene`을 만든다. `PopupBase`를 상속하지 않는다.**

| 기준 | `PopupBase` 재사용 | **신규 `CutsceneScene`** |
|------|------------------|------------------------|
| 화면 점유 | 팝업은 **게임 위에 뜬다**. 부모 씬의 `update()`·트윈·타이머가 계속 돈다 (`IdleBattleView.startBattleCycle()`, `energySystem` 회복 타이머) | 부모 씬을 `scene.pause()`로 정지. 컷씬이 **화면을 점유**한다 |
| 호출 지점 | `MainMenuScene.openPopup()`에 종속. `activePopup` 단일 제약(V-4)에 걸려 **T-09에서 `AscensionPopup`과 동시 표시 불가** | 어느 Scene에서든 `scene.launch()`로 오버레이. `BattleScene`·`StageSelectScene`에서도 동일하게 동작 |
| 레이어 | depth 2000. T-09처럼 팝업 위에 얹으려면 2100 초과 depth 관리 필요 | Scene 단위 최상단. depth 경쟁 없음 |
| 입력 | 부모 씬의 `hitArea`들이 살아 있어 오작동 위험 | Scene 격리로 입력 완전 차단 |
| 생명주기 | 부모 씬 `shutdown()`이 `tweens.killAll()` / `input.removeAllListeners()` 수행 → 타이핑 트윈이 함께 죽음 | 독립 생명주기. 부모 전환과 무관 |
| 배경 유지 | 가능 | 가능 — `scene.pause()`는 **렌더는 유지**하므로 `background: null`(현재 화면 유지) 스키마 시맨틱이 그대로 성립 |

**호출 규약**

```
재생:  현재씬.scene.pause(현재씬.key)
       현재씬.scene.launch('CutsceneScene', { sceneIds: [...], stepId, onComplete })
종료:  CutsceneScene → scene.stop(self) → scene.resume(호출씬)
       → TutorialManager.commitStep(stepId, mode)
```

전투 전후 컷씬(`stage_enter`/`boss_before`/`stage_clear`/`boss_after`)은 **`TransitionManager`(V-6) 단일 경로에 훅**을 건다. 전투 진입 전 / 결과 씬 진입 전에 재생 대기열을 확인하고, 있으면 `CutsceneScene`을 먼저 태운다.

### 3-3. 내레이터 vs 캐릭터 대사의 시각 구분

|------|----------------------------------------|-----------------------------------|

| 대화박스 | **그리지 않음.** 박스 자체가 사라진다 | 표시 |

| 포트레이트 | 슬롯 비움 (이전 화자 포트레이트도 **페이드아웃**) | 좌측 슬롯 표시 |
| 정렬 | 중앙 | 좌측 |
| 폰트 | `sf(20)` `#CBD5E1` · `fontStyle: 'italic'` | `sf(22)` `#F8FAFC` · normal |
| 따옴표 | 없음 (데이터 원문 그대로) | `"..."` 포함 (데이터 원문 그대로) |

### 3-4. `portraitId: null` 폴백 연출 명세

내러티브 §7 이슈 5에 따라 **등록관·모든 적·보스·미공개 화자는 포트레이트 자산이 없다**. 즉 챕터 1의 13장면 중 아이리스 등장 줄을 제외한 **대부분이 이 경로를 탄다.** 폴백은 예외 처리가 아니라 **기본 연출**로 설계해야 한다.

| `speakerType` | 포트레이트 슬롯 | 대화박스 테두리색 | 이름표 배경색 | 이름 표기 |
|--------------|----------------|-----------------|-------------|----------|
| `hero` (자산 있음) | 포트레이트 이미지 | `#6366F1` (primary) | `#6366F1` | 캐릭터명 |
| `hero` (자산 로드 실패) | `HeroAssetLoader` 플레이스홀더 (V-8) | 동일 | 동일 | 동일 |
| `npc` (등록관) | **길드 엠블럼 실루엣** — 저울+열쇠, Graphics 벡터로 런타임 생성. 단색 `#C8A951` α0.55, 크기 260×260, 위치 (250, 700) | **`#C8A951`** (길드 금색) | `#C8A951` | `등록관` |
| `enemy` | **단색 실루엣** `#0B1220`(배경보다 1단계 어두움), 형태는 적 카테고리별 3종 프리셋(소형/인형/거대) 중 택1, 크기 340×460, 위치 (250, 900) | **`#EF4444`** | `#EF4444` | 적 표시명 |
| `unknown` (`???`) | 실루엣 + **가우시안 대신 α 0.35 감쇠**(저사양 대비 블러 미사용) | **`#64748B`** | `#64748B` | `???` |

**등록관 실루엣의 등장 연출**: 챕터 1 진입 첫 5줄은 `???`(회색 실루엣) → 6번째 줄 자기소개에서 **엠블럼이 금색으로 점등**(400ms 컬러 트윈) + 이름표가 `???` → `등록관`으로 크로스페이드. 내러티브 §4-4 규칙 R2("정체 공개는 씬 경계에서만")의 예외 케이스로 등록관은 같은 씬 안에서 공개되므로, **화자색 변화가 그 순간의 유일한 시각 신호**가 된다.

> 신규 이미지 자산 요구는 **0건**이다. 엠블럼·실루엣 3종 프리셋은 전부 Phaser `Graphics`로 그린다. 이는 컷씬 26장면 전체를 아트 의존 없이 출시 가능하게 만드는 조건이며, 나중에 포트레이트가 생기면 `portraitId`만 채워 무손실 승격된다.

### 3-5. 조작 규약

| 입력 | 동작 | 세부 |
|------|-----|------|
| **탭 (타이핑 중)** | 현재 줄 **즉시 완성** | 트윈 중단 후 전문 표시. `▼` 인디케이터 즉시 표시 |
| **탭 (줄 완성 후)** | 다음 줄 | 마지막 줄이면 컷씬 종료 |
| **롱탭 (500ms)** | **자동재생 토글** | 진동 20ms + AUTO 버튼 점등. 다시 롱탭 또는 AUTO 탭으로 해제 |
| **자동재생 중 탭** | 자동재생 **해제** 후 그 탭은 소비하지 않음 | 오조작으로 대사를 건너뛰는 사고 방지 |
| **[건너뛰기] 탭** | 이 컷씬 종료 | 확인 없음. 눌린 후 300ms 입력 잠금 |
| **[기록] 탭** | 지금까지의 줄 목록 오버레이 | 스크롤 가능. 닫으면 원위치 복귀 |
| **시스템 백 키** | [건너뛰기]와 동일 | — |

**타이핑 속도**

| 설정 | 속도 | 40자 대사 소요 |
|------|-----|--------------|
| 느림 | 18자/초 | 2.2초 |
| **보통 (기본)** | **30자/초** | 1.3초 |
| 빠름 | 60자/초 | 0.7초 |
| 즉시 | 0ms | 0초 |

**자동재생 대기 시간**: `줄 완성 후 대기 = 글자수 × 60ms + 700ms`, **하한 1.2초 / 상한 4.5초**.
검산: 아이리스 "말해두는데, 나는 네 것이 아니야. 내 힘은 내 것이다."(31자) → 31×60+700 = 2.56초. 40자 대사 12줄 씬 = 타이핑 1.3초 + 대기 3.1초 = 줄당 4.4초 × 12 = **53초** → 컷씬 1개 45~60초 목표(§2-2)와 일치.

**즉시 완성 규칙의 예외**: `player` 화자(5-5 에필로그 2줄)는 탭으로 즉시 완성되지 않는다. 게임 전체에서 유일하게 **끝까지 들어야 하는 2줄**이다. 이 예외는 다른 어디에도 적용하지 않는다.

### 3-7. 재감상 동선 — **도감(`CollectionPopup`) 안의 '이야기' 탭**

**결정: 도감에 둔다. 설정에 두지 않는다.**

| 근거 | 내용 |
|------|-----|
| **① 시스템 문서가 이미 약속했다** | Skip All 확인 다이얼로그 문구가 "**도감에서 다시 볼 수 있습니다**"로 확정되어 있다(시스템 6-2절). 화면이 이 약속을 배신하면 안 된다. **이것이 결정적 근거다** |
| ② 의미론적 정합 | 도감은 "모은 것을 다시 보는 곳"이다. 이 게임에서 컷씬은 수집물의 일부다 — 미정령을 줍고 이름을 주는 이야기 자체가 수집 대상이다 |
| ③ 설정은 콘텐츠가 아니다 | 설정은 음량·그래픽·계정을 다루는 곳이다. 콘텐츠를 설정에 넣으면 유저는 찾지 못한다(§6 3단계 도달 규칙 위반) |
| ④ 해금 시점 일치 | 도감 해금(1-5 클리어)이 재감상 수요 발생 시점과 정확히 겹친다. 첫 세션을 끝낸 직후가 "아까 그거 뭐였지"가 생기는 최초 시점이다 |

**'이야기' 탭 구조**

```
도감 (CollectionPopup)
├── 영웅        (기존)
├── 기관        (기존)
└── 이야기      ★신규 탭
    ├── 챕터 1 — 균열의 시작        [13 / 13]   ← 시청 수 / 전체

    │    └── 열두 개의 문             ▶ 재생   👁
    ├── 챕터 2 — 신들의 전장         [0 / 3]  🔒 (미도달은 제목도 숨김)

```

| 규칙 | 내용 |
|------|-----|
| 목록 표시 대상 | `story.viewedCutscenes`에 있는 것만. **미도달 컷씬은 제목조차 노출하지 않는다**(스포일러 차단) |
| 건너뜀 표시 | `story.skippedCutscenes`에 있으면 `⏭` 배지 + 목록 상단 "**놓친 이야기 N편**" 요약 |

## 4. 튜토리얼 스텝 데이터 스키마 — UX / game-ux-designer

### 4-1. 하이라이트 대상 지정 — 실제 구현의 최대 난점

메뉴 버튼은 `createBottomMenu()`가 **런타임에 생성**하는 익명 오브젝트다(V-2). JSON 데이터가 이것을 가리키려면 **안정적인 주소 체계**가 있어야 한다. 저장소에 `setName()` 사용처가 0건이므로(V-3) 규칙을 새로 정의할 수 있다.

**TID(Tutorial Target ID) 명명 규칙**

```
TID = {scopeKey}.{group}.{item}

scopeKey : Scene → 클래스명에서 "Scene" 제거 후 소문자   MainMenuScene → mainmenu
           Popup → openPopup()의 popupKey 그대로          AscensionPopup → ascension
group    : 화면 내 논리 영역                              menu | adventure | button | card | route | party | tab
item     : 도메인 ID 또는 기능 키. **기존 명명 규칙 승계**  base_iris / 1-4 / herolist / confirm
```

| 예시 TID | 가리키는 실제 오브젝트 | 소스 |
|---------|---------------------|------|
| `mainmenu.adventure.battle_start` | 현재 모험 패널 전투 시작 버튼 hitArea | `MainMenuScene.createAdventurePanel()` |
| `mainmenu.menu.ascension` | 각인 아이콘의 `hitArea` 사각형 | `createBottomMenu()` L1134 |
| `mainmenu.menu.gacha` | 소환 아이콘 hitArea | 동일 |
| `mainmenu.idle.view` | `IdleBattleView` 루트 컨테이너 | `createIdleBattleView()` |
| `gacha.button.multi_ticket` | `🎫 ×10 소환` 버튼 bg | `GachaPopup` L292 |
| `gacha.panel.rates` | 확률 고지 패널 (신규) | — |
| `ascension.card.base_omar` | 영웅 목록의 오마르 카드 | `_renderHeroListItem()` |
| `ascension.button.ascend` | 각성/각인 실행 버튼 | `_executeAscension()` 바인딩 대상 |
| `ascension.route.list` | 3루트 카드 전체를 감싸는 영역 | `_renderRouteItem()` ×3의 합집합 |
| `partyedit.button.auto` | 자동 편성 버튼 | `PartyEditPopup` |

**3단 해석(Resolution) 전략** — 어느 하나가 실패해도 진행이 멈추지 않는다.

| 순위 | 방법 | 등록 방식 | 실패 시 |
|:---:|------|----------|--------|
| **1** | **`TutorialTargetRegistry` 조회** | 오브젝트 생성 직후 `register(tid, gameObject, sceneKey)` 1줄 호출. 씬 `shutdown()`에서 `clearScope(scopeKey)` | 2로 강등 |
| **2** | **`scene.children.getByName('tid:' + TID)`** | 같은 지점에서 `setName('tid:' + TID)` 1줄 추가. Phaser 내장 API이므로 레지스트리가 유실돼도 동작 | 3으로 강등 |
| **3** | **`fallbackAnchor` 정적 좌표** | JSON에 base 720×1280 좌표 사각형을 직접 기입 | **하이라이트 없이 코치마크만 화면 중앙 하단에 표시**하고 스텝은 계속 진행 |

> **3단계가 존재하는 이유**: 하이라이트가 실패해도 튜토리얼이 멈추면 안 된다. 대상을 못 찾았을 때 강제 마스킹을 그리면 **홀 없는 검은 화면**이 되어 유저가 완전히 갇힌다. 따라서 **대상 해석 실패 = 마스킹 자동 해제 + 코치마크 강등**을 불변 규칙으로 못박는다.

**바운드 계산 규약**

| 오브젝트 유형 | 바운드 산출 | 비고 |
|--------------|-----------|------|
| `Rectangle` (hitArea) | `getBounds()` | 메뉴 버튼·모험 패널 버튼이 전부 이 유형 → **가장 안정적**. 등록 대상은 항상 hitArea를 우선한다 |
| `Text` | `getBounds()` | — |
| `Container` | `getBounds()` | 자식 전체 AABB |
| `Graphics` | **직접 사용 금지** | Graphics는 `getBounds()`가 신뢰 불가. 반드시 동반 hitArea를 등록 |
| 팝업 내부 요소 | 부모 컨테이너 변환 적용 후 월드 좌표로 산출 | `PopupBase.container`는 (0,0) 배치이므로 실질 변환 없음 |

**타이밍 규약**: 팝업/씬 생성 직후 1프레임 대기 후 해석한다(레이아웃 확정 전 조회 방지). 최대 **12프레임(약 200ms)** 재시도 후 3단계로 강등.

**Z 레이어 신설**

| 상수 | 값 | 용도 |
|------|---|------|
| `Z_INDEX.TUTORIAL_MASK` | **3000** | 딤 + 홀 마스크 (`POPUP_NESTED 2100` 초과) |
| `Z_INDEX.TUTORIAL_CONTENT` | **3010** | 핸드포인터·펄스 링·코치마크·설명문 |

### 4-2. 스텝 스키마 필드 정의

파일 위치 제안: `src/data/tutorial.json`. 구조는 `story.json`과 동일하게 `{ "_meta": {...}, "steps": [...] }`.

| 필드 | 타입 | 필수 | 설명 |
|------|------|:---:|------|
| `id` | string | O | `T-01` ~ `T-12`. **시스템 문서 §5-1 체계 승계** |
| `trigger` | object | O | `{ type, ... }`. type ∈ `account_created` \| `step_complete` \| `stage_clear` \| `scene_enter` \| `popup_open` |
| `targetScene` | string \| null | O | Phaser Scene 키. 팝업 스텝은 팝업이 뜨는 부모 씬 키 |
| `targetPopup` | string \| null | X | `popupKey`. 지정 시 스텝 시작에서 해당 팝업 자동 오픈 |
| `targetElement` | string \| null | O | **TID** (§4-1). 하이라이트 없는 스텝은 `null` |
| `fallbackAnchor` | object \| null | X | `{x,y,w,h}` base 720×1280. 3단 해석의 마지막 보루 |
| `instructionText` | string \| null | O | 강제 스텝 **20자 이내**, 안내 스텝 40자 이내 |
| `forced` | boolean | O | `true`는 **T-03/T-05/T-07/T-09 4개뿐** |
| `forceRule` | string \| null | X | `F-1` \| `F-2` (시스템 6-2절 판정 근거) |
| `skipGroup` | string \| null | X | `S-1`~`S-4`. `skipAll` 일괄 대상 판정에 사용 |
| `highlightType` | enum | O | `none` \| `coach_tooltip` \| `coach_arrow` \| `mask_pulse` \| `mask_choice` \| `spotlight_sequence` \| `cutscene_only` |
| `cutsceneIds` | string[] | X | `story.json`의 씬 ID 배열. **ID의 SSOT는 story.json**(내러티브 소유), 본 파일은 참조만 |
| `completionCondition` | object | O | `{ type, ... }` |
| `rewardId` | string \| null | O | **튜토리얼 고유 보상만.** 스테이지 첫클리어·업적 보상은 각 시스템 소관이므로 `null` |

| `resumeAt` | object | O | 이탈 후 재개 지점 |
| `estimatedSec` | number | X | 계측 기준값 |
| `nextStepId` | string \| null | O | 다음 스텝. `null`이면 튜토리얼 종료 |

**`completionCondition.type` enum**

| 값 | 추가 키 | 의미 |
|----|--------|------|
| `cutscene_end` | `sceneId` | 컷씬 재생 완료 또는 스킵 |
| `stage_clear` | `stageId` | 해당 스테이지 승리 |
| `stage_clear_all` | `stageIds[]` | 목록 전부 승리 |
| `gacha_result_confirmed` | — | 10연 결과 화면 닫기 |
| `popup_open` | `popupKey` | 팝업 진입 |
| `ascension_complete` | `heroId` | 각성/각인 완료 |
| `party_saved` | — | 파티 저장 또는 자동 편성 |
| `overlay_dismissed` | — | 안내 오버레이 종료 |

### 4-4. 세이브 필드와의 맞물림

시스템 문서 §5-2 스키마 / §6-1 `commitStep` 규약과의 대응 관계다. **새 세이브 필드를 요구하지 않는다.**

| 스텝 필드 | 세이브 필드 | 쓰기 시점 | 읽기 용도 |
|----------|-----------|----------|----------|
| `id` | `tutorial.completedSteps[]` | commitStep 3단계 | **멱등성 검사 SSOT**. 이 배열에 있으면 즉시 종료 |
| `id` (스킵 시) | `tutorial.skippedSteps[]` | commitStep 4단계 | 폴백 판정 · 스킵률 계측 |
| `nextStepId` | `tutorial.currentStep` | commitStep 7단계 | 재접속 시 진입 지점 |
| `cutsceneIds[]` | `story.viewedCutscenes[]` | commitStep 5단계 | 재노출 방지 + 도감 '이야기' 탭 목록 |
| `cutsceneIds[]` (스킵 시) | `story.skippedCutscenes[]` | commitStep 5단계 | 도감 `⏭` 배지 + 복귀 유저 "놓친 이야기" |
| `unlockMenus[]` | `onboarding.unlockedMenus[]` | commitStep 6단계 | **메뉴 그리드 렌더 SSOT.** `MainMenuScene.createBottomMenu()`가 이 배열로 필터 |
| `rewardId` | 각 보상 처리기 | commitStep 2단계 | — |
| `resumeAt` | (읽기 전용) | — | `PreloadScene` 분기에서 `currentStep`과 조합해 점프 대상 결정 |
| — | `tutorial.completed` | T-12 커밋 시 `true` | 재노출 영구 차단 |
| — | `onboarding.firstAscensionGrantUsed` | T-09 `grant_first_ascension` | 첫 각인 보증 1회 제한 |
| — | `onboarding.freeMultiPullUsed` | T-05 | 무료 10연 1회 제한 |
| — | `onboarding.idleIntroShown` | T-12 | 유휴전투 안내 재노출 방지 |

**금지 사항 재확인 (시스템 §6-1)**
- ❌ 컷씬 재생 완료 콜백에서 보상 지급 → 본 설계의 `rewardId`는 **`commitStep` 2단계에서만** 처리된다. `CutsceneScene`은 보상을 알지 못한다.
- ❌ 보상 지급을 씬 전환 이후로 미룸 → `commitStep`은 씬 전환 **전에** 호출된다.
- ❌ `currentStep`만으로 진행도 판단 → 모든 조건 재평가는 `completedSteps` 기준.

## 5. 스킵 정책과 복귀 유저 UX — UX / game-ux-designer

### 5-1. 스킵 경계의 화면 표현

시스템 문서가 준 F-1/F-2/S-1~S-4 규칙을 **화면에서 어떻게 읽히게 할 것인가**의 문제다. 규칙을 설명문으로 알려주지 않고 **UI 문법으로** 표현한다.

| 구간 | 화면 문법 | 유저가 무의식적으로 읽는 것 |
|------|----------|--------------------------|
| **강제 (F-1/F-2)** | 화면 딤 **72%** + 홀 + 핸드포인터 + 펄스 링. 딤 영역 탭 시 **무반응**(흔들림 피드백 없음) | "지금은 여기만 누를 수 있다" |
| **안내 (S-1~S-4)** | 딤 **없음**. 화살표 + 말풍선만. **다른 곳을 눌러도 다 동작한다** | "이건 제안이지 명령이 아니다" |
| **컷씬 (S-1)** | 우상단 [건너뛰기] 상시 | "언제든 나갈 수 있다" |
| **전투 필수 / 안내 스킵 (S-4)** | 안내 오버레이는 코치마크, 전투 자체는 통상 진입 | "이야기는 건너뛰어도 싸움은 해야 한다" |

**"딤이 있으면 강제, 없으면 안내"** — 이 단일 규칙이 12스텝 전체를 관통한다. 유저는 T-03에서 딤을 한 번 경험한 뒤, 딤이 없는 화면에서는 자유롭게 움직여도 된다는 것을 학습한다. **강제 4개 외에 어떤 스텝에서도 딤을 쓰지 않는다.**

**스킵 가능/불가 경계표**

| 스텝 | 개별 스킵 | Skip All 포함 | 화면상 스킵 진입점 |
|------|:--------:|:------------:|-----------------|
| T-01 | O | O | 컷씬 우상단 + 하단 [전체 건너뛰기] |
| T-02 | O | O | 컷씬 우상단 |
| **T-03** | **X** | **X** | 없음 (딤 상태) |
| T-04 | O (안내만) | O | 코치마크 탭으로 닫기 |
| **T-05** | **X** | **X** | 팝업 하단 [튜토리얼 전체 건너뛰기] — **강제 구간에서도 탈출구는 보인다** |
| T-06 | O | O | 코치마크 닫기 |
| **T-07** | **X** | **X** | 팝업 ✕는 살아 있음 (닫으면 폴백 재오픈) |
| T-08 | O | O | 팝업 ✕ / 자동 편성 |

| T-11 | 안내만 O | 안내만 O | 코치마크 닫기 / 컷씬 우상단 |
| T-12 | O | O | 코치마크 닫기 |

> T-05만 팝업 ✕가 비활성이다. 그 대신 **같은 화면에 Skip All 진입점을 둔다.** 유저가 "닫을 수 없다"를 발견하는 그 순간에 "대신 전체를 건너뛸 수 있다"를 같이 보게 만드는 것이 갇힘(entrapment)과 안내(guidance)를 가르는 선이다.

### 5-2. 중도 이탈 후 재접속 — 화면별 복구 규칙

**복구 원칙 3가지**
1. **커밋되지 않은 스텝은 처음부터.** 부분 진행 상태를 저장하지 않는다(복잡도 대비 효용 없음).
2. **이미 본 컷씬은 다시 틀지 않는다.** `story.viewedCutscenes` 검사 후 건너뛴다.
3. **조건이 이미 충족되어 있으면 조용히 자동 커밋한다.** 예: 이미 1-1을 클리어한 상태로 T-03에 복귀 → 마스킹 없이 즉시 커밋.

| 이탈 지점 | 재접속 시 도착 화면 | 컷씬 | 하이라이트 | 보상 |
|----------|-------------------|------|-----------|-----|
| T-01/T-02 컷씬 중 | `CutsceneScene` — 해당 컷씬 **처음부터** | 재생 | — | 미지급 (커밋 안 됨) |
| T-03 전투 중 | `MainMenuScene` | 이미 본 `cs_1_1_enter` 생략 | **마스킹 재부착** | 미지급 |
| T-03 전투 승리 후 결과 화면에서 이탈 | `MainMenuScene` — 조건 재평가로 **자동 커밋** → T-04 | `cs_1_1_clear` 미시청이면 재생 | T-04 코치마크 | 지급 |
| T-05 팝업 오픈 상태 | `MainMenuScene` → **팝업 자동 재오픈** | — | 마스킹 재부착 | 미지급 |
| T-05 티켓 소모 후 결과 확인 전 | 팝업 재오픈 → **결과 화면부터** (10연 결과는 이미 세이브에 반영) | — | 결과 확인 버튼 강조 | 결과 확인 시 봉투 지급(멱등) |
| T-07 각성 완료 후 팝업 닫기 전 | 팝업 재오픈 → 조건 재평가 **자동 커밋** → T-08 | — | T-08 코치마크 | 지급 |
| T-09 컷씬 시청 후 루트 미선택 | 팝업 재오픈 → **루트 목록부터** | `cs_evolve_gate_iris` **재생 안 함** | 3루트 하이라이트 | 미지급 |
| T-10/T-11 전투 중 | `MainMenuScene` | 진입 컷씬 시청분 생략 | 코치마크 | 미지급 |
| T-12 오버레이 표시 중 | `MainMenuScene` — **1회 재시도** | — | 스포트라이트 | 미커밋 시 미지급 |

**이탈 3일+ / 30일+ 처리** (시스템 §5-3 준수)

| 조건 | 처리 |
|------|-----|
| `tutorial.completed === true` | **재노출 없음.** 통상 로그인 |
| 미완주 + 이탈 3일+ | `currentStep`부터 재개. 진입 시 **"이어서 하기" 카드 1장** 표시: `현재: 챕터 1 - 1-3` / `[이어하기]` `[처음부터 다시 보기]` |
| 미완주 + 이탈 30일+ | 위 + **[처음부터 다시 보기]를 동등 위계로 격상**. 선택 시 컷씬만 재생, **보상 재지급 없음** (완료 스텝은 `completedSteps`가 차단) |

```
       │        │      받고 시작하기        │        │  h 64, 최우선 버튼

```

| 티어 | 요약 카드 | 보상 표시 | 건너뛰는 것 |
|------|----------|----------|-----------|
| ~3일 | **표시 안 함** | 오프라인 보상 팝업만 | 전부 |

**30일+ 시스템 리마인더 3줄** (요약 카드 하단, 각 1줄):
```
· 소환: 지금 티켓 10장으로 10연 1회가 가능합니다
· 각인: 기관을 고르면 영웅이 다른 존재가 됩니다
· 무한탑: 각인서와 각성의 불꽃이 나오는 곳입니다
```
30일 이탈자는 시스템 이름은 기억해도 **무엇을 위한 것인지**를 잊는다. 위치가 아니라 **목적**을 다시 말해준다. 튜토리얼을 다시 태우지 않는 이유이기도 하다 — 완주 유저에게 튜토리얼 재생은 모욕이다(시스템 §5-3).

**무엇을 건너뛰는가**: 복귀 유저에게 **컷씬을 자동 재생하지 않는다.** 놓친 이야기는 ③번 줄의 링크로만 제공한다. 23일 만에 돌아온 사람에게 2분짜리 컷씬을 들이미는 것은 이탈 유발이다.

| 강제 여부 | **절대 강제하지 않는다.** 완주 유저에게 딤을 씌우는 것은 신뢰 파괴 |

## 6. 접근성 · 품질 — UX / game-ux-designer

### 6-1. 텍스트 크기 (base 720 기준 → 실제 1080 렌더)

| 용도 | 호출 | base | **실제 px** | 판정 |
|------|-----|:----:|:----------:|------|
| 컷씬 대사 본문 | `sf(22)` | 22 | **33** | 본작 최대 본문. 한 손 세로 읽기 기준 충분 |
| 컷씬 내레이터 | `sf(20)` | 20 | **30** | 이탤릭 보정으로 본문보다 2px 작게 |
| 컷씬 화자 이름표 | `sf(18)` | 18 | **27** | — |
| 코치마크 본문 | `sf(16)` | 16 | **24** | — |
| 튜토리얼 지시문 | `sf(20)` 굵게 | 20 | **30** | 강제 스텝은 한 줄만 존재하므로 크게 |
| 메뉴 라벨 | `sf(11)` → **`sf(13)`로 상향 권고** | 13 | **19.5** | 현재 코드 `sf(11)`=16.5px. **읽는 텍스트 최소 기준 미달** |
| **읽는 텍스트 하한** | `sf(14)` | 14 | **21** | 이 아래는 배지·미세 표기 전용 |
| **절대 하한** | `sf(12)` | 12 | **18** | 배지 내부 숫자만 허용 |

> 메뉴 그리드 라벨 `sf(11)`(16.5px)은 4열 배치의 폭 제약 때문에 생긴 값이다. 그리드가 0~7개로 시작하는 온보딩 구간에서는 **열 수를 줄여 라벨을 `sf(13)`로 올릴 여유가 있다**: 항목 3개면 3열, 4개면 4열, 7개 이상이면 4열. 항목 수에 따라 열 수를 가변으로 두면 라벨 크기와 탭 타겟이 동시에 개선된다.

**텍스트 크기 조절 옵션**: 설정에 3단계(작게 0.9× / 보통 1.0× / 크게 1.2×). 컷씬 본문과 코치마크에만 적용. `sf(22) × 1.2 = 39.6px`에서도 대화박스 3줄 안에 들어가는지는 §6-2에서 검증한다.

### 6-2. 컷씬 텍스트 한 줄 최대 글자 수와 줄 수

```
대화박스 내부 폭 = base 600 (박스 672 − 좌 56 − 우 16)
실제 폭 = 600 × 1.5 = 900px
본문 폰트 = sf(22) = 33px   ← 한글은 대체로 폰트 크기 ≈ 글자 폭

줄당 최대 글자 수 = 900 ÷ 33 ≈ 27자   (하드 상한)
권장 상한 24자                          (안전 마진 3자)
최대 표시 줄 수 3줄  →  대사 1줄당 최대 81자 (권장 72자)
```

**"크게(1.2×)" 검증**
```
sf(22) × 1.2 = 39.6px  →  900 ÷ 39.6 ≈ 22자/줄  →  3줄 = 66자
```
66자를 넘는 대사는 크게 설정에서 잘린다. 따라서 **대본 1줄의 상한을 66자로 확정**한다.

**내러티브 대본 실측 검증**

| 대사 | 글자수 | 27자/3줄 | 22자/3줄(크게) |
|------|:-----:|:-------:|:-------------:|
| "그건 미정령이야. 이름도, 형태도, 갈 곳도 없는 것. 균열이 흘린 조각이지." | 40 | ✅ 2줄 | ✅ 2줄 |
| 내레이터 "한쪽에는 잿빛 전운이, 다른 쪽에는 아침의 금빛이 걸려 있었다. 경계선에서 두 하늘이 서로를 갈아내고 있었다." | 58 | ✅ 3줄 | ⚠️ 3줄 꽉참 |
| 내레이터 "헬헤임의 문이 열리고, 모든 신화의 망자가 한 전장으로 쏟아졌다. 그리스의 망자와 일본의 망자가 나란히 걷고 있었다." | 62 | ✅ 3줄 | ⚠️ 3줄 꽉참 |

| 항목 | 값 |
|------|---|
| 캐릭터 대사 최대 줄 수 | **3줄** |
| 내레이터 최대 줄 수 | **4줄** (박스가 없어 세로 공간이 더 있음, wrap 560 → 25자/줄 → 100자) |
| **대본 1줄 상한 (내러티브에 요청)** | **캐릭터 66자 / 내레이터 90자** |
| 초과 시 처리 | 자동 분할하지 않는다. **데이터 검증 스크립트로 빌드 시 경고** — 자동 분할은 화자의 호흡을 파괴한다 |

| 항목 | 규정 |

### UXI-03 확정 기록 — 오프라인 보상 상한 (ISS-01)

> **확정일**: 2026-09-02 · **작업**: T-Q5 · **확정값**: **24시간**

**어느 쪽이 정본인가 — 코드가 실제로 지급하는 쪽이다.**

두 구현을 코드에서 추적한 결과, **재화를 실제로 지급하는 경로는 하나뿐**이다.

```
MainMenuScene 오프라인 보상 모달 [받기]
  → SaveManager.claimOfflineRewards()
  → SaveManager.calculateOfflineRewards()
  → minutesAway = Math.min(minutesAway, 1440)   ← 24시간
  → SaveManager.addGold(...) / player.exp += ...
```

`IdleProgressSystem.calculateOfflineRewards()`는 같은 모달의 **표시값 병합**(`MainMenuScene.create()`의
`Math.max(saveManagerGold, dpsGold)`)과 보스 누적 데미지 계산에만 관여하고 **재화를 지급하지 않는다.**
따라서 유저가 실제로 받는 상한은 24시간이며, 12시간은 지급에 관여한 적이 없는 값이다.

시스템 문서 §4-3은 고지 상한으로 12시간을 제안했으나, 그 근거(`IdleProgressSystem.MAX_OFFLINE_HOURS`)가
지급 경로가 아니었다. **고지한 상한보다 실제 지급이 큰 상태**였으므로 신뢰 손상은 없었지만,
안내 문구를 12시간으로 굳히면 그 순간부터 고지와 지급이 어긋난다.

| 조치 | 내용 |
|------|------|
| SSOT 신설 | `src/config/onboardingConfig.js` → `OFFLINE_REWARD_CAP_HOURS = 24` |
| 이중 구현 해소 | `IdleProgressSystem.MAX_OFFLINE_HOURS`가 위 상수를 참조 (12 → 24) |
| `SaveManager.js` | **수정하지 않음**(수정 금지 파일). 대신 `tests/config/onboardingConfig.test.js`가 소스의 `1440` 리터럴을 읽어 SSOT와 일치하는지 잠근다 |
| 데이터 | `src/data/tutorial.json` T-12 `offlineCapHours`: `"TBD_ISS-01"` → `24` |

**남는 부수 효과 2건** (이 작업 범위 밖, 별도 판단 필요)

1. `IdleProgressSystem`의 누적 데미지 상한이 12h → 24h로 늘어난다. 다만 `accumulatedDamage`가
   보스 HP에서 잘리므로(100% 캡) 실질 증가폭은 제한적이다.
2. 모달 표시값이 `max(SaveManager, IdleProgressSystem)`이라 **표시 > 지급**이 될 수 있다.
   상한을 맞춰 격차는 줄었지만 두 공식이 다른 한 완전히 사라지지 않는다. 표시를 지급 경로로
   일원화하는 것은 경제 담당의 판단 영역이다.
