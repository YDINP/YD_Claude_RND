## 1. 재현한 로직

GachaSystem의 확률 로직을 그대로 이식했다 (Phaser/DOM 의존 제거, 값은 SSOT 주석과 일치):

```
RATES = { SSR: 0.015, SR: 0.085, R: 0.30, N: 0.60 }
PITY  = { softPity: 75, hardPity: 90, softPityBonus: 0.06, pickupPity: 180 }

determineRarity(currentPity):
  currentPity >= 90            -> SSR 확정
  ssrRate = 0.015 (+ (p-75)*0.06 if p>=75, cap 1.0)
  srRate  = 0.085 × 0.8        (p>=75 시)     # 소프트 피티 중 SR 축소
  rRate   = 0.30  × 0.9        (p>=75 시)     # 소프트 피티 중 R 축소
  순차 누적분포: SSR → SR → R → 나머지 N
pull 루프: currentPity++ 후 판정, SSR 시 피티 리셋
10연차: 결과에 SR/SSR이 없으면 마지막 1개를 SR로 교체 (피티 무영향)
픽업: pickupRate 0.5 (50/50), lost5050 캐리 또는 픽업피티 도달 시 확정
```

### 코드 감사에서 발견된 사양 불명확점 (시뮬 해석에 영향)

| # | 발견 | 영향 |
|---|------|------|
| B-1 | **`pickupPityCounter`는 어디서도 증가하지 않음** (`SaveManager.updateGachaCounter`는 pity/totalPulls만 갱신). `determinePickupCharacter`/`isPickupGuaranteed`는 읽기만 함 | 픽업 천장이 **현재 사실상 데드 코드**. 시뮬은 `_meta` 주석("180회 픽업 확정") 의도대로 **누적 뽑기 횟수 기반**으로 해석해 구현 |
| B-2 | `isPickupGuaranteed`는 `pickupPityCount >= pickupPity - 1`(179), `determinePickupCharacter`는 `>= 180` — off-by-one 불일치 | UI 표기와 실제 판정이 1회 어긋날 수 있음 |
| B-3 | `getPityInfo()`(:399)만 소프트 피티 증분을 `0.05`로 계산 (determineRarity는 `0.06`) | UI에 표시되는 "현재 SSR 확률"이 실제보다 낮게 나옴 |

## 2. 시뮬레이션 결과 (실측)

**조건**: 결정론적 시드(mulberry32), 100계정 × 10,000회 = 계정당 모드별 100만 회.

### 2-1. 이론 기대치 (해석해 — 편차 판정 기준선)

| 지표 | 값 |
|------|-----|
| SSR 사이클 길이 기대값 E[L] | **46.69연차** |
| 실효 SSR 출현율 (피티 포함) | **2.142%** (표기 1.5% 대비 +0.642%p) |
| 하드피티(90연차) 도달 확률/사이클 | **8.28×10⁻⁴ %** (≈ 12만 사이클당 1회) |

> 소프트 피티(+6%/회 × 15회) 때문에 실효 SSR율은 표기값보다 약 43% 높다. 이것은 오류가 아니라 설계된 천장 효과다. 따라서 "±0.5% 편차" 검증은 **이론 실효율 대비**로 수행한다.

### 2-2. 출현율 실측

| 모드 | SSR | SR | R | N | SSR 이론 대비 편차 | ±0.5%p 판정 |
|------|-----|----|----|----|------------------|------------|
| **10연차 모드** (SR 보장 적용, 실전형) | **2.147%** | **11.696%** | 29.846% | 56.312% | +0.005%p | **PASS** |
| 단발 모드 (대조군) | **2.153%** | 8.457% | 29.934% | 59.457% | +0.011%p | **PASS** |

- 10연차 모드의 SR +3.24%p는 **10연 SR 보장** 효과 (N→SR 1개 교체가 배치당 최대 1회 발동).
- R/N은 소프트 피티 구간 축소(×0.9/×0.8)와 보장 교체가 상쇄되어 명목치 부근 유지.

### 2-3. SSR 도달 분포

| 모드 | 평균 | 중앙값 | P95 | 최대 |
|------|------|--------|-----|------|
| 10연차 | 49.5회 | 51회 | 82회 | 85회 |
| 단발 | 45.7회 | 41.5회 | 80회 | 84회 |

### 2-4. 천장(hardPity 90) 검증

| 항목 | 결과 |
|------|------|
| SSR 없이 90연차 초과 위반 | **0건** (양 모드 공통, 기대값 0) |
| 관측 최장 무SSR 간격 | 89연차 (10연차) / 88연차 (단발) |
| 하드피티 90에서 강제 획득한 건수 | 0건 — 이론 도달 확률이 너무 낮아(8.28e-4%/사이클, 100만 회 기대 ≈ 0.18건) 미관측. **보장 로직 자체는 `pity>=90 → SSR` 단순 분기로 정상이며, 실질적 천장은 소프트 피티가 담당** |

✅ **결론: hardPity 90은 "위반 0건"으로 보장됨을 확인.**

### 2-5. 픽업 천장(pickupPity 180) 검증

| 항목 | 10연차 | 단발 |
|------|--------|------|
| 첫 픽업 획득까지 평균 | 75.9회 | 73.3회 |
| 첫 픽업 P95 / 최대 | 151 / 160회 | 161 / 166회 |
| **180회 내 첫 픽업 획득 계정 비율** | **100.000%** | **100.000%** |
| 계정당 평균 픽업 획득 (10k pull 기준) | 142.5회 | 143.1회 |

✅ **결론: 누적 180회 내 픽업 확정 100% 달성 확인.**
⚠️ 단, 이는 B-1의 "데드 카운터"를 정상 동작한다고 가정했을 때의 결과 — **실제 클라이언트 코드로는 픽업 천장이 작동하지 않으므로 수정 필요** (`SaveManager.updateGachaCounter` 또는 `pull()`에서 `pickupPityCounter`/`lost5050` 갱신 추가).

## 3. 일일 재화 수지 시뮬 (무과금, Lv.30 기준)

### 3-1. 파라미터

| 항목 | 값 | 출처 |
|------|-----|------|
| 최대 에너지 | 160 (=100 + 2×30) | EnergySystem.getMaxEnergy |
| 자연 회복 잠재량 | 288/일 (5분당 1) | ENERGY_CONFIG |
| 파밍 스테이지 | ch2-3 normal: 에너지 6 → 골드 1,500 / EXP 750 | stages.json |
| 일일 퀘스트 | 젬 110, 골드 1,800 | quests.json daily_001~005 |
| 주간 퀘스트 일평균 | 젬 50 | quests.json weekly |
| 10연 비용 | 젬 2,700 + **에너지 100** | GachaSystem MULTI_COST / ENERGY_COST_PER_PULL |

### 3-2. 에너지 수지

| 시나리오 | 가용 에너지 | 스테이지 실행 | 골드/일 | EXP/일 |
|----------|-----------|-------------|---------|--------|
| 보수적 (캡 도달 후 방치) | 160 | 26회 | **40,800** (파밍 39,000 + 퀘스트 1,800) | 19,500 |
| 낙관적 (288 전량 활용) | 288 | 48회 | **73,800** | 36,000 |

### 3-3. 가챠 지속 가능성

- 젬 수입 160/일 → 10연(2,700) 충족에 **약 16.9일**, 월 약 **1.8회 10연**.
- 신규 유저는 ch1 첫 클리어 점프(+620젬)로 초기 2~3회 10연 가능.
- **PRD-3 이중 비용 주의**: 가챠는 젬 외에 뽑기당 에너지 10을 소모 → 10연 1회 = 에너지 100 = 스테이지 16.7회 포기 ≈ **골드 25,000 기회비용**. 에너지가 병목인 성장기에는 가챠와 파밍이 직접 경쟁한다.
- 보석 에너지 충전(50젬→50에너지)은 골드 환산 12,500/50젬으로, 젬을 직접 10연에 쓰는 것(300젬=1뽑)보다 골드 수급 목적이라면 손해.

### 3-4. 밸런스 코멘트

1. **실효 SSR율 2.14% vs 표기 1.5%**: 확률 표기 고지 관점에서 표기값은 "기본 확률"임을 UI에 명시할 것 (소프트 피티 포함 안내). Genshin류 관행과 동일.
2. **월 1.8회 10연은 F2P로 매우 빠듯** — 이벤트 교환소(events.json: 이벤트당 gems 300~500)와 업적 젬이 실질 수입원. 본 시뮬의 160/일은 하한 추정치.
3. **B-1~B-3 버그 3건**은 밸런스 이전에 신뢰성 문제 → 우선 수정 권장.
