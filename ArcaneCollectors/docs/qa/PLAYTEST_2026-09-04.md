**1차 시나리오(1~8)는 전부 라이브에서 수행했다. 로컬 보완은 없다.**
2차(9~13, 전 기능 커버리지)는 팀 리드 지시로 **로컬 dev 서버** 대상이며 아직 실행하지 않았다.

## 이번 스윕과 `qa-sweep.mjs` 의 차이

`qa-sweep` 은 화면을 열어 겹침·터치타깃·콘솔에러를 훑는 정적 점검이다.
이 스윕은 **플레이해서 기능이 도는지**를 본다 — 레벨업하면 전투력이 실제로 오르는지, 배지 숫자가
실제 수령 가능 건수와 같은지, 전투에 들어간 아군이 내 영웅과 같은 존재인지.
그래서 이번에 나온 P0 두 건은 정적 점검으로는 잡히지 않는 종류다(화면은 멀쩡히 그려진다).

### "열렸다" 와 "보인다" 를 구분한다 — Modal alpha 대응

`Modal` 의 컨테이너 alpha 가 0 에서 복원되지 않아 **오프라인 보상 팝업이 화면에 아예 안 뜨던**
버그가 있었다(부모 0 × 자식 1 = 완전 투명). 객체 트리는 멀쩡하니 "팝업이 열렸다" 는 통과한다.
실제로 내 `renderStats` 도 alpha 를 보지 않아 **그런 팝업을 정상으로 셀 수 있었다** — 고쳤다.

시나리오 10 은 팝업마다 세 겹으로 본다.

| 겹 | 확인 | 비고 |
|---|---|---|
| ① 열림 | `activePopup` / `activePopupKey` | 기존 |
| ② 보이는 내용 | 조상까지 곱한 **누적 alpha ≥ 0.05** 인 텍스트만 센다. 투명해서 제외된 수(`hiddenTexts`)도 함께 남긴다 | 신규 |
| ③ **화면 픽셀** | Phaser `renderer.snapshotArea()` 로 화면 3지점을 실제로 읽어 조작 전후를 비교 | 신규 |

세 겹 중 하나라도 "안 보임" 이면 **P0** 로 기록한다.

**픽셀 판정에서 걸린 함정** — 로비는 명상 뷰의 오라·게이지가 계속 움직여서 아무 조작 없이도
표본이 흔들린다(같은 지점 79.2 → 81.7 실측). 그래서 단순 비교는 못 쓴다. **조작 없이 두 번 찍어
노이즈 폭을 먼저 재고**, 조작 후 변화가 `max(노이즈×3, 4)` 를 넘을 때만 "바뀌었다" 로 본다.
스냅샷은 **순차 호출**해야 한다 — Phaser 렌더러가 대기 중 스냅샷을 하나만 들고 있어서 동시에
부르면 앞선 요청이 타임아웃난다(실측).

**탐지기도 양방향으로 실증했다** (self-test 20/20):
- 정상 팝업 → 픽셀 변화 감지 (평균 75.0 → 28.1)
- `root.setAlpha(0)` 로 Modal 버그를 재현 → **"화면에 안 보임" 으로 판정** (76.1 → 78.9, 노이즈 범위 내)

`Modal` 을 직접 만드는 지점은 팝업 등록 맵 밖에 있다 — `MainMenuScene.js:425 · 546 · 1495`
(오프라인 보상·에너지 충전·파티 안내). 트리거가 상황 의존적이라 전수 자동화는 못 하고,
오프라인 보상 Modal 은 시나리오 14b 에서 실제로 띄워 확인한다.

### 인벤토리 스키마 변경 대응 (`[]` → `{ equipment, items }`)

장비가 저장 때마다 소실되던 버그의 근본 수정이다(`SaveManager._migrateInventorySchema`).
검수에 세 곳이 걸린다.

- **시나리오 13(레거시 C)** — 마이그레이션 후 `inventory` 가 `{ equipment, items }` 로 정규화되는지 확인하고, 이어서 `giveAllEquipment()` → 임의 저장 유발 → **장비 개수가 줄지 않는지**(소실 재발 감시)까지 본다.
- **시나리오 15(장비 장착)** — 구·신 스키마를 모두 받아 읽는다(`inventory.equipment` → `equipment` → 배열 순).
- **픽스처(확정)** — 팀 리드 지시로 **B 는 신 스키마 `{ equipment: [], items: [] }`, C 는 구 배열 그대로**. `qa-sweep.mjs` 와 `playtest-fixtures.mjs` **두 파일을 함께** 고쳤고 패리티 9/9 통과를 확인했다. 이 비대칭은 의도된 것이라 패리티 테스트에 단정으로 박아 뒀다 — B 를 배열로 두면 부팅 때 마이그레이션을 타서 **정상 v2 계정을 검증하는 픽스처가 하나도 없게 되고**, 마이그레이션 경로는 C 가 이미 담당하므로 커버리지가 겹친다.

### 팀 기준 — 지급되지 않는 보상은 화면에 표시하지 않는다

2026-09-05 하루에 이 계열에서만 6건이 나왔다(레이드 조각/SSR권, 친구 포인트 상점 3종,
타워 `ssrTicket`). 전부 **화면에는 있는데 지급 경로가 없는** 항목이었다.
시나리오 16 이 네 경로에서 이 기준을 강제한다 — **레이드 · 친구 상점 · 무한탑 · 스테이지 전투**.

| 단계 | 내용 |
|---|---|
| ① 표기 수집 | 화면에서 `골드 2840` 같은 수치 표기와 `SSR권`·`조각`·`장비 확률` 같은 **지급 경로 없는 라벨**을 긁는다 |
| ② 동작 | 수령 버튼을 누르거나 전투를 실제로 끝낸다 |
| ③ 대조 | 세이브 재화 스냅샷 차이를 낸다 |
| ④ 판정 | 지급 경로 없는 라벨이 남아 있으면 **P1** / 수치 표기보다 적게 들어오면 **P1** / 보상을 표시했는데 아무 것도 안 늘면 **P1** |

수치 없는 항목(`조각`·`SSR권`)은 대응 필드가 늘었는지만 본다 — **지급량 규칙을 테스트가 다시
구현하면 그게 또 하나의 진실 원본이 되어 언젠가 어긋난다.** 전투는 밸런스가 판정 대상이 아니므로
`setOneHitKill`/`setInvincible` 로 확실히 이기게 하고 끝나면 되돌린다(보상 계산은 치트와 무관한
경로를 그대로 탄다).

### `shutdown()` 삼켜진 예외

`src/main.js` 의 try/catch 가 삼키는 예외는 화면상 드러나지 않는다. **1건이라도 있으면 결함으로
센다** — 정리 코드가 조용히 실패하는 건 안 도는 것과 같다. 시나리오 9·10 양쪽에서
계측 훅이 잡은 예외와 `[main] …shutdown() 실패` 경고를 합쳐 판정한다.

**미검증으로 남을 가능성이 있는 것** — 장비 장착 → 스탯 반영(P2-10 때문에 장착 후보가 없다),
전투 중 상태이상 아이콘(발생 조건 통제 불가), 애니메이션·오디오(자동 판정 대상 아님).

**적 아트 화풍**은 재생성 진행 중(27/84)이라 리포트에만 적고 결함으로 세지 않는다.

## 전투 종료 후 결과 화면 미전환 — 원인 조사 (2026-09-07)

`battleEnded=true` 인데 결과 화면으로 넘어가지 않는 현상을 파고들었다. **서로 다른 두 가지**가 섞여 있었다.

### (A) 컷씬이 결과 화면을 덮는 경우 — 하네스 문제

정지 시점의 활성 씬이 `CutsceneScene` 이었고, 계측 결과 `endBattle` 1회 · `showBattleResult` 1회
**모두 정상 호출, 예외 0건**이었다. stage 첫 클리어의 `oncePerAccount` 컷씬이 결과 화면 위에 떠
`isActive('BattleResultScene')` 가 false 로 떨어진 것으로, 팀 리드가 메모리 트랙에서 관측한 것과 같다.
**게임 결함이 아니다.** 컷씬 넘김 횟수를 2 → 5 로 올리고, **컷씬을 넘긴 직후 결과 화면을 재확인**하도록
고쳤다(`viaCutscene`).

### (B) 씬 전이가 아예 없는 경우 — 게임 결함 후보

> **[3차 정정 2026-09-07] 아래의 원인 지목(`TransitionManager.isTransitioning` 잠금)은 철회한다.**
> 그때 값을 읽은 방식(페이지 안 동적 `import('/src/utils/TransitionManager.ts')`)이 **앱과 다른
> 싱글톤 인스턴스**를 준다는 것이 3차에서 실증됐다(`tests/e2e/module-identity-verify.mjs`).
> 따라서 `isTransitioning: false` 는 잠금 여부를 긍정도 부정도 하지 못한다.
> **증상 관측(60초간 씬 전이 0회, `endBattle:1 / showResult:1 / errors:[]`)은 그대로 유효**하고,
> 원인은 다시 미상이다. 하네스는 이제 앱이 받은 URL 로 import 하도록 고쳤으므로 다음 재현 때는
> 유효한 값이 남는다. 자세한 내용은 3차 절 "방법론 발견" 참조.

이쪽은 다르다. 60초 동안 **씬 조합 변화가 0회**다(이력에 `0s BattleScene` 하나뿐). 컷씬도 결과 화면도
뜨지 않는다. 그런데 계측값은 (A)와 같다:

```
probe: { endBattle: 1, showResult: 1, errors: [] }
scenes: ["BattleScene"]  (60초 내내)
turn 5, ended true, 적 전멸, 아군 생존
testSpeedBoost 3 / bs.battleSpeed 1
```

즉 `endBattle()` → `showBattleResult()` 까지 정상 실행되고 예외도 없는데 **씬 전환만 일어나지 않는다.**
`showBattleResult()` 의 마지막은 `transitionManager.victoryTransition(...)` 이고, 그 첫 줄은:

```ts
// src/utils/TransitionManager.ts:366
victoryTransition(scene, data = {}): void {
  if (this.isTransitioning) return;   // ← 조용히 무시된다
```

**`isTransitioning` 이 잠긴 채로 남아 있으면 전환이 아무 로그 없이 무시된다.** 같은 파일의 안전 타이머는
나중에 잠금을 풀지만(`console.warn('[TransitionManager] Safety timeout - force reset')`),
그때는 `victoryTransition` 이 이미 반환된 뒤라 **아무도 다시 부르지 않는다** → 영구 정지.

방증: `MainMenuScene` 은 전투 **시작** 전에 `transitionManager.reset?.()` 으로 이 잠금을 선제적으로 푼다.
같은 파일에 "잠긴 채로 두면 battleEntryTransition 이 조용히 무시되어 전투가 시작되지 않는다"는 주석이
달려 있다. **전투 시작 쪽에는 방어가 있고 전투 종료 쪽에는 없다.**

- 확인한다 — StageSelect 헤더 **[뒤로] 를 실제로 탭**했을 때(스택이 빈 상태) 모달이 되살아나고
  골드가 다시 들어오는가.
- 못 한다 — 유저가 "내비 스택이 빈 채로 StageSelect 에 있는" 상태에 어떻게 닿는가.
  그건 별도 확인이 필요하다.

## 방법론 발견 — 페이지 안 동적 `import()` 는 앱과 다른 싱글톤을 준다

`tests/e2e/module-identity-verify.mjs` (신규, 재실행 가능)

Vite dev 는 앱 모듈을 `/src/utils/TransitionManager.ts?t=1788759587926` 처럼 **무효화 타임스탬프가
붙은 URL** 로 받는다. 쿼리 없는 `import('/src/utils/TransitionManager.ts')` 는 다른 URL → 모듈이
새로 평가되고 **싱글톤도 새로 만들어진다.** A/B 대조 실측:

```
modA.default === modB.default   →  false
실제 전이(로비 [보스전] → slideTransition) 중 isTransitioning:
  A(쿼리 없는 경로)  true 관측  0 / 40
  B(앱이 받은 URL)   true 관측  3 / 40
```

같은 함정을 EnergySystem 에서도 봤다 — 내가 읽은 값은 `0/102`(생성자 초기값)인데 HUD 는 `102/102`
였고, 그 상태로 **에너지 20 짜리 보스전 진입이 정상 성공**했다. 즉 내 쪽이 틀렸다.

**따라서 2차 보고의 N-2 원인 진단(`TransitionManager.isTransitioning` 잠금)은 근거가 무효다.**
그때 읽은 `isTransitioning: false` 는 유령 인스턴스의 값이라 잠금 여부를 긍정도 부정도 하지 못한다.
**증상 관측(60초간 씬 전이 0회, `endBattle:1 / showResult:1 / errors:[]`)은 그대로 유효**하고,
원인 지목만 철회한다. 하네스는 이제 resource timing 에서 앱이 받은 URL 을 찾아 그걸 import 한다.

## 18a — 반복이 곧 증거다

간헐 결함이라 1회 통과는 증거가 아니다. **몇 회 돌렸는지를 결과에 남긴다**(`진입 N/M회, 정지 K회`).

- 회차마다 전투 **전·후**의 `isTransitioning` 을 **앱이 실제로 쓰는 인스턴스**에서 잰다
  (`transitionState()` — resource timing 에서 앱이 받은 `?t=` URL 을 찾아 import). 3차에 밝혀진
  유령 인스턴스 함정을 그대로 밟지 않기 위해서다.
- 정지가 나면 그 회차의 `diag`·씬 전이 이력·캡처(`18a-stall-round{N}.png`)를 남긴다.
- 정지가 **없어도** "다음 전투 시작 시점에 잠금이 남아 있는가"를 따로 본다 — 굳어 가는 전조를 잡는다.
- 보스전은 1회 20 에너지라 반복하려면 채워야 한다. `DebugManager.refillEnergy()`(→ 실패 시
  `setEnergy(999)`)를 쓴다. 이 치트는 앱의 `energySystem` 을 직접 갱신하므로 인스턴스 불일치가 없다.
- 한 번도 진입 못 하면 "정지 0회" 를 **통과로 세지 않고** 미검증으로 남긴다.

> `fix-transition-lock` 담당께 — 회귀 테스트에서 `isTransitioning` 을 읽을 때
> `import('/src/utils/TransitionManager.ts')` 를 쓰면 **앱과 다른 싱글톤**을 읽습니다.
> 실증: `tests/e2e/module-identity-verify.mjs` (`modA.default === modB.default → false`,
> 실제 전이 중 true 관측이 쿼리 없는 쪽 0/40 · 앱 URL 쪽 3/40).

## 18b — 무엇을 "잘림"으로 볼 것인가

`HeroDetailScene.showEquipmentList()` 는 팝업을 고정 높이로 두고 목록만 `ScrollContainer` 로 돌린다.
그래서 **후보가 뷰포트에 다 들어가는 경우에만** 잘림이 결함이다. 넘치면 잘리는 게 스크롤의 정상 동작이다.

| 검사 | 기준 |
|---|---|
| ① 뷰포트 ↔ 닫기 줄 | 스크롤 뷰포트 하단이 `[닫기]` 줄 위에서 끝나는가 |
| ② 다 들어가는 경우 | `후보 수 × 행 간격 ≤ 뷰포트 높이` 이면 **잘린 행 0건**이어야 한다 |
| ③ 넘치는 경우 | 첫 행만 온전히 보이면 통과 (잘림은 정상) |
| ④ 표시 ↔ 실제 | 화면 `보유 N개` == 세이브의 미장착 후보 수 |

- 행 간격은 소스 상수(`rowH = s(76)`)를 그대로 쓰지 않고 **실측**한다 — 렌더 1080x1920 / 기준
  720x1280 의 배율이 곱해지므로 상수를 그대로 비교하면 틀린다.
- 뷰포트는 행에 걸린 **마스크 도형의 bounds** 로 얻는다. 못 얻으면 자동 판정을 포기하고
  캡처 육안(`18b-picker-{i}-{슬롯}.png`)으로 넘긴다 — 통과로 세지 않는다.
- 슬롯 표기는 소스가 정본이다(`equipmentConfig.js`): 무기 · 방어구 · **악세서리** · 유물.
  ('액세서리'가 아니다 — 라벨 탐색이 통째로 빗나갈 자리였다)
- 후보 0개면 `보유한 {슬롯} 장비가 없습니다` 문구를 확인하고 잘림 검사는 건너뛴다.

## 18c — M-2 의 등급을 가른다

3차 보고에서 M-2 를 "유저 조작으로는 재현 안 됨" 으로 P2 에 뒀는데, 호출부 전수 확인 결과
**`catch` 폴백이 아닌 정상 분기 두 곳**이 데이터 없이 로비를 재시작한다(위 "M-2 의 문 전수" 표).
그중 `StageSelectScene` 헤더 **[뒤로] 버튼**은 유저가 실제로 누르는 버튼이다.

- 진입은 디버그 API 로 하되(로비에 StageSelect 직행 버튼이 없다), **나오는 길은 UI [뒤로] 탭**이다.
  내비 스택이 비어 있어 폴백 분기를 탄다.
- 모달 재노출 + 골드 증가가 함께 잡히면 **P1 로 올린다**(유저가 누르는 버튼으로 재화가 샌다).
  모달만 뜨고 지급이 없으면 P2 로 남긴다.
- **한계를 결과에 함께 남긴다** — 이 블록은 폴백 분기의 *결과*만 확인한다.
  유저가 "스택이 빈 채로 StageSelect 에 있는" 상태에 닿는지는 증명하지 못한다.
