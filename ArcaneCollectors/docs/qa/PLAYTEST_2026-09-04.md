## 출처 표기

**1차 시나리오(1~8)는 전부 라이브에서 수행했다. 로컬 보완은 없다.**
2차(9~13, 전 기능 커버리지)는 팀 리드 지시로 **로컬 dev 서버** 대상이며 아직 실행하지 않았다.
라이브가 정적 프로덕션 빌드임에도, 부팅 **전에** `localStorage.arcane_debug_enabled='true'` 를 심으면

빌드 모드와 무관하게 항상 노출된다(같은 파일 1178행). 두 가지를 확인한 뒤 라이브만으로 진행했다.

## 이번 스윕과 `qa-sweep.mjs` 의 차이

`qa-sweep` 은 화면을 열어 겹침·터치타깃·콘솔에러를 훑는 정적 점검이다.
이 스윕은 **플레이해서 기능이 도는지**를 본다 — 레벨업하면 전투력이 실제로 오르는지, 배지 숫자가
실제 수령 가능 건수와 같은지, 전투에 들어간 아군이 내 영웅과 같은 존재인지.
그래서 이번에 나온 P0 두 건은 정적 점검으로는 잡히지 않는 종류다(화면은 멀쩡히 그려진다).

### "열렸다" 와 "보인다" 를 구분한다 — Modal alpha 대응

`Modal` 의 컨테이너 alpha 가 0 에서 복원되지 않아 **오프라인 보상 팝업이 화면에 아예 안 뜨던**
버그가 있었다(부모 0 × 자식 1 = 완전 투명). 객체 트리는 멀쩡하니 "팝업이 열렸다" 는 통과한다.
실제로 내 `renderStats` 도 alpha 를 보지 않아 **그런 팝업을 정상으로 셀 수 있었다** — 고쳤다.

시나리오 10 은 팝업마다 세 겹으로 본다.

| 겹 | 확인 | 비고 |
|---|---|---|
| ① 열림 | `activePopup` / `activePopupKey` | 기존 |
| ② 보이는 내용 | 조상까지 곱한 **누적 alpha ≥ 0.05** 인 텍스트만 센다. 투명해서 제외된 수(`hiddenTexts`)도 함께 남긴다 | 신규 |
| ③ **화면 픽셀** | Phaser `renderer.snapshotArea()` 로 화면 3지점을 실제로 읽어 조작 전후를 비교 | 신규 |

세 겹 중 하나라도 "안 보임" 이면 **P0** 로 기록한다.

**픽셀 판정에서 걸린 함정** — 로비는 명상 뷰의 오라·게이지가 계속 움직여서 아무 조작 없이도
표본이 흔들린다(같은 지점 79.2 → 81.7 실측). 그래서 단순 비교는 못 쓴다. **조작 없이 두 번 찍어
노이즈 폭을 먼저 재고**, 조작 후 변화가 `max(노이즈×3, 4)` 를 넘을 때만 "바뀌었다" 로 본다.
스냅샷은 **순차 호출**해야 한다 — Phaser 렌더러가 대기 중 스냅샷을 하나만 들고 있어서 동시에
부르면 앞선 요청이 타임아웃난다(실측).

**탐지기도 양방향으로 실증했다** (self-test 20/20):
- 정상 팝업 → 픽셀 변화 감지 (평균 75.0 → 28.1)
- `root.setAlpha(0)` 로 Modal 버그를 재현 → **"화면에 안 보임" 으로 판정** (76.1 → 78.9, 노이즈 범위 내)

`Modal` 을 직접 만드는 지점은 팝업 등록 맵 밖에 있다 — `MainMenuScene.js:425 · 546 · 1495`
(오프라인 보상·에너지 충전·파티 안내). 트리거가 상황 의존적이라 전수 자동화는 못 하고,
오프라인 보상 Modal 은 시나리오 14b 에서 실제로 띄워 확인한다.

### 인벤토리 스키마 변경 대응 (`[]` → `{ equipment, items }`)

장비가 저장 때마다 소실되던 버그의 근본 수정이다(`SaveManager._migrateInventorySchema`).
검수에 세 곳이 걸린다.

- **시나리오 13(레거시 C)** — 마이그레이션 후 `inventory` 가 `{ equipment, items }` 로 정규화되는지 확인하고, 이어서 `giveAllEquipment()` → 임의 저장 유발 → **장비 개수가 줄지 않는지**(소실 재발 감시)까지 본다.
- **시나리오 15(장비 장착)** — 구·신 스키마를 모두 받아 읽는다(`inventory.equipment` → `equipment` → 배열 순).
- **픽스처(확정)** — 팀 리드 지시로 **B 는 신 스키마 `{ equipment: [], items: [] }`, C 는 구 배열 그대로**. `qa-sweep.mjs` 와 `playtest-fixtures.mjs` **두 파일을 함께** 고쳤고 패리티 9/9 통과를 확인했다. 이 비대칭은 의도된 것이라 패리티 테스트에 단정으로 박아 뒀다 — B 를 배열로 두면 부팅 때 마이그레이션을 타서 **정상 v2 계정을 검증하는 픽스처가 하나도 없게 되고**, 마이그레이션 경로는 C 가 이미 담당하므로 커버리지가 겹친다.

### 팀 기준 — 지급되지 않는 보상은 화면에 표시하지 않는다

2026-09-05 하루에 이 계열에서만 6건이 나왔다(레이드 조각/SSR권, 친구 포인트 상점 3종,
타워 `ssrTicket`). 전부 **화면에는 있는데 지급 경로가 없는** 항목이었다.
시나리오 16 이 네 경로에서 이 기준을 강제한다 — **레이드 · 친구 상점 · 무한탑 · 스테이지 전투**.

| 단계 | 내용 |
|---|---|
| ① 표기 수집 | 화면에서 `골드 2840` 같은 수치 표기와 `SSR권`·`조각`·`장비 확률` 같은 **지급 경로 없는 라벨**을 긁는다 |
| ② 동작 | 수령 버튼을 누르거나 전투를 실제로 끝낸다 |
| ③ 대조 | 세이브 재화 스냅샷 차이를 낸다 |
| ④ 판정 | 지급 경로 없는 라벨이 남아 있으면 **P1** / 수치 표기보다 적게 들어오면 **P1** / 보상을 표시했는데 아무 것도 안 늘면 **P1** |

수치 없는 항목(`조각`·`SSR권`)은 대응 필드가 늘었는지만 본다 — **지급량 규칙을 테스트가 다시
구현하면 그게 또 하나의 진실 원본이 되어 언젠가 어긋난다.** 전투는 밸런스가 판정 대상이 아니므로
`setOneHitKill`/`setInvincible` 로 확실히 이기게 하고 끝나면 되돌린다(보상 계산은 치트와 무관한
경로를 그대로 탄다).

### `shutdown()` 삼켜진 예외

`src/main.js` 의 try/catch 가 삼키는 예외는 화면상 드러나지 않는다. **1건이라도 있으면 결함으로
센다** — 정리 코드가 조용히 실패하는 건 안 도는 것과 같다. 시나리오 9·10 양쪽에서
계측 훅이 잡은 예외와 `[main] …shutdown() 실패` 경고를 합쳐 판정한다.

**미검증으로 남을 가능성이 있는 것** — 장비 장착 → 스탯 반영(P2-10 때문에 장착 후보가 없다),
전투 중 상태이상 아이콘(발생 조건 통제 불가), 애니메이션·오디오(자동 판정 대상 아님).

**적 아트 화풍**은 재생성 진행 중(27/84)이라 리포트에만 적고 결함으로 세지 않는다.

연출의 "느낌"·색 대비의 주관적 판단·오디오는 `manual()` 로 표시만 하고 캡처를 남긴다.
겹침 판정은 스크롤 컨테이너(마스크가 걸린 목록) 항목을 제외한다 — 제외하지 않으면 긴 목록마다 거짓 양성이 쏟아진다.
