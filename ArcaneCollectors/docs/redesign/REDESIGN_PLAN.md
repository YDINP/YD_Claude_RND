# ArcaneCollectors 비주얼 리디자인 계획

> **범위**: 게임 전 화면의 비주얼 리디자인 방향, 화면별 명세, 구현 태스크 분해
> **기준 해상도**: 1080×1920 (9:16). 이 문서의 모든 좌표는 **base 720×1280** 이며 `s()` = ×1.5 로 렌더된다.
> **선행 문서**: `docs/DESIGN_SYSTEM.md`(토큰 SSOT) · `docs/PROCEDURAL_ART_GUIDE.md` · `docs/story/UX_ONBOARDING_FLOW.md`(컷씬·온보딩 레이아웃 확정본)
> **동반 문서**: `tools/art/asset-spec.json`(생성 에셋 명세) · `docs/redesign/ASSET_USAGE_MAP.md`(에셋↔코드 매핑)
> **캡처 근거**: `docs/redesign/screenshots/before/` 29장 (2026-09-02, Playwright/Chromium, 게스트 신규 계정)

## 0. 요약

현재 빌드는 **에셋 파일이 사실상 0개**다. `public/assets/` 아래 포트레이트 91장을 제외한 모든 디렉터리가 `.gitkeep`만 있는 빈 폴더이며, 배경·아이콘·프레임·버튼은 전부 `TextureGenerator` / `BackgroundFactory` / `IconFactory`가 런타임에 그리는 프로시저럴 도형이다. 그 결과 화면은 **평면 그라디언트 + 원형 도형 + 시스템 이모지**의 조합으로 수렴했고, 어느 화면도 "이 게임의 화면"으로 식별되지 않는다.

동시에 **레이아웃 결함이 아트 부재보다 먼저 눈에 띈다**. 메인 메뉴에서 유휴전투 뷰가 현재 모험 패널 위에 겹쳐 그려지고, 영웅 상세는 4개 패널이 서로를 덮으며 화면 하단 55%가 비어 있다. 아트를 얹기 전에 이 겹침을 먼저 제거해야 한다.

이 문서는 세 가지를 정의한다.

1. **진단** — 화면별로 무엇이 왜 깨졌는가 (§1)
2. **방향** — 생성 일러스트 배경 + 반투명 글래스 패널 + 교단색 액센트로 통일하는 구체 규칙 (§2)
3. **명세와 태스크** — 화면별 좌표 명세(§3)와 파일 단위 구현 분해(§4)

## 2. 방향

### 2-1. 미학적 방향

| 항목 | 결정 |
|------|------|
| **개념 한 단어** | **신탁(Oracle)**. 신화 교단들이 균열을 통해 서로를 침범하는 세계. 차갑고, 신성하고, 위험하다 |
| **톤** | 모던 + 전문적. Blue Archive의 **정보 밀도와 정렬 규율**, NIKKE의 **딥 다크 + 발광 액센트**. `DESIGN_SYSTEM.md`의 하이브리드 기조를 그대로 승계한다 |
| **차별화 요소 (Cult Tint)** | 화면의 액센트 색이 고정이 아니라 **현재 맥락의 교단 색을 따른다**. 영웅 상세는 그 영웅의 교단색, 스테이지는 챕터 지배 교단색, 소환은 픽업 교단색. 패널 테두리·글로우·진행바가 함께 물든다 |
| **색상 이야기** | 베이스는 `bg.primary #0D0F1A` 심야 인디고. 그 위에 광원을 둘만 쓴다. `brand.primary #06BBFA`는 차가운 신호광으로 시스템과 조작을 맡고, `brand.accent #FFD60A`는 신성으로 보상과 희귀를 맡는다. 교단 12색은 **세 번째 광원**으로만 등장해 화면마다 표정을 바꾼다 |
| **사용자가 기억할 한 가지** | "패널 뒤로 그 화면의 그림이 흐릿하게 비친다". 전 화면 공통 글래스 패널 |

### 2-2. 금지 규칙

```
□ 시스템 이모지를 아이콘으로 사용           → 벡터 아이콘 또는 생성 아이콘으로 교체
□ 2색 선형 그라디언트 배경                  → 생성 일러스트 + 딤
□ 팔레트 밖 원색(#22C55E 등) 직접 사용      → DESIGN 토큰 경유
□ 패널을 불투명 단색으로 채우기              → 글래스 규칙(2-3) 준수
□ 한 화면에서 3개 이상의 라운드 반경 혼용     → sm/md/lg/xl 4단계만
□ 보라-흰색 그라디언트                      → 금지
```

### 2-3. 글래스 패널 규칙 (Phaser에 CSS blur가 없다는 제약의 해법)

Phaser 3.60 이상은 `gameObject.postFX.addBlur()`를 지원하지만 모바일 GPU에서 프레임당 비용이 크고, 배경이 매 프레임 바뀌지 않는 이 게임에는 과하다. **사전 블러 배경 페어링**으로 해결한다.

**구조 — 아래에서 위로 5겹**

```
① bg_{scene}            원본 배경 (cover-fit, depth 0)
② bg_{scene}_blur       같은 배경의 사전 블러본. 패널 사각형으로 crop 해서 그 자리에만  (depth 9)
③ 틴트 레이어           #0D0F1A alpha 0.55 라운드 사각형                              (depth 10)
④ 림 라이트             상단 1px #FFFFFF alpha 0.10 + 하단 1px #000000 alpha 0.25     (depth 10)
⑤ 아웃라인              2px, 교단색(없으면 brand.primary) alpha 0.45                  (depth 10)
```

②는 `scene.add.image(...).setCrop(panelX, panelY, panelW, panelH)`로 배경과 **동일한 화면 좌표에 정렬**해 얹는다. 배경이 움직이지 않으므로 시차가 생기지 않고, 진짜로 패널 뒤가 흐리게 비치는 결과가 나온다. 블러본은 ComfyUI 출력이 아니라 **빌드 스크립트가 원본에 가우시안 24px과 밝기 −15%를 적용해 굽는다**(`tools/art/build-blur.mjs`). 배경 1장당 파일 2개다.

**알파 값 표**

| 표면 | 틴트 알파 | 아웃라인 | 용도 |
|------|----------|---------|------|
| `glass.panel` | 0.55 | 2px 교단색 α0.45 | 씬 내 섹션 패널 |
| `glass.card` | 0.62 | 1px `#FFFFFF` α0.12 | 리스트 아이템, 영웅 카드 |
| `glass.popup` | 0.78 | 2px `brand.primary` α0.55 | 모달과 팝업 본체 |
| `glass.hud` | 0.70 | 없음, 하단 1px α0.25 | 상단바, 전투 HUD |

저사양 폴백은 한 줄 분기로 처리한다. `DESIGN.effects.useBlurBackdrop = false`이면 ②를 건너뛰고 ③의 알파를 0.55에서 0.88로 올린다.

### 2-4. 9-slice 프레임 규격

Phaser 네이티브 `scene.add.nineslice()`를 쓴다.

| 프레임 | 원본 | 코너 (L,R,T,B) | 최소 렌더 크기 | 용도 |
|--------|------|---------------|--------------|------|
| `frame_panel` | 512×512 | 96,96,96,96 | 192×192 | 씬 섹션 패널 |
| `frame_popup` | 512×512 | 96,96,120,96 | 192×216 | 팝업 본체 (상단 헤더 장식 포함) |
| `frame_card_N/R/SR/SSR` | 512×512 | 64,64,64,64 | 128×128 | 영웅·장비 카드 |
| `btn_primary/secondary/ghost` | 512×160 | 72,72,40,40 | 144×80 | 버튼 (가로 3-slice로도 동작) |

생성 규칙은 하나다. **코너 96px 안쪽에 의미 있는 형태를 넣지 않는다.** 늘어나는 변(edge) 영역은 해당 방향으로 균일한 패턴이어야 한다.

### 2-5. 아이콘 크기 체계

| 토큰 | base px | 렌더 px | 용도 |
|------|--------|--------|------|
| `icon.xs` | 16 | 24 | 인라인 수치 앞 |
| `icon.sm` | 24 | 36 | 리스트 항목, 재화 표시 |
| `icon.md` | 32 | 48 | 스탯, 탭 |
| `icon.lg` | 48 | 72 | 메뉴 그리드, 장비 슬롯 |
| `icon.xl` | 64 | 96 | 교단 엠블럼, 결과 화면 |

**터치 타겟은 아이콘 크기와 분리한다.** 시각 아이콘이 `icon.sm`(36px)이어도 히트 영역은 최소 `s(48)`=72×72px를 유지한다. 현재 상단바의 `s(44)`=66px 설정 버튼은 **72px로 상향**한다.

색상 대비율 검증은 이 문서의 범위가 아니다. 팔레트 확정 후 `accessibility` 에이전트에 감사를 위임한다.

### 2-6. 타이포 스케일

세 서체의 역할을 분리한다. 현재 대부분의 씬이 `'Noto Sans KR'`을 하드코딩하고 있어 `Orbitron`과 `Roboto Mono`가 사실상 죽어 있다.

### 2-7. 배경 적용 규칙

생성 원본은 SDXL 세로 최대치인 **832×1216**. 목표는 1080×1920이고 비율은 0.5625 대 0.684로 다르다.

```
1. 832×1216 생성
2. ×1.30 업스케일 → 1082×1581                (build 스크립트, Lanczos)
3. Phaser에서 cover-fit:
   scale = max(1080/1082, 1920/1581) = max(0.998, 1.214) = 1.214
   → 세로를 채우고 가로 약 24%를 잘라낸다
4. 그러므로 생성 프롬프트는 가로 중앙 60%에 주요 형태를 배치해야 한다.
   좌우 20%씩은 잘려나간다는 전제로 "centered composition, empty margins"를 넣는다.
```

전 화면 공통으로 배경 위에 `#0D0F1A alpha 0.35` 딤을 깔아 텍스트 대비를 확보한다. 전투 화면만 0.20으로 낮춰 배경을 더 보여준다.

#### T-29 완료 기록 — 포트레이트 페이로드 최적화

T-03으로 실제 아트가 살아나면서 첫 로드에 48.1 MB가 블로킹으로 내려왔다. 포트레이트 38장이 전부 1024×1024 PNG이고 장당 약 1.4 MB였기 때문이다.

지연 로드로 전환하는 대신 **포맷·해상도 변환**을 택했다. 메인 메뉴의 파티 표시와 유휴전투 뷰가 씬 생성 시점에 텍스처를 요구하고, 없으면 `ensureTexture()`가 플레이스홀더를 만들어 버린다. 즉시 로드를 지연으로 바꾸려면 `MainMenuScene`까지 함께 고쳐야 하는데, 변환만으로 96%를 줄일 수 있어 그럴 필요가 없어졌다.

**저장 구조**

| 디렉터리 | 내용 | 용도 |
|----------|------|------|
| `public/assets/characters/portraits/` | WebP 91장, 2.4 MB | 런타임. 긴 변 512 상한, q82. 256px 원본은 업스케일하지 않는다 |
| `public/assets/characters/portraits@2x/` | PNG 91장, 50 MB | 원본. 영웅 상세의 큰 표시에만 지연 로드 |

빌드 스크립트는 `tools/portraits/build-runtime-portraits.py`이며 멱등이다. 재실행하면 `portraits@2x/`를 원본으로 삼아 WebP만 다시 굽는다. 저장소에는 이미지당 정확히 2벌(런타임 WebP + 원본 PNG)만 남는다.

**측정 결과**

| 지표 | T-29 이전 | T-29 이후 | 변화 |
|------|----------|----------|------|
| 초기 포트레이트 전송량 | 48.10 MB | **1.86 MB** | −96.1% |
| 포트레이트 저장 용량 (런타임) | 48.88 MB | **2.16 MB** | −95.6% |
| 영웅 상세 추가 전송 (@2x 1장) | 0 MB | 1.43 MB | 온디맨드 |
| 메인 메뉴 도달 (localhost, 워밍) | 6,687 ms | **5,342 / 5,482 ms** | 약 −1.2 s |

localhost에서의 시간 단축이 전송량 감소폭에 못 미치는 것은 정상이다. 루프백에서는 대역폭이 병목이 아니라 디코드와 Vite 변환이 병목이기 때문이다. **실제 이득은 전송량 쪽에 있다.** 10 Mbps 모바일 회선 기준으로 48.1 MB는 약 40초, 1.86 MB는 약 1.5초다.

### 캡처

`tools/art/capture-before.mjs`를 복제해 `tools/art/capture-after.mjs`를 만들고, 동일한 29개 화면 상태를 현재 코드(포트 3000)로 캡처했다. `screenshots/after-full/`에 29장 전부 저장됨(누락 없음, before와 파일명 1:1 일치).

before 스크립트와의 차이는 두 가지다.

1. **프롤로그 컷씬 처리** — 신규 게스트 계정은 로그인 직후 T-01/T-02 컷씬이 자동 재생되며 `MainMenuScene`을 일시정지시킨다. `tests/e2e/skip-path-parity.mjs`의 `handleCutsceneIfAny`/`clearPrologue` 패턴을 이식해 Skip All로 2건을 처리했다.
2. **온보딩 메뉴 게이트 우회** — `MenuGridGate`(T-C7 점진 해금)가 도입되어 튜토리얼 미완료 신규 계정은 그리드 메뉴 13종이 전부 잠긴 채 그려지지 않는다. 캡처 스크립트가 `openPopup()`을 강제 호출해 팝업을 열어도, 잠금 상태에서는 콘텐츠 없이 튜토리얼 코치마크(다음 행동 유도 오버레이)만 남아 화면이 비어 보였다. 세이브에 `tutorial.completed = true`를 주입해 전량 해금한 뒤 `MainMenuScene`을 재시작하는 방식으로 우회해, before와 공정하게 비교 가능한 실제 콘텐츠를 캡처했다. `BattleResultScene`도 결과창 표시 전에 `stage_clear` 컷씬을 먼저 띄우므로 동일하게 Skip All을 선행시켰다.
