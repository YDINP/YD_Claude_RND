# 20회차 — foxtrot·hotel 사망 (2026-09-21)

> 사용자 상시 지시: **캐릭터가 사망하면 살리지 말 것.**
> 그리고 **죽을 때마다 기록해서 개선점을 찾아 업데이트하고 서버를 재시작할 것.**

## 무슨 일이 있었나

| | |
|---|---|
| 죽은 사람 | foxtrot, hotel (여덟 중 둘) |
| 시체 자리 | (82,18) · (106,20) |
| 기지 | x 25..64 언저리 |
| 잃은 것 | 포탑 6대 (70 → 64) |
| 발견 시각 | tick 1000075, 배포 직전 점검 중 |

둘 다 **기지 동쪽 한참 밖**에서 죽었다. 죽은 자리에서 기지까지는
스무 칸이 아니라 마흔에서 예순 칸이다.

## 왜

동쪽 밭이 커졌다. 실측:

```
우리 건물 중 x>70 에 선 것      276 채
그중 «아무 포탑도 안 덮는» 것    97 채
동쪽 끝 건물   x = 94
동쪽 끝 포탑   x = 104
```

포탑은 동쪽으로 x=104 까지 나가 있다. 그런데 «줄»이 아니라 «점»이다 -
276채 중 97채가 사거리 밖이다. 채굴기를 늘릴수록 밭은 동쪽으로 자라는데,
방어선은 그 속도를 못 따라갔다.

무리는 그 밭에서 일한다. `grow` 가 채굴기를 세우러 가고, `flow` 가 벨트를
깔러 가고, `tidy` 가 상자를 걷으러 간다. **일하러 가는 곳이 지켜지지
않았다.**

    지킬 것을 지키는 것과 «일하러 가는 곳을 지키는 것»은 다른 일이다.

`guard.py` 는 「값어치가 큰 무리부터」 지킨다. 그 기준은 옳지만, 값어치는
«거기 선 건물»로 센다. 사람이 자주 가는 곳이라는 사실은 값어치에 안
들어간다. 채굴기 한 대뿐인 변두리라도 무리가 매 순번 걸어가는 길목이면
지켜야 한다.

## 이번에 고친 것

- 방어선을 동쪽 밭까지 늘린다 (`guard.py --want` 를 올려 97채의 공백을
  메운다). 즉효약이다.

## 다음에 고칠 것

- `guard.py` 의 값어치 셈에 «무리가 가는 곳»을 더한다. 지금은 건물만
  센다 - 걸음이 잦은 곳이 곧 사람이 죽는 곳이다.
- 무방비 건물이 일정 수를 넘으면 증식(`grow`)을 멈춘다. 지킬 수 없는
  만큼 늘리는 것은 늘리는 것이 아니라 «내주는» 것이다.
- 밭으로 보내는 계획에 «가는 길이 지켜지는가»를 먼저 묻는다. 못 지키면
  그 밭은 나중 차례다.
