## 개선점

### 1. 기지가 뚫렸는데 아무도 안 물러났다 — 고침

마지막 말이 그대로 남아 있다:

```
적 36마리가 28타일 앞에 있습니다. ... 연구를 먼저 돌리겠습니다.
적 36마리가 18타일 앞에 있습니다. ...
적 36마리가 13타일 앞에 있습니다. ...
적 36마리가  0타일 앞에 있습니다. ...
bravo이(가) 쓰러졌습니다. 남은 사람 0명.
```

서른여섯 마리가 걸어 들어오는 동안 넷이 전부 제자리에서 일을 했다.
`flee_job` 에 이 한 줄이 있었기 때문이다:

```python
# 이미 기지에 있으면 더 물러날 데가 없다. 그럴 때는 차라리 일을 한다.
if math.dist(self.seat(worker), (home["x"], home["y"])) < 12:
    return None
```

적이 «밖»에 있을 때는 맞는 말이다. 기지가 이미 뚫렸을 때는 사형선고다.

**물러날 데가 없는 것이 아니라 «반대쪽»이 있다.** `threat` 에 떼의
무게중심(`swarm`)을 붙이고, 기지 안에 적이 있으면 그 반대로 60타일
물러난다.

### 2. 죽은 사람의 부탁이 여덟 시간을 살았다 — 고침

같은 세 줄이 519분 내내 반복됐다:

```
bravo | delta님, iron-chest 1개 갖다 드리겠습니다.
bravo | delta님 부탁을 못 지켰습니다: no crewmate named delta
bravo | give 실패: no crewmate named delta
```

delta는 오래전에 죽었다. 그런데 부탁은 안 내려갔다. 집으면 `take` 가
`posted` 를 지금으로 덮고, 못 지키면 다시 열린다. **그 두 줄이 만나면
시효가 영영 안 온다 — 못 채우는 부탁일수록 더 오래 산다.**

두 갈래로 막았다.

* 사람이 쓰러지면 그 사람 앞으로 붙은 부탁도 같이 내린다(`Board.forget`).
* 처음 붙은 때(`first`)를 따로 기억하고, 몇 번을 돌든 15분이면 내린다
  (`HARD_TTL`). 덮이는 시계로 시효를 재던 것이 근본 원인이다.

### 3. 공장이 교착이었다 — 위 둘의 아래에 깔린 것으로 본다

```

stone-furnace        no_ingredients                    4
```

**채굴기는 꽉 차서 멈췄고 화로는 비어서 멈췄다.** 둘 사이 열 몇 타일을
건너는 손이 없었다. 벨트 63칸과 인서터 14개가 이미 있었는데도 그렇다.

남은 한 사람(bravo)이 그 손이어야 했는데, 519분을 2번 고리에 썼다.
그래서 이것을 따로 고치지 않고 1·2번의 결과로 본다. **다음 판에서 같은
교착이 또 나오면 그때는 별개의 원인이다.**
