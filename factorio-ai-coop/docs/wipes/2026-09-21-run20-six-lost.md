# 20회차 — 여덟 중 여섯 사망 (2026-09-21, tick 1021424)

> 사용자 상시 지시: **캐릭터가 사망하면 살리지 말 것.**
> **죽을 때마다 기록해서 개선점을 찾아 업데이트하고 서버를 재시작할 것.**

## 무슨 일이 있었나

| | |
|---|---|
| 죽은 사람 | foxtrot, hotel, alpha, delta, charlie, echo (여덟 중 여섯) |
| 살아남은 사람 | bravo (발전소, 서쪽 먼 곳), golf |
| 잃은 것 | 포탑 70 → 55 대 |
| 남은 것 | 화로 48 · 채굴기 181 · 벨트 174 — **거의 그대로다** |
| 공습 규모 | 기지 120칸 안에 적 111마리 |
| 지나간 뒤 | 기지 150칸 안에 적 0 |

**기지는 멀쩡했다.** 포탑 쉰다섯 대가 물결을 다 막아 냈다. 죽은 것은
전부 «기지 밖 밭에 나가 있던 사람»이다.

## 왜 — 숫자 하나가 전부를 말한다

> 사용자: "이게 너무 포탑을 띄워놓으면 안되는이유야."

```
우리 건물          443 채
포탑 사거리 안     169 채   =  38%
무방비             226 채
포탑                55 대
```

포탑끼리의 «간격»은 오히려 촘촘했다 — 쉰다섯 중 쉰셋이 서로의 사거리
안에 있었다. 문제는 그 촘촘한 사슬이 **x=-63 에서 106 까지 펼쳐진 공장을
감싸기엔 너무 짧다**는 것이다. 사슬이 62%를 바깥에 두었고, 무리는 매
순번 그 바깥으로 걸어갔다.

    지킬 것을 지키는 것과 «일하러 가는 곳을 지키는 것»은 다른 일이다.

`guard.py` 의 목표가 「포탑 몇 대」였던 것이 잘못이다. **대수는 판이
커질수록 뜻을 잃는다** — 구리 화로를 「줄 끝 두 대」로 박아 두었다가
마흔 대 중 두 대가 된 것과 똑같은 함정이다.

## 두 번 죽었다 — 그리고 둘째 번이 더 나쁘다

처음에 foxtrot 과 hotel 이 (82,18)·(106,20) 에서 죽었다. 기록하고 방어선을
보강하는 동안 둘째 물결이 왔고, 그때 네 명이 더 죽었다.

**내가 후퇴를 지시한 뒤에도 죽었다.** charlie 와 echo 는 40칸 안에 적을
66마리씩 두고 있었고, 「창고로 걸어가라」는 지시는 그 66마리를 뚫고
가라는 말이었다.

    보낼 때 묻지 않으면, 부를 때는 이미 늦다.

이 저장소의 어느 고리도 보내기 전에 「거기 가도 되는가」를 묻지 않았다.
`flow` 는 벨트를 깔러, `grow` 는 채굴기를 세우러, `guard` 는 포탑을
세우러, `tidy` 는 상자를 걷으러 보낸다. 전부 «무엇을 할지»는 따지는데
«가는 길이 안전한지»는 아무도 안 본다.

## 이번에 고친 것

| 어디 | 무엇을 |
|---|---|
| `guard.py` | 목표를 「포탑 몇 대」에서 «덮인 비율»로. `covered()` 가 매 순번 443채 중 몇 채가 사거리 안인지 센다. `--cover 95` 가 완료 조건 |
| `grow.py` | 덮인 비율이 80% 미만이면 **안 늘린다**. 지킬 수 없는 만큼 늘리는 것은 늘리는 것이 아니라 내주는 것이다 |
| `danger.py` (신규) | 보내기 전에 묻는 `safe()`·`sift()`, 그리고 위험에 든 사람을 **하던 일을 끊고** 불러들이는 상시 고리. 취소를 먼저 하지 않으면 대기줄이 다시 밭 한복판으로 끌고 간다 |

## 다음에 고칠 것

- 각 고리(`flow`/`grow`/`tidy`/`guard`)가 `danger.sift()` 를 거쳐 자리를
  고르도록. 지금은 `danger.py` 가 «부르는» 일만 하고, 보내는 쪽은 아직
  안 묻는다.
- 먼 밭은 «초소»를 먼저 세우고 그 다음에 일한다. 포탑 없이 먼저 간
  사람이 이번에 죽었다.
- 총과 탄약을 들려 보낸다. 지금 무리는 맨손이다.
