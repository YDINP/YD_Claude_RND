## 1. 허브 컨셉

**세련된 모던 카지노 라운지.** 번쩍이는 네온이나 만화적인 과장 대신, 깊은 네이비 바탕에 브라스(황동) 금속 질감과
유리 하이라이트로 고급 멤버스 라운지의 절제된 분위기를 낸다. 서로 다른 게임(클래식 777, 프루트 피에스타 등)이
허브 안에서 나란히 놓여도 하나의 브랜드로 읽히도록, 모든 심볼은 동일한 3/4 탑뷰 카메라 각도·글로시 토이 렌더링·
스튜디오 조명 세팅을 공유한다. 모바일 퍼스트이므로 심볼은 실제 릴 렌더 크기인 **64px에서도 실루엣이 구분**되어야
하고, 이는 심볼마다 형태를 확실히 다르게(원형/막대형/별형/텍스트형) 만드는 것으로 확보한다.

### 금지 사항
- 포토리얼리스틱 렌더 (사람 얼굴, 실사 텍스처) 금지 — 토이 렌더 스타일 고정
- 지시하지 않은 텍스트·글리프 삽입 금지 (`BAR`, `WILD`처럼 심볼 고유 문자만 허용)
- 산만한 배경, 다중 오브젝트, 워터마크, 서명 금지
- 이미지에 그림자를 구워 넣는 것(baked-in drop shadow) 금지 — 그림자는 렌더러가 런타임에 합성

## 3. 에셋 스펙 표

| 종류 | 생성 크기 (gpt-image-1) | 후처리 | 최종 산출 | 용도 |
|---|---|---|---|---|
| 심볼(symbol) | 1024×1024 | 크로마키 제거 → 트림(bbox) → 리사이즈 | `512×512` webp (렌더러) + `128×128` webp (썸네일/페이테이블 UI) | 릴 위 심볼 스프라이트 |
| 릴 프레임(frame) | 1024×1536 | 릴 창 영역만 크로마키 제거(알파) → 리사이즈 | `1080×1350` webp (portrait) | 릴을 감싸는 브라스 베젤, 창 안쪽은 투명 |
| 배경(bg) | 1024×1536 | 리사이즈(크로마키 없음) | `1080×1920` webp (portrait) | 게임 화면 최하단 배경 |
| 로비 썸네일(thumb) | 1536×1024 | 리사이즈(크로마키 없음) | `640×400` webp | 로비 카드 목록 이미지 |

### 파일 명명 규칙
```
games/<id>/theme/symbols/<symbolId>.webp   # 512px, 렌더러가 실제 로드
games/<id>/theme/symbols/<symbolId>@thumb.webp  # 128px, 선택. 없으면 512본을 축소 사용
games/<id>/theme/frame.webp
games/<id>/theme/bg.webp
games/<id>/thumb.webp
```
`<symbolId>`는 반드시 `math.json`의 `symbols[].id`와 정확히 일치해야 한다 (예: `wild`, `seven`, `bar3`, `bar2`,
`bar1`, `bell`, `cherry`, `blank`). 렌더러가 이 id로 파일을 찾기 때문에 하나라도 어긋나면 심볼이 깨진다.

## 4. classic-777 컨셉 시트

**컨셉명: Brass Lounge 777 (브라스 라운지 777)**

선정 이유: 허브 톤이 "번쩍이지 않는 모던 카지노 라운지"로 이미 정해져 있다 (네이비 셸 + 브라스 포인트).
클래식 777은 허브의 1호 게임이자 가장 보수적인 3×3 5라인 구성이므로, 레트로 다이너(Neon Diner)나
라스베가스 네온 같은 시끄러운 컨셉 대신 **"고급 라운지의 빈티지 슬롯 머신"** 이미지를 잡는다. 어두운 네이비
공간에 브라스 금속과 벨벳 질감의 조명이 떨어지는 느낌으로, 허브 셸과 게임 화면 사이에 시각적 단절이 없다.

무드: 차분하고 고급스럽지만 심볼 자체는 클래식 슬롯의 원색(빨강 세븐, 초록 체리 잎)을 살려 게임성이 죽지
않게 한다. "라운지"는 배경/프레임의 무드이고, 심볼은 여전히 선명한 캐주얼 게임 색이다.

## 5. 릴 프레임 기획

브라스 베젤 프레임 1장이 릴 캔버스를 감싼다. 캔버스 1080×1350 (portrait) 기준 레이아웃:

```
y   0% ─┬─────────────────────────────┐
        │   상단 마퀴 (게임명 플레이트)   │  0% – 18%
y  18% ─┼─────────────────────────────┤
        │  브라스 베젤 사이드 필러       │
        │  ┌─────────────────────┐    │
        │  │                     │    │  릴 창(window)
        │  │   3×3 릴 창 영역      │    │  x  8% – 92%
y  22% ─┼──│  (#00FF00 채움)      │──┤  y 22% – 68%
        │  │                     │    │
y  68% ─┼──└─────────────────────┘──┤
        │  브라스 디바이더 스트립       │  68% – 74%
y  74% ─┼─────────────────────────────┤
        │  페이라인 레전드 스트립        │  74% – 92%
y  92% ─┼─────────────────────────────┤
        │  하단 브라스 받침대(그림자)     │  92% – 100%
y 100% ─┴─────────────────────────────┘
        x 0%                        100%
```

- **상단 마퀴 (0–18%)**: 어두운 네이비 플레이트에 브라스 스크롤워크 테두리, `CLASSIC 777` 워드마크를
  브라스 세리프 각인으로 새김. 게임마다 프레임을 따로 생성하므로 게임명을 직접 구워 넣는다.
- **릴 창 (x 8–92%, y 22–68%)**: 실제 게임 심볼은 PixiJS가 이 영역 위에 별도로 그린다. 프레임 아트에서는
  이 사각형을 평평한 `#00FF00`으로 채워 생성하고, 후처리에서 알파로 뚫어(키잉) 아래 레이어(릴 캔버스)가
  비쳐 보이게 한다. 창 안쪽 가장자리에 살짝 안으로 파인 느낌의 브라스 이너 베젤 하이라이트만 남긴다.
- **디바이더 (68–74%)**: 가느다란 브라스 스트립 하나로 창과 레전드를 분리.
- **페이라인 레전드 (74–92%)**: 브라스 스트립 위에 5개 페이라인 모양을 작은 라인 아이콘으로 음각 표현
  (가로줄 3개 + 대각선 2개) — `math.json`의 `paylines`와 시각적으로 대응.
- **하단 받침대 (92–100%)**: 무게감을 주는 짙은 그림자와 브라스 받침 몰딩.
- 좌우 사이드 필러(약 0–8%, 92–100% x축)는 상단부터 하단까지 이어지는 브라스 스크롤워크 기둥.

## 6. 생성 파이프라인

### 프로바이더
| 프로바이더 | 용도 | 알파 지원 |
|---|---|---|
| OpenAI `gpt-image-1` | 1차. `size` 파라미터가 1024×1024 / 1024×1536 / 1536×1024만 허용 | `background: transparent` 네이티브 지원 (심볼에 한해 크로마키 대신 사용 가능) |
| Google Gemini 이미지 모델 | 2차 (비용/쿼터 대체) | 알파 미지원 → 항상 불투명 반환 |
| 로컬 ComfyUI (기존 세팅 재활용) | 오프라인 폴백 | 워크플로우 의존, 기본은 불투명 |

**결정: 프롬프트 자체는 항상 `#00FF00` 크로마키 배경을 명시한다.** 이유는 세 프로바이더 중 Gemini와
ComfyUI가 알파를 못 뱉기 때문에, 프롬프트 레벨에서 프로바이더에 관계없이 동일하게 동작하는 방식(크로마키)을
기본값으로 고정한다. `gpt-image-1`을 쓸 때는 `theme-gen`이 `background: "transparent"` 파라미터를 추가로
얹어 크로마키 없이 바로 알파를 받을 수 있지만(선택적 최적화), 프롬프트 텍스트 자체를 바꾸지 않아도 되도록
설계한다 — 즉 크로마키 지시문은 "이 배경을 나중에 제거할 것"이라는 의도 표시이지, 실제 매 프로바이더에서
그린 배경이 그대로 남는다는 뜻은 아니다.

**키잉 절차 (`tools/theme-gen`, `sharp` 사용):**
1. `#00FF00` 근접 색상(허용 오차 포함)을 알파 0으로 치환
2. 디스필(despill): 남은 초록 색 번짐을 인접 픽셀의 보색으로 감쇠시켜 가장자리 초록 테두리 제거
3. 알파 채널 기준 바운딩 박스로 트림 (심볼 에셋만 해당 — 프레임은 창 영역만 부분 키잉이므로 트림하지 않음)
4. 목표 해상도로 리사이즈 후 `webp` 인코딩 (심볼 512/128, 프레임 1080폭, 배경 1080폭, 썸네일 640폭)

### 일관성 확보 전략
- 모든 프롬프트가 동일한 `stylePrefix` 문자열로 시작 (스타일 고정)
- 신규 게임 착수 시, 개별 심볼 프롬프트를 낱개로 생성하기 전에 **심볼 전체를 하나의 그리드 이미지로
  먼저 생성**해 조명 방향·재질·팔레트가 스타일 락(lock) 되었는지 눈으로 먼저 확인한 뒤 개별 심볼로 넘어간다
- `negative` 프롬프트도 전 에셋 공유 (금지 요소 목록, `prompts.json`의 `negative` 필드)

### QA 체크리스트
- [ ] 64px로 축소했을 때도 심볼 실루엣이 서로 구분되는가 (형태 기반, 색만으로 구분되면 안 됨)
- [ ] 심볼마다 실루엣이 명확히 다른가 (원형 vs 막대형 vs 별형 vs 숫자형)
- [ ] 의도하지 않은 텍스트/글리프 드리프트가 없는가
- [ ] 전 심볼의 조명 방향이 동일한가 (좌상단 하이라이트로 통일)
- [ ] 크로마키 제거 후 가장자리에 초록 번짐(디스필 실패)이 남지 않았는가
- [ ] 프레임의 릴 창이 정확히 8–92% / 22–68% 영역에 위치하는가 (렌더러 오버레이 좌표와 어긋나면 심볼이
      베젤에 가려지거나 창 밖으로 삐져나옴)

### 양산 절차 (신규 게임)
```bash
cp games/_template/art/prompts.json games/<새-게임-id>/art/prompts.json
# prompts.json 안의 "game", "concept", 심볼별 prompt를 새 게임 컨셉으로 교체
pnpm --filter @tgslot/theme-gen gen games/<새-게임-id>
```
