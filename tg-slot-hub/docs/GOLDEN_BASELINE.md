# live 6팩 회귀 기준점 (E0)

기준 커밋: `bb0ac97` 엔진(연쇄·클러스터 작업 착수 전). 계획: `docs/PLAN_candy-cluster-pop.md` §2 E0.

## 1. 골든 해시

- 테스트: `packages/slot-engine/src/golden.test.ts`, 기준값 `src/__golden__/hashes.json`
- 팩마다 시드 `golden-<id>`, 베팅액 `betLevels[0]`, 유료 2,000라운드(프리스핀은 끝까지)
- `JSON.stringify(SpinResult[])`의 sha256. 엔진을 고친 뒤에도 6/6 같아야 한다
- 의도한 변경일 때만 `UPDATE_GOLDEN=1 pnpm exec vitest run src/golden.test.ts`로 다시 쓴다

## 2. 2M 시뮬레이션 (seed 42)

`pnpm --filter @tgslot/rtp-sim sim <id> --spins 2000000 --seed 42` (총 베팅 100, 기본 게임 RTP, σ는 라운드 배수 기준).

## 3. 갱신 기록

| 날짜 | 팩 | 이유 | 이전 해시 → 새 해시 |
|---|---|---|---|
| 2026-11-26 | royal-diamond-777 | 검수 R10: 첫 화면(정지 위치 0)이 당첨처럼 보이지 않도록 `math.json` 스트립 5개를 원형 회전(릴별 2·8·4·10·36칸). 스크립트로 확인한 결과 스트립 외 필드는 바이트 동일, 각 스트립은 이전 스트립의 순수 회전이라 심볼 빈도·RTP는 그대로다(해석 RTP 0.9446965514194323 → …322, 부동소수 순서 차이). 같은 시드의 정지 위치가 가리키는 심볼만 달라져 해시가 바뀐다. 다른 5팩 해시는 그대로. 2M 표의 royal 행도 새 스트립으로 다시 쟀다(표본 실현값만 달라짐). | `3aba5a2e…99652e6` → `2e65d6ad…eaaf55e2` |

첫 화면 문제는 이후 허브가 `pickIdleStops`(slot-engine)로 당첨 없는 대기 정지 위치를 렌더러에 넘겨 모든 팩에서 풀었다. royal의 회전은 무해해서 되돌리지 않는다.
