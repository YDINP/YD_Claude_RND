# 피처 구매(보너스 바로 사기)

프라그마틱식 «Buy Feature»를 가상 코인 허브에 붙인 기록. 설계·가격표·환수율·제외 게임·남은 문제를 정리한다.

## 1. 설계

### 방식: 조건부 추출(거절 표본 추출)

- 구매 = 유료 기본 판 한 번을 «그 게임의 대표 보너스가 열리는 판» 분포에서 무작위로 뽑는 것.
- 서버는 **평범한 유료 판**을 새 서버 시드로 돌려 보고, 대표 보너스가 열린 판이 나오면 그 판을 쓴다. 결과를 고치지 않고 거르기만 한다.
- 그래서 저장된 시드·nonce(`${seed}:${nonce}`)로 평소 판과 똑같이 재현된다(provably fair 유지). 엔진 테스트가 12팩 × 20판에서 «찾은 판 = 공개 시드로 다시 돌린 판»과 잭팟 추첨값까지 같은지 확인한다.
- 탐색 상한 `FEATURE_BUY_MAX_TRIES = 20,000`(가장 드문 보너스 평균 시도 수 약 221의 약 90배). 상한에 닿으면 아무것도 차감하지 않고 `503 FEATURE_BUY_SEARCH_FAILED`.

### API 규칙

- 비용 = `price × totalBet`, **한 번만** 차감한다(원장 사유 `feature_buy`, refId = roundId). 진입 판 베팅은 비용에 들어 있어 `spin_bet`은 생기지 않는다.
- 응답에 `featureBuy: { cost }`. 같은 키 재전송은 저장된 라운드(`rounds.feature_buy_cost`)로 같은 응답을 준다.
- 거부: 프리스핀(주문 라운드 포함) 진행 중 → `409 FEATURE_BUY_BLOCKED reason=FREE_SPINS_ACTIVE`, 더블업 판돈이 살아 있음 → `reason=GAMBLE_OPEN`(만료된 판돈은 평소처럼 돌려주고 진행), 구매 없는 게임 → `409 FEATURE_BUY_UNAVAILABLE`, `debug`와 함께 → `400`.
- 베팅은 허용 단계·레벨 상한 이하(`400 INVALID_BET`/`BET_LOCKED`), 잔액이 비용보다 적으면 `402`.
- XP·미션(«N번 돌기»는 1회, «당첨»은 비용 이상)·리더보드(최고 배수 = 당첨 ÷ 비용, 스핀 수 1)·잭팟 적립·허브 세션 손익은 비용을 이 판의 베팅액으로 본다.
- 구매 판은 더블업을 열지 않는다.
- `/games/:id/math`는 math.json 원본을 그대로 주므로 `featureBuy`가 실린다.

## 2. 가격 정하는 법

가격 = E[구매 라운드 총당첨 | 보너스 진입] ÷ 기본 목표 환수율(94.5%).
라운드 총당첨 = 진입 판 당첨 + 이어지는 프리스핀 전부(잭팟 제외). 코인 리스핀·말판·룰렛은 진입 판 안에서 끝난다.

**반올림 단위**: 10 → 5 → 1 → 0.5 → 0.2 → 0.1 순서로 시도해, 반올림이 만드는 환수율 오차가 0.3%p 이하인 가장 큰 단위를 쓴다(모든 베팅 단계에서 비용이 정수 코인인 단위만).
명세의 «5·10 단위»를 그대로 쓰지 않은 이유: 우리 대표 보너스 기대값이 16~77배(가격 17~82배)로 작아서, 가격 17에서는 1 단위 반올림만으로도 환수율이 최대 2.8%p 움직인다. ±1%p를 지키려면 소수 한 자리가 필요했다(예: shiba 16.8배 → 베팅 25에 420코인).

**표본**: 진입 판은 서버와 같은 거절 표본 추출로 뽑고, 프리스핀이 이어지는 게임은 진입 판마다 이어지는 프리스핀을 독립 RNG로 10번 돌려 평균한다(진입 판 하나가 i.i.d. 표본 하나 → 평균은 불편, 표준오차는 표본 표준편차/√진입 수).

## 5. 허브 화면

- 조작부 윗줄(속도 세그먼트 오른쪽)에 «피처 구매 / 베팅 ×가격» 버튼. 스핀 줄과 다른 줄이라 390px에서 스핀 버튼을 좁히지 않는다.
- 누르면 매번 확인 시트: 무엇이 바로 시작되는지 한 줄(«스캐터 3개 이상이 떨어진 판으로 시작해요. 프리스핀이 바로 열려요.»), 비용(«베팅 20 × 100배 = 2,000»), 잔액, [취소] [구매].
- 오토스핀·프리스핀·스핀(연출) 중·더블업·잔액 부족이면 버튼이 흐려지고, 누르면 시트 대신 이유 한 줄을 잠깐 띄운다. 시트가 열린 사이 잔액이 모자라지면 [구매]가 꺼지고 이유가 보인다.
- 구매 판은 평소 스핀과 같은 흐름이라 보너스 진입 연출(커튼·팝업·말판·룰렛·리스핀)을 그대로 탄다.
- 도움말 배당표 탭 위쪽에 «피처 구매» 한 단락(가격·시작 판·평균 환수율).

## 6. 같이 고친 것: 게임 주소 새로고침 기본 베팅

- 증상: 게임 주소로 바로 들어와 새로고침하면 기본 베팅 규칙(잔액 0.2~0.5%)이 로비를 거쳤을 때와 다른 값을 냈다.
- 원인: 기본 베팅은 레벨 베팅 상한 안에서 고르는데, 바로 들어오면 허브의 레벨 정보(`/me`)가 아직 없어서 `store/game.ts load()`가 상한을 100으로 가정했다. 체험판에서 재현: 레벨 6(상한 200)·잔액 6만 → 로비 경유 200, 바로 새로고침 100.
- 고침: `load()`가 레벨 정보가 없으면 math와 함께 `/me`를 받기 시작하고(진입은 기다리지 않는다), 도착했을 때 베팅이 아직 잠정 값 그대로면(사용자가 안 바꿨고 판·프리스핀·재시도 키가 없으면) 상한을 알고 다시 고른다. `/me`가 실패하면 예전처럼 보수적 가정으로 남는다. 테스트 2개(`store/gameDefaultBet.test.ts`). 고친 뒤 체험판: 레벨 6·잔액 6만 로비 200 / 바로 새로고침 200, 신규 1만 둘 다 20(`docs/qa/feature-buy/default-bet-direct-reload-*.webp`).
- 명세 예시(classic 20 → 50)는 같은 경로에서 잔액이 10,000을 넘었을 때의 규칙 값(10,001~ → 50)과도 겹친다. 잔액 10,000 경계에서 20/50이 갈리는 것은 규칙 그대로다(QA 로그 «기본 베팅 경계»).

## 7. 남은 문제·결정할 것

- **가격 모양**: ±1%p를 지키느라 21.2·45.2·17.7 같은 소수 가격이 됐다. 정수(또는 5·10 단위)를 원하면 각 팩 math를 조금 손봐 E[라운드]를 맞추거나, 환수율 허용폭을 넓혀야 한다.
- **가격 수준**: 프라그마틱은 보통 100배다. 우리 대표 보너스가 16~82배라 구매가 싸게 보이고, 신규 잔액 1만으로도 베팅 100이면 1~5번 산다. 책임 설계(손실 속도) 관점에서 구매에 하루 횟수 제한이나 레벨 조건을 둘지 결정이 필요하다.
- **지역 규제**: 실제 돈이 오가는 곳 일부(예: 영국)는 피처 구매를 금지한다. 가상 코인이라 해당하지 않지만, 나중에 상품 판매와 엮이면 다시 볼 것.
- 오토스핀에서는 살 수 없다(명세대로). «구매 오토»는 넣지 않았다.
