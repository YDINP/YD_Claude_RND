# Royal Diamond 777 / 로열 다이아몬드 777

> 물음표 타일이 한꺼번에 같은 심볼로 뒤집히는, 브라스 라운지의 정통 후속작.

5릴 3행 10라인. 카탈로그 #3.

빈칸은 없다. 릴의 모든 칸이 실제 심볼이다.

## RTP를 두 조각으로 나눠 놓은 이유

허브 잭팟은 하우스가 재원을 대고 베팅액의 1.5%를 되돌린다. 그래서 게임 페이테이블은
**94.5%**를 겨냥하고, 잭팟을 얹어 체감 96%가 된다. 잭팟은 수학 모델 밖(API의 잭팟 원장)에
있어 `computeExactRtp`에 잡히지 않는다.

| 조각 | 값 | 소유자 |
|---|---|---|
| 기본 게임 RTP (`rtpTarget`) | 94.5% | `math.json` 페이테이블 |
| 허브 잭팟 기여 (`jackpotContribution`) | 1.5% | API의 잭팟 원장 |
| **체감 총 RTP** (`rtpTotalTarget`) | **96.0%** | 플레이어가 실제로 받는 값 |

## 실측 수치

정지 조합이 2억 9천만 개라 전수 조사가 불가능하지만 **해석적으로 정확한 값**을 쓴다.
미스터리 공개 심볼로 조건부화하면 릴 독립이 복원되기 때문이다 (아래 메커닉 절 참고).

| 지표 | 값 |
|---|---|
| 산출 방식 | **해석적 계산** (`method: "analytic"`) |
| 기본 게임 RTP | **94.4697%** (목표 94.5% 대비 -0.030%p) |
| 체감 총 RTP | **95.970%** |
| 적중률 | **35.05%** (표본 추정, `audit` 유료 200만 스핀·시드 42) |
| 관측 최대 배수 | **335.40x** (같은 표본의 라운드 최댓값, 프리스핀 누적 포함) |
| 정지 조합 수 | 291,753,252 |

RTP 구성:

| 조각 | 기여 | 비중 |
|---|---:|---:|
| 페이라인 | 76.871% | 81.4% |
| 스캐터 | 2.668% | 2.8% |
| 프리스핀 | 14.930% | 15.8% |

프리스핀 진입 확률은 **1.0725%**, 약 93스핀에 한 번이다.
스캐터 3개 이상이면 프리스핀 8회가 열리고 승리에 2배가 곱해진다. 리트리거로 8회가 더 붙는다.

적중률과 최대 배수는 표본에서 나온 값이라 표본이 바뀌면 달라진다. RTP만 정확값이다.

| 표본 | 적중률 | 최대 배수 |
|---|---:|---:|
| `audit` 200만 스핀(시드 42) | 35.05% | 335.40x |
| 시드를 바꿔 200만 스핀씩 4번(2026-11-26) | 34.96~35.09% | 200~458x |
| `sim --exact` (20만 스핀, 유료 스핀의 기본 게임 승리만) | 35.07% | 120.00x |

시드 4개 평균 RTP는 94.460%로 정확값 94.4697%와 -0.009%p 차이다. 최대 배수는 꼬리값이라 표본이 클수록 커진다.
적중률은 5릴 권장 범위(25~35%)의 위쪽 끝이다. RTP 정확값이 목표에 -0.03%p로 붙어 있고 표본 오차 안이라 고치지 않았다.

재현:

```bash
pnpm --filter @tgslot/rtp-sim sim royal-diamond-777 --exact
pnpm --filter @tgslot/rtp-sim run audit royal-diamond-777 --shards 4   # docs/RTP_AUDIT_royal-diamond-777.md
```

## 미스터리 공개

```json
"mutations": [
  { "type": "mystery", "symbol": "mystery",
    "weights": { "seven": 4, "diamond": 6, "bar3": 8, "bell": 14, "cherry": 26 } }
]
```

릴이 멈춘 뒤, 화면의 **모든** 미스터리 칸이 가중 추첨된 **하나의** 심볼로 동시에 바뀐다.
칸마다 따로 뽑지 않는다. 따로 뽑으면 칸 사이의 상관이 사라져 아래 해석식이 깨진다.

공개 풀에서 와일드와 스캐터는 제외된다. 공개 후 스캐터가 늘면 프리스핀 트리거 확률이
흔들리기 때문이고, 스키마가 이를 강제한다.

**왜 해석적으로 풀리는가.** "공개가 s였다"는 조건 아래에서 그리드는 미스터리 심볼이 s로
치환된 것과 같다. 릴별 심볼 분포는 미스터리의 확률 질량이 s로 옮겨간 것이고, 릴끼리는
여전히 독립이다. 따라서

```
E[승리] = Sum_s  P(공개 = s) x E[승리 | 미스터리 -> s]
```

이고 각 조건부 항은 기존 페이라인 닫힌 식 그대로다. 근사가 아니라 정확값이다.
`rtp.test.ts`가 이 값이 몬테카를로와 3 표준오차 안에서 맞는지 고정해 둔다.

## 첫 화면

렌더러는 모든 릴을 정지 위치 0에서 시작한다(`initialStops` 미지정). 그래서 **각 릴 스트립의 0~2번 칸이 게임을 처음 열었을 때 보이는 화면**이다.
2026-11-26 이전에는 다섯 릴이 모두 0번에 `wild`를 두어 윗줄이 와일드 5개(최고 배당 모양)로 열렸다. 당첨이 아닌데 당첨처럼 보이는 화면이었다.

스트립을 원형으로 돌려 와일드·스캐터가 없고 어느 페이라인도 당첨이 아닌 화면으로 바꿨다. 새 스트립은 옛 스트립을 왼쪽으로 k칸 돌린 것이다(`새[i] = 옛[(i + k) % 길이]`).

| 릴 | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| 돌린 칸 수 k | 2 | 8 | 4 | 10 | 36 |

| 행 | 릴 1 | 릴 2 | 릴 3 | 릴 4 | 릴 5 |
|---|---|---|---|---|---|
| 윗줄 | `seven` | `diamond` | `bar2` | `bell` | `bar1` |
| 가운데 | `bar2` | `bell` | `bar1` | `cherry` | `bar3` |
| 아랫줄 | `bar3` | `cherry` | `diamond` | `seven` | `mystery` |

- 첫 두 릴에서 같은 심볼이 페이라인 위에 나란히 서지 않게 골랐다(체리 2개 지급과 닮은 모양도 없다).
- 원형 회전은 균등 추첨이라 확률이 그대로다. 해석 RTP가 회전 전과 소수 16자리까지 같다(`0.9446965514194322`).
- 대신 같은 시드로 뽑은 스핀의 격자는 달라진다. `packages/slot-engine/src/__golden__/hashes.json`의 이 게임 골든 해시는 새로 만들어야 한다(`UPDATE_GOLDEN=1`).
- 스트립을 다시 고치면 0~2번 칸을 눈으로 확인한다.

당첨 칸은 하이라이트 상자와 위 연출로 표시한다. 당첨 선을 긋지 않고, 화면 전체를 가로지르는 광택도 쓰지 않는다.

- **전환 클립**: 진입은 소스 `royal-exit.mp4`(저장소 밖 `D:/park/transition-sources/`)의 8.30→11.00초를 등속으로 쓰고(소스 11.04초의 이음매 앞에서 끊음) 마지막 0.30초는 끝 프레임을 붙들고, 끝 8프레임(0.5초)은 복귀 클립의 첫 프레임(흐린 판)으로 디졸브한다(`opaqueMs 2500`, 블러 시그마 2.0). 복귀는 같은 소스의 가변속 컷(0.00~0.60초 등속 + 0.60~5.10초 1.875배)이다. 구간 근거는 `docs/TRANSITION_DESIGN.md` 3-3·3-6.
  **알려진 흠**: 복귀는 끝에 쐐기가 가장자리 25~30% 남는다. 진입 클립 머리는 게임 화면에서 라운지 장면으로 바로 컷이다(재생 쪽 페이드인 몫, 공용).
- **프리스핀 배경**: `bg-freespins.webp`(`theme.json`의 `backgroundFreeSpins`). 이 배경이 없던 때는 렌더러가 팔레트 `frame` 색을 알파 0.22로 덮어 회색 안개처럼 보였다(R2, 해결).
- **빅윈 연출**(`celebration`): 청록 빔 광선 + 보석 파티클(`gem`·`spark`, 다이아 심볼) + 이중 물결 + 세리프 제목. `storm`은 보라, `cataclysm`은 붉은 가장자리로 덮어쓴다.
- **사운드**(`sound.preset`): `bell`. 효과음은 `apps/hub/src/lib/audio.ts`의 `BELL_RECIPE`, 배경음은 `bgm.ts`의 `LOUNGE`로 `classic-777`과 같은 세트다.
  이 게임 고유의 소리는 아직 없고 미스터리 공개음(`mutation`)이 `docs/SOUND_CHECK.md`에서 «주의» 등급이다. 최종 귀 판정은 사용자 몫이다.
- **이름과 그림**: 스캐터 이름은 «데코 스타»(`Deco Star`)지만 그림은 받침 위의 다이아몬드이고 별 모양은 와일드다. 이름 변경은 사용자 확인이 필요해 그대로 두었다(`CHECKLIST.md` 9절).

## 수정할 때

`math.json`을 고치면 반드시 다시 측정하고 이 문서의 숫자를 갱신한다.

```bash
pnpm --filter @tgslot/rtp-sim sim royal-diamond-777 --exact
pnpm --filter @tgslot/rtp-sim test
```

게이트는 RTP 목표 +-0.5%p를 검사하고, 몬테카를로 모델은 `|rtp - target| <= max(0.5%p, 3xSE)`와
리포트의 `spins`/`seed`/`stderr`/`ci95` 존재를 함께 본다.
절차는 `games/_template/HOWTO.md` 참고.

스트립(`strips`)을 건드리면 위 «첫 화면»의 0~2번 칸도 같이 확인하고,
`packages/slot-engine/src/__golden__/hashes.json`의 골든 해시를 다시 만든다(통합 담당).
