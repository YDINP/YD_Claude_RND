# Shiba Shrine / 시바 신사

> 시바가 경내를 가로지르며 와일드 발자국을 뿌리는, 페이라인 없는 243길 축제.

5릴 3행 **243 ways**. 카탈로그 #5.

빈칸은 없다. 릴의 모든 칸이 실제 심볼이다.

## RTP를 두 조각으로 나눠 놓은 이유

허브 잭팟은 하우스가 재원을 대고 베팅액의 1.5%를 되돌린다. 그래서 게임 페이테이블은
**94.5%**를 겨냥하고, 잭팟을 얹어 체감 96%가 된다. 잭팟은 수학 모델 밖(API의 잭팟 원장)에
있어 `computeExactRtp`에 잡히지 않는다.

| 조각 | 값 | 소유자 |
|---|---|---|
| 기본 게임 RTP (`rtpTarget`) | 94.5% | `math.json` 페이테이블 |
| 허브 잭팟 기여 (`jackpotContribution`) | 1.5% | API의 잭팟 원장 |
| **체감 총 RTP** (`rtpTotalTarget`) | **96.0%** | 플레이어가 실제로 받는 값 |

## 실측 수치

랜덤 와일드 드롭은 배치가 서로 배타적이라 릴 간 상관을 만든다. **몬테카를로**로 잰다.
(드롭이 없는 순수 ways 모델은 해석적으로 정확히 풀린다. `expectedWaysMultiplier` 참고.)

| 지표 | 값 |
|---|---|
| 산출 방식 | **몬테카를로** (`method: "monte-carlo"`) |
| 스핀 수 / 시드 | 25,000,000 / `w2-verify` |
| 기본 게임 RTP | **94.388%** (목표 94.5% 대비 -0.112%p) |
| 표준오차 | 0.0881%p |
| 95% 신뢰구간 | [94.2153%, 94.5609%] (반폭 **0.1728%p**) |
| 체감 총 RTP | **95.888%** |
| 적중률 | **35.404%** |
| 최대 배수 (기본 게임) | **221.60x** |
| 정지 조합 수 | 313,331,760 |

독립 시드 교차 확인: seed `tune-25m`, 2,500만 스핀에서 94.498% (표준오차 0.088%p).
두 시드를 합치면 94.44% +- 0.06%p다.

RTP 구성:

| 조각 | 기여 | 비중 |
|---|---:|---:|
| ways | 59.45% | 63.0% |
| 스캐터 | 5.75% | 6.1% |
| 프리스핀 | 29.18% | 30.9% |

프리스핀 진입 확률은 **2.282%**, 약 44스핀에 한 번이다.
스캐터 3개 이상이면 프리스핀 8회가 열리고 승리에 2배가 곱해진다. 리트리거로 8회가 더 붙는다.

재현:

```bash
pnpm --filter @tgslot/rtp-sim sim shiba-shrine --exact --mc 5000000
```

## 페이테이블

페이라인이 없다. **인접한 릴의 매칭 칸 수를 곱한 것**이 경로 수이고,
지급액은 `경로 수 x 배수 x 웨이당 베팅액`이다.

배수 기준은 **웨이당 베팅액 = 총 베팅액 / 25**다. 총 베팅액이 아니다.
243 ways에서 5연속이 총 베팅액의 150배라면 말이 안 되므로, 라인 게임의 "라인당 베팅액"에
해당하는 단위를 하나 둔다. `ways.betDivisor`가 그 값이고 기본은 업계 관례대로 25다.

| 심볼 | 5개 | 4개 | 3개 |
|---|---:|---:|---:|
| 시바 (`shiba`) | 151 | 44 | 15 |
| 판다 (`panda`) | 87 | 26 | 9 |
| 카피바라 (`capy`) | 66 | 22 | 7 |
| 너구리 (`tanuki`) | 51 | 17 | 6 |
| 복고양이 (`cat`) | 36 | 13 | 4 |
| 비단잉어 (`koi`) | 26 | 9 | 3 |
| 당고 (`dango`) | 18 | 7 | 2 |
| 오마모리 (`charm`) | 13 | 4 | 1 |

**토리이 와일드에는 자체 배당 행이 없다.** 와일드는 모든 심볼을 대체하므로 와일드만으로 채워진
줄은 **최고 심볼(시바) 배당으로** 지급된다. 와일드에 따로 배수를 주면 시바보다 낮은 값은 절대
도달하지 않는 죽은 행이 되고, 높은 값을 주면 "와일드가 시바보다 세다"는 별개의 규칙이 생긴다.
전자는 플레이어를 헷갈리게 하고 후자는 이 게임의 의도가 아니라, 행 자체를 두지 않는다.

### 스캐터

스캐터는 페이라인과 무관하게 화면에 보이는 칸을 전부 센다. 배수 기준은 **총 베팅액**이다.

| 스캐터 | 총 베팅액 배수 |
|---|---:|
| 3개 | 2x |
| 4개 | 8x |
| 5개 | 30x |

## 243 ways와 랜덤 와일드 드롭

```json
"payModel": "ways",
"ways": { "base": 243, "bothWays": false, "betDivisor": 25 },
"mutations": [
  { "type": "randomWild", "symbol": "wild", "chance": 0.2,
    "countWeights": { "1": 60, "2": 30, "3": 10 },
    "reels": [1, 2, 3], "coverScatter": false }
]
```

**ways.** 왼쪽 릴부터 매칭이 이어지는 동안 릴별 칸 수를 곱한다. 5릴이 전부 3칸이면 3^5 = 243경로다.
와일드는 릴 카운트에 합산되므로 드롭 하나가 경로 수를 크게 늘린다.

**지급 칸이 전부 와일드인 줄은 심볼 하나로만 지급한다.** 와일드는 모든 심볼을 대체하므로
와일드로만 채워진 줄은 시바·판다·카피바라… 여덟 후보에 동시에 성립한다. 엔진은 길이별 최고
배수를 가진 후보(이 게임은 전 길이에서 `shiba`)만 지급하고 나머지는 접는다.
따라서 와일드 5연속은 시바 5연속(151배)으로 쳐서 지급된다.
페이라인 게임의 "라인당 최고 해석 하나" 규칙과 같은 처리다.

**드롭.** 매 스핀 20% 확률로 릴 2/3/4에 와일드가 떨어진다. 개수는 60:30:10 가중으로 1~3개,
스핀당 기대 추가 와일드는 0.3개다. 스캐터 칸과 이미 와일드인 칸은 후보에서 빠지고,
후보가 요구 개수보다 적으면 가능한 만큼만 놓는다(예외가 아니다).

RNG 소비 순서는 `릴 정지 5회 -> 드롭 확률 1회 -> 개수 추첨 1회 -> 위치 추첨 k회`로 고정이다.
같은 시드를 재생하면 정지 위치도 드롭 좌표도 그대로 재현된다.

## 릴 구성

릴 1/2는 오마모리가, 릴 3은 당고가 채운다. 서로의 연속을 막아 ways 적중률을 35%대로 누른다.
릴 4/5는 시바/카피바라로 채워 4/5연속 배당을 키운다. 와일드는 뒤쪽 릴에 더 많다.

| `wild` | 1 | 1 | 1 | 3 | 4 |
| `scatter` | 2 | 3 | 3 | 2 | 2 |

| `panda` | 3 | 4 | 5 | 6 | 5 |
| `capy` | 4 | 6 | 3 | 6 | 8 |

## 수정할 때

`math.json`을 고치면 반드시 다시 측정하고 이 문서의 숫자를 갱신한다.
분산이 커서 300만 스핀의 표준오차가 0.25%p나 된다. **최종 확인은 2,500만 스핀으로 한다.**

```bash
pnpm --filter @tgslot/rtp-sim sim shiba-shrine --exact --mc 25000000 --mc-seed w2-verify
pnpm --filter @tgslot/rtp-sim test
```

페이테이블은 RTP에 **선형**이다. 배수를 바꿔도 정지 위치와 드롭은 그대로이므로,
한 번 잰 심볼·길이별 기여도로 "어느 배수를 +1 하면 RTP가 몇 %p 오르는지"를 그대로 계산할 수 있다.
이번 조정(시바 5연속 150 -> 151, 카피바라 65 -> 66, 잉어 25 -> 26)도 그렇게 +0.43%p를 채웠다.

게이트는 RTP 목표 +-0.5%p를 검사하고, 몬테카를로 모델은 `|rtp - target| <= max(0.5%p, 3xSE)`와
리포트의 `spins`/`seed`/`stderr`/`ci95` 존재를 함께 본다.
절차는 `games/_template/HOWTO.md` 참고.
