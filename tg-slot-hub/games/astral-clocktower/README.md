# Astral Clocktower / 별의 시계탑

> 탑의 층이 하나씩 올라가고, 빛 기둥이 다섯 칸을 통째로 삼킨다.

**4릴 5행 625 ways.** 카탈로그 #16. 허브에서 **유일한 세로 격자**이고, 프레임 캔버스도
유일하게 세로(`1024×1536`)다. 설계 원본은 `docs/PORTRAIT_SLOT_DESIGN.md`,
구현 중에 설계가 틀린 것으로 드러난 부분은 그 문서의 **부록 B**에 적어 두었다.

빈칸은 없다. 릴의 모든 칸이 실제 심볼이다.

## 왜 세로인가

정사각 캔버스 5종은 프레임이 컨테이너 **폭**에 묶여서, 폰 세로 화면에서는 릴 위아래에 배경 띠가
크게 남는다. 세로 캔버스에서는 스테이지가 캔버스보다 납작해 **높이**가 먼저 묶이므로
프레임 높이 = 스테이지 높이가 되고 위아래 띠가 0이 된다.

| 캔버스 | 프레임 표시 @430 | 셀 | 위아래 띠 | 좌우 띠 |
|---|---|---:|---:|---:|
| 1024×1024 (현행 v4, 같은 4×5) | 430 × 430 | 66.9px | 145px | 0 |
| **1024×1536 (v5)** | **384.7 × 577** | **88.3px** | **0** | 45.3px |

대가는 좌우 45.3px이고 그 자리는 배경(bg)이 채운다. 셀 88.3px는 **허브 전 게임 최대**다
(현행 최대는 shiba-shrine의 69.2px).

셀 크기는 스테이지 높이에 **선형**이다 — `셀 ≈ 0.153 × min(스테이지 높이, 1.5 × 스테이지 폭)`.
**WinStrip이나 컨트롤에 한 줄을 얹는 것은 이 팩에서 셀을 깎는 일이다**(10px = 셀 1.5px).

| 스테이지 (부록 A 실측) | 창 | 셀 |
|---|---|---:|
| 430 × 577 (평시) | 369.3 × 470.3 | **88.3px** |
| 390 × 489 (평시) | 313.0 × 398.5 | **74.9px** |
| 430 × 645 (전체화면 TMA) | 412.8 × 525.7 | 98.8px |

**평시 값이 곧 최소값이다.** 설계 부록 A-2가 «갬블 패널이 열리면 스테이지가 10% 줄어 심볼이
작아진다»를 지적했었는데(그 상태의 셀은 79.5 / 66.0px로 아래 체크리스트 하한을 밑돌았다),
더블업 줄을 WinStrip 흐름 밖으로 띄워 고쳐졌다 — 평시와 패널이 열린 상태의 스테이지 높이가
실측으로 같다. 79.5 / 66.0px는 이제 «되돌아가면 이렇게 된다»는 회귀 기준선일 뿐이다.

## RTP를 두 조각으로 나눠 놓은 이유

허브 잭팟은 하우스가 재원을 대고 베팅액의 1.5%를 되돌린다. 그래서 게임 페이테이블은
**94.5%**를 겨냥하고, 잭팟을 얹어 체감 96%가 된다.

| 조각 | 값 | 소유자 |
|---|---|---|
| 기본 게임 RTP (`rtpTarget`) | 94.5% | `math.json` 페이테이블 |
| 허브 잭팟 기여 (`jackpotContribution`) | 1.5% | API의 잭팟 원장 |
| **체감 총 RTP** (`rtpTotalTarget`) | **96.0%** | 플레이어가 실제로 받는 값 |

## 실측 수치

ways + 뮤테이션 결합이라 해석 경로가 없다. **몬테카를로**로 잰다.

| 지표 | 값 |
|---|---|
| 산출 방식 | **몬테카를로** (`method: "monte-carlo"`) |
| 스핀 수 / 시드 | 20,000,000 / `monte-carlo` |
| 기본 게임 RTP | **94.484%** (목표 94.5% 대비 **-0.016%p**) |
| 표준오차 | 0.1022%p |
| 95% 신뢰구간 | [94.284%, 94.684%] (반폭 **0.2002%p**) |
| 체감 총 RTP | **95.984%** |
| 적중률 | **29.083%** |
| 최대 배수 (기본 게임, 표본) | **139.25x** (100만 스핀 별도 표본 267.88x) |
| 라운드 배수 표준편차 | **4.534** |
| 정지 조합 수 | 18,386,944 |

RTP 구성:

| 조각 | 기여 | 비중 |
|---|---:|---:|
| ways | 85.03% | 90.0% |
| 스캐터 | 0.56% | 0.6% |
| 프리스핀 | 8.90% | 9.4% |

프리스핀 진입 확률은 **0.4887%**, 약 205스핀에 한 번이다.

**필요 표본.** `n* = (1.96 × 4.534 / 0.002)² = 19.8M`. 20M에서 CI 반폭이 0.2002%p로
정밀도 기준선(0.2%p)에 정확히 걸치므로, 정식 감사는 여유를 두고 **2,500만 스핀**으로 돌린다.

재현:

```bash
pnpm --filter @tgslot/rtp-sim sim astral-clocktower --mc 20000000 --sample 1000000
```

## 페이테이블

페이라인이 없다. **인접한 릴의 매칭 칸 수를 곱한 것**이 경로 수이고,
지급액은 `경로 수 x 배수 x 웨이당 베팅액`이다.

배수 기준은 **웨이당 베팅액 = 총 베팅액 / 100**이다. 다른 팩(`betDivisor` 25)과 다른 이유는
아래 «왜 `betDivisor`가 100인가»에 적었다.

카운트 2는 **없다.** 4릴 5행에서 카운트 2를 열면 적중률이 60%대로 폭주한다.

| 심볼 | 4개 | 3개 | | 심볼 | 4개 | 3개 |
|---|---:|---:|---|---|---:|---:|
| 성반 (`astrolabe`) | 53 | 8 | | 황동 열쇠 (`key`) | 6 | 4 |
| 탑의 부엉이 (`owl`) | 29 | 8 | | 추 (`pendulum`) | 5 | 4 |
| 달시계 (`moondial`) | 20 | 4 | | 별가루 병 (`starjar`) | 4 | 3 |
| 톱니 (`gear`) | 10 | 4 | | 깃펜 (`quill`) | 3 | 3 |

**별창 와일드에는 자체 배당 행이 없다.** 와일드는 모든 심볼을 대체하므로 와일드만으로 채워진
줄은 최고 심볼(성반) 배당으로 지급된다. 게다가 와일드는 릴 1·2에만 있어서 릴 0부터 시작하는
와일드 전용 연속 자체가 생기지 않는다.

### 스캐터

스캐터는 화면에 보이는 칸을 전부 센다. 배수 기준은 **총 베팅액**이다.

| 스캐터 | 총 베팅액 배수 |
|---|---:|
| 3개 | 1x |
| 4개 | 6x |

**스캐터는 낱개로만 놓는다.** 스택으로 두면 한 릴만으로 3칸이 보여 프리스핀 진입이
0.49%가 아니라 18%가 된다(부록 B-3에 실측). 릴별로 1 / 2 / 2 / 1개다.

### 왜 `betDivisor`가 100인가

최저 베팅에서 웨이당 베팅액이 1이 되면 페이테이블 배수는 **정수**여야 한다
(`schema.ts`의 지급 코인 정수 검사). 625 ways · 5행에서는 3연속의 경로 수가 평균 9.8,
4연속이 21이라 배수 1 하나가 이미 크다. `betDivisor` 25로는 하위 5종이 전부 `3:1 / 4:1`로
뭉개져 **배당표 사다리가 사라진다.** 100이면 해상도가 4배가 되어 8종이 53 → 3까지 내려가는
사다리를 만들 수 있다. `betLevels`는 그에 맞춰 100 … 4000이다.

## 625 ways와 피처 두 개

```json
"payModel": "ways",
"ways": { "base": 625, "bothWays": false, "betDivisor": 100 },
"mutations": [
  { "type": "expandWild", "symbol": "wild", "reels": [1, 2], "minCount": 1, "coverScatter": false },
  { "type": "upgrade", "from": "gear",     "to": "moondial", "minCount": 3, "chance": 0.03 },
  { "type": "upgrade", "from": "key",      "to": "gear",     "minCount": 3, "chance": 0.07 },
  { "type": "upgrade", "from": "pendulum", "to": "key",      "minCount": 3, "chance": 0.07 },
  { "type": "upgrade", "from": "starjar",  "to": "pendulum", "minCount": 3, "chance": 0.07 },
  { "type": "upgrade", "from": "quill",    "to": "starjar",  "minCount": 3, "chance": 0.07 }
]
```

**신규 엔진 프리미티브는 0개다.** 위 둘은 웨이브 1이 이미 쓰던 것이고, 새로움은 메커닉이
아니라 격자에서 나온다.

**F1. 확장 와일드 = 5칸 빛 기둥.** 같은 프리미티브가 세로 격자에서 66% 더 강하다 —
5×3에서 확장 릴은 ways 경로를 ×3으로 만들지만 4×5에서는 **×5**다. 둘 다 확장되면 ×25다.
릴 0을 제외하는 이유는 릴 0이 통째로 와일드면 화면의 모든 후보가 항상 3연속 후보가 되어
적중률과 RTP가 동시에 폭주하기 때문이고, 릴 3 제외는 4연속(최대 배당) 빈도를 억제하기 위함이다.
릴당 확장 확률은 `q ≈ 0.15`, 스핀당 확장 발생은 `1 - 0.85² ≈ 0.28`이다.
`coverScatter: false` — 덮으면 프리스핀 RTP가 흔들린다.

**F2. 층 승급 사다리.** 엔진의 `upgrade`는 `from→to` 한 쌍이라 사다리는 뮤테이션 배열로 만든다.
**반드시 상위 단부터 선언한다** — 하위부터 선언하면 같은 스핀에서 `quill`이 `moondial`까지
연쇄 승급한다. `minCount: 3`은 화면 전체 개수 기준이라 20칸 격자에서 자주 충족되고,
RNG 소비는 스핀당 **정확히 5회 추가**(선언 순서대로 각 1회)로 결정론적이다.
승급 사다리에 `scatter`가 없으므로 승급이 프리스핀 트리거를 바꾸지 않는다.

**F3. 스캐터 프리스핀.** 3개 이상이면 10회가 열리고 승리에 2배가 곱해진다. 리트리거 있음.
정적 검사 `count × p = 10 × 0.0049 = 0.049 < 1` 통과.

RNG 소비 순서는 `릴 정지 4회 → 확장 스캔 → 승급 5회`로 고정이다.

## 릴 구성

하위 5종은 스택 3칸짜리 3덩어리, 상위 3종은 스택 3칸짜리 2덩어리다. 스택은 적중률을
낮추면서 성립 시 ways 곱을 키워 **세로 격자의 변동성을 만드는 유일한 손잡이**다.
와일드는 릴 1·2에만 낱개 2개, 스캐터는 전 릴에 낱개다.

## 아트 — 아직 없다

`art/prompts.json`(15장)은 완성돼 있으나 **생성물이 없다.** `codex` 프로바이더가 사용량
한도에 걸려 있고(해제 예정 2026-09-08 17:10) `OPENAI_API_KEY`·`GEMINI_API_KEY`도 없다.
로컬 ComfyUI(SDXL)로는 크로마키 배경도, 프레임의 플랫 초록 창도 그려지지 않아 쓸 수 없다
(부록 B-5에 실측). 한도가 풀리면:

```bash
pnpm --filter @tgslot/theme-gen gen games/astral-clocktower
git add games/astral-clocktower/theme games/astral-clocktower/thumb.webp
pnpm pack:check
```

프레임은 세로 규격(ART_DIRECTION v5)이라 창 탐지가 **세로 전용 영역**을 타야 한다.
`tools/theme-gen`의 `frameWindowRegion()`이 캔버스 종횡비로 자동 선택한다 — 생성 로그의
`frame: frame 릴 창 감지 ... h=`가 0.78 미만이면 탐지가 잘린 것이니 그때는 프레임을 다시 생성한다.

## 수정할 때

`math.json`을 고치면 반드시 다시 측정하고 이 문서의 숫자를 갱신한다.
분산이 커서 300만 스핀의 표준오차가 0.26%p나 된다. **최종 확인은 2,000만 스핀 이상으로 한다.**

```bash
pnpm --filter @tgslot/rtp-sim sim astral-clocktower --mc 20000000 --sample 1000000
pnpm --filter @tgslot/rtp-sim test
```

페이테이블은 RTP에 **선형**이다. `astrolabe` 4연속 배수 +1이 RTP +0.27%p다
(이번 마무리 조정도 51 → 53으로 +0.52%p를 채웠다).
