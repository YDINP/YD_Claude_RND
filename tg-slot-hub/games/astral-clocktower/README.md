# Astral Clocktower / 별의 시계탑

> 탑의 층이 하나씩 올라가고, 빛 기둥이 다섯 칸을 통째로 삼킨다.

**4릴 5행 625 ways.** 카탈로그 #16. 허브에서 **유일한 세로 격자**이고, 프레임 캔버스도
유일하게 세로(2:3)다. 생성은 `1024×1536`으로 요청했고 저장된 `frame.webp`·`bg.webp`는 같은 비율의
`1080×1620`이다. 설계 원본은 `docs/PORTRAIT_SLOT_DESIGN.md`,
구현 중에 설계가 틀린 것으로 드러난 부분은 그 문서의 **부록 B**에 적어 두었다.

> 릴 번호는 이 문서 전체에서 **1부터** 센다(2번째 릴 = 코드의 `reels: [1]`). `math.json`의 `reels` 인덱스만 0부터다.

빈칸은 없다. 릴의 모든 칸이 실제 심볼이다.

## 왜 세로인가

정사각 캔버스 5종은 프레임이 컨테이너 **폭**에 묶여서, 폰 세로 화면에서는 릴 위아래에 배경 띠가
크게 남는다. 세로 캔버스에서는 스테이지가 캔버스보다 납작해 **높이**가 먼저 묶이므로
프레임 높이 = 스테이지 높이가 되고 위아래 띠가 0이 된다.

| 캔버스 | 셀 @430 | 위아래 띠 | 근거 |
|---|---:|---:|---|
| 1024×1024 (옛 v4, 같은 4×5) | 66.9px | 145px | 설계 계산값 |
| **세로 2:3 (현행 v5)** | **96.5px** | **0** | 2026-11-26 실측 |

스테이지가 2:3에 가까워(아래 표) 프레임이 높이에 묶이고, 430에서는 프레임이 스테이지보다 좌우로
4~5px씩 넘쳐 잘리지만 눈에 띄지 않는다. 설계 때 예상한 좌우 배경 띠는 거의 남지 않았다.
셀 96.5px는 **허브 전 게임 최대**다(다음은 shiba-shrine의 69.2px).

셀 크기는 스테이지 높이에 **선형**이다 — 실측으로 `셀 ≈ 0.147 × 스테이지 높이`(0.149 @390, 0.146 @430).
**WinStrip이나 컨트롤에 한 줄을 얹는 것은 이 팩에서 셀을 깎는 일이다**(10px = 셀 1.5px).

| 스테이지 (검수 실측, 2026-11-26) | 창 (`frameLayout`) | 셀 간격 | 당첨 강조 상자 |
|---|---|---:|---:|
| 430 × 659 | 379.8 × 489.0 | **96.5px** | 91px |
| 390 × 583 | 344.5 × 432.6 | **87.0px** | 83.5px |

**평시 값이 곧 최소값이다.** 설계 부록 A-2가 «갬블 패널이 열리면 스테이지가 10% 줄어 심볼이
작아진다»를 지적했었는데, 더블업 줄을 WinStrip 흐름 밖으로 띄워 고쳐졌다 — 평시와 패널이 열린
상태의 스테이지 높이가 같다. (이전 문서의 셀 88.3 / 74.9px 표와 «패널이 열리면 79.5 / 66.0px»는
스테이지가 지금보다 낮던 시절의 값이다. 회귀 기준선으로만 기억할 것.)

## RTP를 두 조각으로 나눠 놓은 이유

허브 잭팟은 하우스가 재원을 대고 베팅액의 1.5%를 되돌린다. 그래서 게임 페이테이블은
**94.5%**를 겨냥하고, 잭팟을 얹어 체감 96%가 된다.

| 조각 | 값 | 소유자 |
|---|---|---|
| 기본 게임 RTP (`rtpTarget`) | 94.5% | `math.json` 페이테이블 |
| 허브 잭팟 기여 (`jackpotContribution`) | 1.5% | API의 잭팟 원장 |
| **체감 총 RTP** (`rtpTotalTarget`) | **96.0%** | 플레이어가 실제로 받는 값 |

## 실측 수치

ways + 뮤테이션 결합이라 해석 경로가 없다. **몬테카를로**로 잰다. `math.json`은 2026-09-06 이후
바뀌지 않았고, 아래 세 측정은 **같은 수학을 시드·스핀 수만 달리해 잰 것**이다. 표본 오차 범위
안에서 서로 맞는다 — 숫자가 조금씩 다른 건 측정 시드 차이일 뿐이다.

| 지표 | 개발 측정 | **정식 감사 (기준)** | 검수 독립 재측정 |
|---|---:|---:|---:|
| 시점 | 아트 생성(11-10) 이전 | 2026-11-10 | 2026-11-26 |
| 스핀 수 / 시드 | 20,000,000 / `monte-carlo` | **25,000,000 / `42`** | 8,000,000 / `review-seed-A` |
| 기본 게임 RTP | 94.484% | **94.249%** (목표 대비 -0.251%p) | 94.247% |
| 표준오차 | 0.1022%p | 0.091%p | 0.161%p |
| 95% 신뢰구간 반폭 | 0.2002%p | **0.179%p** | 0.316%p |
| 체감 총 RTP (+잭팟 1.5%) | 95.984% | **95.749%** | 95.747% |
| 적중률 | 29.083% | 29.084% | 29.098% |
| 라운드 배수 표준편차 | 4.534 | 4.557 | - |
| 프리스핀 진입 확률 | 0.4887% | 0.4906% | 0.4918% |
| 최대 배수 (표본 극단값) | 139.25x | 496.84x(분포 표본) / 401.20x(단일 시뮬) | - |
| 정지 조합 수 | 18,386,944 | 18,386,944 | 18,386,944 |

세 측정을 표본 수로 가중하면 **약 94.34%**다 — 게이트(94.5% ± 0.5%p) 안이고, 중앙보다 0.16%p 낮다.
이 정도는 규칙 위반이 아니라서 `math.json`은 건드리지 않았다(조정한다면 `astrolabe` 4연속 53 → 54가
약 +0.27%p이고, 그때는 25M 정식 감사·골든 해시·이 표를 함께 갱신해야 한다).

**최대 배수는 표본마다 크게 흔들린다.** 꼬리 값이라 표본 한 번의 극단값일 뿐이고 RTP 판정에 쓰이지 않는다
(게이트는 «100x 이상»만 본다). 감사 문서의 두 값(496.84x / 401.20x)이 다른 이유는
`docs/RTP_AUDIT_astral-clocktower.md` 3절 아래 주석에 적었다. 도움말은 최대 당첨을 약속하지 않는다.

RTP 구성 (정식 감사 25M 기준):

| 조각 | 기여 | 비중 |
|---|---:|---:|
| ways | 84.82% | 90.0% |
| 스캐터 | 0.56% | 0.6% |
| 프리스핀 | 8.87% | 9.4% |

프리스핀 진입 확률은 정확 계산으로 **0.4895%**(P(스캐터 3개 이상)), 약 204스핀에 한 번이다.
스캐터 4개는 0.0136%.

**필요 표본.** `n* = (1.96 × σ / 0.002)²`: σ 4.534(개발)면 19.8M, σ 4.557(감사)이면 약 19.9M이다.
정식 감사는 여유를 두고 **2,500만 스핀**으로 돌려 CI 반폭 0.179%p로 기준선(0.2%p) 안에 들어왔다.

## 페이테이블

페이라인이 없다. **인접한 릴의 매칭 칸 수를 곱한 것**이 경로 수이고,
지급액은 `경로 수 x 배수 x 웨이당 베팅액`이다.

배수 기준은 **웨이당 베팅액 = 총 베팅액 / 100**이다. 다른 팩(`betDivisor` 25)과 다른 이유는
아래 «왜 `betDivisor`가 100인가»에 적었다.

카운트 2는 **없다.** 4릴 5행에서 카운트 2를 열면 적중률이 60%대로 폭주한다.

| 심볼 | 4개 | 3개 | | 심볼 | 4개 | 3개 |
|---|---:|---:|---|---|---:|---:|
| 성반 (`astrolabe`) | 53 | 8 | | 황동 열쇠 (`key`) | 6 | 4 |
| 탑의 부엉이 (`owl`) | 29 | 8 | | 추 (`pendulum`) | 5 | 4 |
| 달시계 (`moondial`) | 20 | 4 | | 별가루 병 (`starjar`) | 4 | 3 |
| 톱니 (`gear`) | 10 | 4 | | 깃펜 (`quill`) | 3 | 3 |

**별창 와일드에는 자체 배당 행이 없다.** 와일드는 모든 심볼을 대체하므로 와일드만으로 채워진
줄은 최고 심볼(성반) 배당으로 지급된다. 게다가 와일드는 2·3번째 릴에만 있어서 1번째 릴부터 시작하는
와일드 전용 연속 자체가 생기지 않는다.

### 스캐터

스캐터는 화면에 보이는 칸을 전부 센다. 배수 기준은 **총 베팅액**이다.

| 스캐터 | 총 베팅액 배수 |
|---|---:|
| 3개 | 1x |
| 4개 | 6x |

**스캐터는 낱개로만 놓는다.** 스택으로 두면 한 릴만으로 3칸이 보여 프리스핀 진입이
0.49%가 아니라 18%가 된다(부록 B-3에 실측). 릴별로 1 / 2 / 2 / 1개다.

### 왜 `betDivisor`가 100인가

최저 베팅에서 웨이당 베팅액이 1이 되면 페이테이블 배수는 **정수**여야 한다
(`schema.ts`의 지급 코인 정수 검사). 625 ways · 5행에서는 3연속의 경로 수가 평균 9.8,
4연속이 21이라 배수 1 하나가 이미 크다. `betDivisor` 25로는 하위 5종이 전부 `3:1 / 4:1`로
뭉개져 **배당표 사다리가 사라진다.** 100이면 해상도가 4배가 되어 8종이 53 → 3까지 내려가는
사다리를 만들 수 있다. `betLevels`는 그에 맞춰 100 … 4000이다.

## 625 ways와 피처 두 개

```json
"payModel": "ways",
"ways": { "base": 625, "bothWays": false, "betDivisor": 100 },
"mutations": [
  { "type": "expandWild", "symbol": "wild", "reels": [1, 2], "minCount": 1, "coverScatter": false },
  { "type": "upgrade", "from": "gear",     "to": "moondial", "minCount": 3, "chance": 0.03 },
  { "type": "upgrade", "from": "key",      "to": "gear",     "minCount": 3, "chance": 0.07 },
  { "type": "upgrade", "from": "pendulum", "to": "key",      "minCount": 3, "chance": 0.07 },
  { "type": "upgrade", "from": "starjar",  "to": "pendulum", "minCount": 3, "chance": 0.07 },
  { "type": "upgrade", "from": "quill",    "to": "starjar",  "minCount": 3, "chance": 0.07 }
]
```

**신규 엔진 프리미티브는 0개다.** 위 둘은 웨이브 1이 이미 쓰던 것이고, 새로움은 메커닉이
아니라 격자에서 나온다.

**F1. 확장 와일드 = 5칸 빛 기둥.** 같은 프리미티브가 세로 격자에서 66% 더 강하다 —
5×3에서 확장 릴은 ways 경로를 ×3으로 만들지만 4×5에서는 **×5**다. 둘 다 확장되면 ×25다.
1번째 릴을 제외하는 이유는 1번째 릴이 통째로 와일드면 화면의 모든 후보가 항상 3연속 후보가 되어
적중률과 RTP가 동시에 폭주하기 때문이고, 4번째 릴 제외는 4연속(최대 배당) 빈도를 억제하기 위함이다.
(확장 대상은 2·3번째 릴 = 코드의 `"reels": [1, 2]`.)
릴당 확장 확률은 `q ≈ 0.15`, 스핀당 확장 발생은 `1 - 0.85² ≈ 0.28`이다.
`coverScatter: false` — 덮으면 프리스핀 RTP가 흔들린다.

**F2. 층 승급 사다리.** 엔진의 `upgrade`는 `from→to` 한 쌍이라 사다리는 뮤테이션 배열로 만든다.
**반드시 상위 단부터 선언한다** — 하위부터 선언하면 같은 스핀에서 `quill`이 `moondial`까지
연쇄 승급한다. `minCount: 3`은 화면 전체 개수 기준이라 20칸 격자에서 자주 충족되고,
RNG 소비는 스핀당 **정확히 5회 추가**(선언 순서대로 각 1회)로 결정론적이다.
승급 사다리에 `scatter`가 없으므로 승급이 프리스핀 트리거를 바꾸지 않는다.

**F3. 스캐터 프리스핀.** 3개 이상이면 10회가 열리고 승리에 2배가 곱해진다. 리트리거 있음.
정적 검사 `count × p = 10 × 0.0049 = 0.049 < 1` 통과.

RNG 소비 순서는 `릴 정지 4회 → 확장 스캔 → 승급 5회`로 고정이다.

## 빅윈 연출 (`theme.json` `celebration`)

허브 오버레이·프리스핀 종료 팝업·렌더러 버스트가 같은 스킨을 쓴다. 등급 이름은 쉬운 한국어로 덮어썼다.

| 등급 (배수) | 이름 | 광선·고리 색 |
|---|---|---|
| 10x~ `surge` | 큰 당첨 | 코발트 |
| 20x~ `blast` | 대박 당첨 | 호박 |
| 50x~ `storm` | 초대박 당첨 | 루비 |
| 100x~ `cataclysm` | 시계탑의 기적 | 금백색 |

- 파티클은 톱니·별·유리 조각에 **팩 심볼(부엉이·성반)** 을 섞어 흩날린다. 허브는 심볼 파티클을
  기본 크기의 2.6배로 그려서 `size`를 1.2로 낮췄다(1.5~1.9에서는 심볼이 금액 글자를 자주 가렸다).
- 허브 오버레이의 어두운 배경은 공용이라 팩에서 못 바꾼다. 대신 광선 세기(0.8~0.9)와 색 채도를 올려
  어둡게 눌린 인상을 줄였다.
- ⚠ `labels`는 언어와 무관하게 그대로 나온다(허브 한계). 영어 사전으로 켜도 한국어 이름이 뜬다 —
  검수 sharedIssues에 올렸다.

## 수정할 때

`math.json`을 고치면 반드시 다시 측정하고 이 문서의 숫자를 갱신한다.
분산이 커서 300만 스핀의 표준오차가 0.26%p나 된다. **최종 확인은 2,000만 스핀 이상으로 한다.**

```bash
pnpm --filter @tgslot/rtp-sim sim astral-clocktower --mc 20000000 --sample 1000000
pnpm --filter @tgslot/rtp-sim test
```

페이테이블은 RTP에 **선형**이다. `astrolabe` 4연속 배수 +1이 RTP +0.27%p다
(이번 마무리 조정도 51 → 53으로 +0.52%p를 채웠다).
